# 文风与风格模仿工程

> **一句话**：模仿不是抄一个人，是**拼三种能力**。
> 只学骨架 = 顺滑但没记性；只学刀锋 = 犀利但招黑；只学底色 = 温润但没传播。

## 核心原则

1. **模仿招式，不模仿人** —— 身份、素材、人脉都抄不走，能抄的只有结构、判据和节奏。
2. **每个招式必须可数** —— 凡是写不出"自检判据"的风格描述，一律视为无效形容词，不写进定义。
3. **先学整体，再长出自己** —— 前三个月只跑一个固定套餐，跑顺了再混搭。
4. **反面样本和正面样本一样重要** —— 知道不模仿谁，比知道模仿谁更能救命。
5. **（2026-09-04 用户校准）原型只借"挖题方法"，不借"句子与腔调"** —— 博主的教学价值在于：他们示范了怎么从新闻里找到能写的东西（一手事实 + 处理角度 + 结构节奏）。**成稿必须基于一手事实、以博主本人（橙子哥哥/techdog：深圳独立开发者、做 AI 产品的人）的口吻从零撰写**——不挪用/改写原型原文句子、不用他们的标志比喻与语气词、不扮演任何原型人设。判定：稿子给熟悉博主本人的人读，读不出"这是模仿谁写的"，只读得出"这是 techdog 写的"，才算过。
6. **（2026-09-04 用户校准）"过程可见/金句/查证"是自然结果，不是表演动作** —— 为过判据硬塞"我查了"、硬造金句、虚构"朋友/场景"开场，会把稿子变成招式堆砌，读者（包括博主本人）一眼陌生。判据是事后检验，不是写作清单。

## 一、三种能力源

| 能力源 | 解决什么 | 最强提供者 | 缺失后果 |
|---|---|---|---|
| **骨架** | 读者读得下去、跟得住 | 九边 | 散、跳、读不进去 |
| **刀锋** | 读者觉得"你说到点子上了" | 半佛仙人 | 温吞、没记性 |
| **底色** | 读者觉得"这个人值得长期关注" | 池建强 | 有传播无人格 |

## 二、使用流程

```
① 确认当前使用的套餐（默认 A，用户可切换）
② 按套餐的"位置 → 提供者 → 比重"表搭骨架
③ 逐段套用对应原型卡的"结构模板"
④ 成稿后跑 §四 的九条落地校验
⑤ 任一 FAIL 项 → 修到过为止，不准交付
```

**默认套餐 A（技术人文 + 利益解构 + 唠嗑逻辑）**

| 位置 | 提供者 | 比重 / 要求 |
|---|---|---|
| 开篇 200 字 | 池建强 | 具体的人或场景切入；口语、克制、有余味；**禁止概念开场** |
| 主体骨架 | 九边 | 现象 → 表面原因 → 本质原因 → 结论 → 启示（**"表面原因"段不可省**） |
| 观点刀锋 | 半佛仙人 | ≥1 处利益溯源：谁出钱 / 谁受益 / 谁付代价 |
| 证据密度 | 老蒋巨靠谱 | ≥1 处"我查了 / 问了"的过程可见；数据必有出处 |
| 结尾 | 池建强 | 留白或余味；**禁止总结陈词、禁止喊口号** |

套餐 B（一线亲历 + 查证 + 持续）、套餐 C（大众共鸣 + 唠嗑骨架）见 `references/style-profiles.md` §六。

## 二·五、人格路由矩阵（按热点选配方）

> **能不能按热点换人格？能。但换的是配方，不是人。**
> 整体换人设 = 人设分裂，读者今天关注明天取关。分层换配方 = 一个人面对不同题材用不同打法，这才是真博主。

### 三层人格架构

| 层 | 变不变 | 内容 |
|---|---|---|
| **L0 恒定层** | **任何热点都不变** | 价值观 · 禁语 · 开篇必须有具体的人 · 判断必须可证伪 · 结尾留白不总结 · 数据必有出处 |
| **L1 配方层** | **按热点类型路由** | 骨架 / 刀锋 / 证据 由谁提供（下表六型） |
| **L2 招式层** | 按段落借招 | 某一段具体用谁的招式，可临场调用借招库 |

**L0 是人格连续性的锚。** 读者认出"还是你"，靠的是 L0 不变；读者觉得"这篇写得到位"，靠的是 L1 选对。

### 六型路由表

| # | 热点类型 | 识别特征 | 配方 | 关键判据（不满足 = 选错型） |
|---|---|---|---|---|
| **A** | 技术 / 产品发布 | 有一手信源、可复现（GitHub、论文、发布会） | **查证型**：九边骨架 + 老蒋查证 + 池建强底色 | ≥1 处"我跑了/我查了"；给出"这对你意味着什么" |
| **B** | 商业博弈 / 资本事件 | 多方利益、信息不透明（融资、并购、价格战、裁员） | **解构型**：半佛利益溯源 + 九边骨架 + 傅盛数字 | 点名 ≥3 个具体利益角色；≥3 个具体数字 |
| **C** | 职业焦虑 / 个人命运 | 高共鸣、低信息（AI 取代、35 岁、裁员潮） | **共鸣型**：李尚龙金句 + 池建强留白 + 九边兜底逻辑 | 必须给出机制解释，不能停在情绪；不煽情 |
| **D** | 公共事件 / 舆情争议 | 阵营对立、情绪高涨、事实未清 | **克制型**：老蒋过程可见 + 半佛利益 + **延后判断** | 明确写出"哪些还没查清"；不站队、不预判责任 |
| **E** | 长期趋势 / 宏观 | 无具体触发点、极易写空（AGI、算力、人口） | **预言型**：阮一峰确定性 + 傅盛可回溯判断 + 九边五段 | 必须给出**证伪条件**和**检验日期**；否则弃题 |
| **F** | 亲历 / 复盘 | 一手经验、你自己的数据（踩坑、产品数据、决策复盘） | **亲历型**：傅盛亲历 + 池建强留白 | 写进翻车细节；给出可回溯的时间点 |

**选型失败的可观测信号**：技术发布写成了情绪文（A 用了 C）→ 通篇观点但读者问"所以要不要用"；商业博弈写成信息汇编（B 用了 A）→ 事实很全但没有刀；长期趋势写成感慨（E 用了 C）→ 读完感觉很深，什么也没带走。

### 知识距离降档规则（防止不懂装懂）

路由前先问：**我离这个话题有多远？**

| 距离 | 判定 | 允许的判断强度 |
|---|---|---|
| **近** | 我是当事人 / 从业者，有一手细节 | 下强判断，配证伪条件 |
| **中** | 懂原理但不在现场 | 只做结构解释 + 利益溯源，不给终局判断 |
| **远** | 只是看了新闻 | **降档**：只做"我查到了什么"的查证服务，或明确弃题 |

> 距离远却下了强判断 = 装懂。**装懂一次，人设资产清零。**

### 防漂移约束

1. **同一周内配方最多切换一次**，切换必须在自检报告里写明原因。
2. **L0 恒定层任何情况下不让步**——哪怕用户要求"这篇写得激进点"，开篇有人 / 可证伪 / 结尾留白三条也不动。
3. **连续 3 篇同型**说明选题面窄了，不是配方用熟了，应主动换型。
4. 用户指定的配方与路由表冲突时：**执行用户指定，但必须在自检报告标注冲突与风险**（例：用户要"模仿周鸿祎写一篇"→ 只借"一个热点拆成系列"这一招，并注明流量黏不住的风险）。

### 成稿必须声明路由

自检报告新增一行，格式：

```
人格路由：热点类型 B（商业博弈）→ 解构型配方；知识距离：中；本周第 1 次切换；L0 三项未让步
```

## 四、九条落地校验（成稿必跑）

| # | 检查项 | 来源 | 判据 |
|---|---|---|---|
| 1 | 开篇 200 字内有具体的人或场景 | 池建强 | 概念开场 = FAIL |
| 2 | 走完五段推进，且"表面原因"段未省略 | 九边 | 缺段 = FAIL |
| 3 | 全文点名 ≥3 个具体利益角色 | 半佛仙人 | 用"某些人 / 资本" = FAIL |
| 4 | 有 ≥1 处"我查了 / 问了"的过程可见 | 老蒋巨靠谱 | 无过程 = FAIL |
| 5 | 有 ≥3 个具体数字 | 傅盛 | 数字 <3 = FAIL |
| 6 | 有 ≥1 句可脱离文章独立传播的金句 | 李尚龙 | 无 = WARN |
| 7 | 为核心机制造了一个可传播的词 | 卢诗翰 | 无 = WARN（不阻塞） |
| 8 | 结尾不是总结陈词 | 池建强 | 喊口号 / 总结 = FAIL |
| 9 | 无"震惊 / 速看"标题党、无"随着…的发展"八股 | 通用红线 | 命中 = FAIL |

**与 `scripts/check_article.py` 的分工**：脚本管**结构层**（首图、标题字数、h2 数量、段落长度、Markdown 残留、死链）；本表管**内容层与风格层**。两者都要过。

> ⚠️ **脚本只接受 HTML 成稿**（`check_article.py <article.html>`），它把 Markdown 残留当缺陷。
> **Markdown 草稿阶段不要跑脚本**——跑必 FAIL 且全是误报（h2×0、Markdown 残留、0 段落）。
> 草稿阶段只跑本表；等转成 HTML 交付稿再跑脚本。

## 六、风格漂移检测

连写 5 篇不同话题后，检查：

- [ ] 开篇是否**连续 3 篇都是概念开场**（说明池建强招式没吃进去）
- [ ] 是否**连续 3 篇缺"表面原因"段**（说明退回了直给结论的懒路径）
- [ ] 金句密度是否 ≥1 句 / 500 字
- [ ] 是否出现"随着…的发展""总而言之""首先其次最后"（AI 味回归）

漂移即回退到模板重跑，不要靠临场发挥补救。

## 八、发布草稿流程（封面图零返工，直接走已验证链路）

> **发布走 dev 机器 content-hub 直连 POST**，这是标准发布路径。
> 核心是把「封面图可访问」这一步**提前并固化**，发布时只需一次 POST，不再临时救火。

### 8.1 总流程

```
定题 → 出封面并挂 dev 可访问 URL → 写 md（首图引用该 URL）→ md 转 HTML → 一次 POST 建草稿 → 后台确认 → 手动群发
```

### 8.2 封面图处理（最关键，提前做）

1. `ImageGen` 出封面 PNG（本地）。
2. `scp` 到 dev：
   ```bash
   scp /local/cover.png ubuntu@175.27.189.123:/tmp/cover_<slug>.png
   ```
3. dev 起 loopback 服务（content-hub 同在 dev，抓 `127.0.0.1` 即可，无需公网 IP）：
   ```bash
   ssh ubuntu@175.27.189.123 "cd /tmp && (python3 -m http.server 6099 >/dev/null 2>&1 &)"
   ```
4. 文章首图固定引用 `http://127.0.0.1:6099/cover_<slug>.png`。

⚠️ **封面三不**：不用 base64、不用本地路径、不临时才想。只要首图是 http(s) 且 dev 能抓到，绝不会「缺少封面」。

### 8.3 发布（一次 POST）

```bash
ssh ubuntu@175.27.189.123 "curl -s -X POST http://127.0.0.1:6007/api/content/wechat/draft \
  -H 'Content-Type: application/json' \
  -d '{\"title\":\"标题\",\"html\":\"<body><p>首段含封面img</p>...</body>\"}'"
```
返回 `media_id` 即建草稿成功；去公众号后台确认排版，**默认不自动群发**。凭证 dev 已配，无需填密钥。

### 8.4 发布前 30 秒自检（必做）

- HTML 前 200 字内有 `<img src="http` 且为 http(s) URL（非 base64 / 非本地路径）→ 否则必「缺少封面」。
- 标题 ≤64 字、`h2`≥3、无 Markdown 残留、段落 ≤180 字。

### 8.5 介质纪律

- 全程改 `.md`，HTML 只在最后一步转出来（别碰 HTML 成品改稿）。
- 定稿即按标题命名（保留 A/B/C 前缀），避免后期改名牵连编辑入口。
