## 1. 背景与目标

### 1.1 要解决的问题

| # | 问题 | 现象 | 根因 |
|---|---|---|---|
| P1 | 慢工具（如 90s 网络调用）中途 SSE 被代理掐断 | 客户端连接超时，流中断，用户白等 | SSE 流在工具执行期间无任何字节输出，nginx/网关按空闲超时掐连接 |
| P2 | C 端用户遇到需确认工具，干等 60s 后失败 | C 端无 HITL 确认 UI，用户莫名其妙等一分钟 | 装配侧把 `requiresConfirm` 工具装进了 C 端工具清单，模型调了才发现要确认 |
| P3 | 越权确认权限请求，挂起到超时 | 他人确认被拒后，发起者还要等到 60s 超时才知道失败 | `PermissionBroker.resolve()` 越权时只返回 false，**没唤醒挂起的 Promise** |
| P4 | 出问题无法按 runId 反查 | 前端只有 conversationId，排障要在库里翻 | `agent_runs` 主键是自增 uuid，**没存引擎生成的 runId** |
| P5 | 调试台看不到 intent 事件 | 模型意图分类结果黑盒 | `AgentPlayground.vue` 事件消费 switch 里没有 `intent` case |

### 1.2 验收目标

| # | 目标 | 判据 |
|---|---|---|
| G1 | 挂 90s 慢工具客户端不被掐断 | 工具执行期间每 ~15s 有一帧 `: keepalive` SSE 注释 |
| G2 | C 端装配侧不装 requiresConfirm 工具 | C 端请求的工具清单里无 banned 工具；日志可见过滤数量 |
| G3 | 越权确认立刻失败 | 越权调用 POST /agent/permission/:id → 立刻返回 forbidden，挂起工具同步 reject，不等 60s |
| G4 | runId 可反查 | SSE intent/final 帧带 runId；`agent_runs` 表主键即该 runId |
| G5 | 调试台可见 intent | AgentPlayground 收到 intent 事件后展示意图分类结果 |

### 1.3 Non-goals（明确不做）

| 不做 | 原因 |
|---|---|
| HITL 确认 UI（C 端） | 本期只做「装配侧不装」——C 端不做确认交互是产品决策，不是缺陷 |
| runId 全链路透传到日志/监控 | 本期只做 SSE 透出 + 落库可反查；进 APM 是 B2 计价批次的事 |
| intent 事件契约扩展 | 本期只消费已有的 intent 帧，不新增字段 |
| 多 Agent 编排（B5） | 铁律 B0→B4→B5，本批只止血 |

## 2. 方案设计

### 2.1 架构与数据流

```
C 端 / Admin 端
    │ POST /agent/run | /agent/admin-run
    ▼
agent.controller.ts ── scene: 'c-end' | 'admin'（新增透传）
    │
    ├──► AgentRunner.stream(input, userId, confirmHandler)
    │         │  runId = randomUUID()（已有）
    │         ▼
    │    AgentEngine.run(input, userId, runId, confirmHandler)
    │         │
    │         ├─ N3: scene==='c-end' → toolsRequiringConfirm(agent) 过滤工具清单
    │         ├─ 工具执行/等待期间 ──► N1: 每 15s 推 ": keepalive\n\n" 注释帧
    │         └─ emit intent/final ──► N5: 帧体带 runId
    │
    ├──► PermissionBroker.register/resolve
    │         └─ N4: 越权 → entry.resolve(false) 立刻唤醒 + 返回 forbidden
    │
    └──► agent-log 内部端点 recordRun
              └─ N5: runId 即 agent_runs 主键（复用，零 DDL）
```

### 2.2 页面清单（含菜单）

| 页面 | 改动 | 门禁 |
|---|---|---|
| AgentPlayground.vue（Admin 调试台） | 补 intent 事件消费 case，展示意图分类 | R11 UI 门——见 §2.5 原型通行证 |
| 其他页面 | 不动 | — |

### 2.3 接口清单

| 接口 | 方法 | 变更 | 兼容性 |
|---|---|---|---|
| `/agent/run`、`/agent/admin-run` | POST | 请求体新增可选 `scene`（缺省 `'c-end'`）；SSE 帧体新增 `runId` | **向后兼容**——字段只增不改 |
| `/agent/permission/:requestId` | POST | 返回体从 `{ ok: boolean }` 改为 `{ ok: true } \| { ok: false, code }` | **微破坏**——旧前端只读 `ok` 字段，`ok===true` 语义不变；`ok===false` 现在带 code |
| 内部 `agent-runs/record` | POST | `runId` 字段语义升级为「主键」 | 内部接口，唯一消费方是 agent-runner |

### 2.4 数据结构

**StreamEvent（agent-core/runtime.interface.ts）**：
```ts
export interface StreamEvent {
  type: 'intent' | 'tool_call' | 'tool_result' | 'permission_request' | 'delta' | 'final' | 'error';
  // ...既有字段
  /** 本次运行 ID（N5）：intent/final/error 帧携带，前端可反查 agent_runs */
  runId?: string;
}
```

**RunInput** 新增：
```ts
export interface RunInput {
  // ...既有字段
  /** 运行场景（N3）：'c-end' 触发装配侧过滤 requiresConfirm 工具；缺省按 'c-end' 处理 */
  scene?: 'c-end' | 'admin';
}
```

**agent_runs 表**：**零 DDL**——N5 复用主键 `id` 存引擎 runId（原自增 uuid 改为调用方传入 randomUUID）。

### 2.5 配置清单 / 原型通行证

| 项 | 值 |
|---|---|
| keepalive 间隔 | 15s（`KEEPALIVE_MS = 15_000`，硬编码常量，不做配置项——间隔与代理超时挂钩，不该被业务改） |
| 越权返回码 | `not_found` / `forbidden`（HTTP 仍 200，业务码在 body；避免改 HTTP 状态码导致旧前端弹「网络错误」） |
| **N6 原型通行证** | AgentPlayground 补 intent 消费属**表单/展示增强**，走 §2.5 动作门：改 `docs/ui/prototypes/admin-agent-playground.html`（如无则新建）+ `Design: pass` 后动 UI 源码 |

### 2.6 依赖系统或接口

| 依赖 | 用途 | 风险 |
|---|---|---|
| `agent-core` 包 | StreamEvent 契约 + 引擎装配 + runner | 已有，只增不改 |
| `ai-service` agent-log 内部端点 | agent_runs 落库 | 已有，仅传参语义变化 |
| 反向代理空闲超时（nginx/网关） | keepalive 间隔对照 | 15s 间隔 < 常见 60s 空闲超时，留 4 倍余量 |

### 2.7 初始化数据 / 种子数据

无。本批不涉及数据迁移/种子。

### 2.8 权限模型

| 端点 | 门 | 说明 |
|---|---|---|
| `/agent/run` | AuthGuard（登录即可） | C 端场景 |
| `/agent/admin-run` | PermissionGuard + `agents:debug` | 不变 |
| `/agent/permission/:id` | AuthGuard | 不变；越权判定在 broker（userId 比对） |

### 2.9 接口设计约束

- SSE 帧**只增字段不改语义**——`runId` 挂在 intent/final/error 上，旧前端忽略未知字段。
- `scene` 缺省按 `'c-end'` 处理——**安全侧默认**：admin 未传 scene 时宁可过滤掉 requiresConfirm 工具（admin 可显式传 `scene: 'admin'`）。
- 越权即拒的攻击面评估见 permission-broker.ts 注释：requestId 为随机 UUID，能发起越权调用的人必然能看到 SSE 流（与「不确认等超时」等价），只是把失败提前。

## 3. 影响面与风险

### 3.1 改动范围矩阵

| 文件 | 改动 | 类型 |
|---|---|---|
| `packages/agent-core/src/interfaces/runtime.interface.ts` | StreamEvent + RunInput 加字段 | 契约（只增） |
| `packages/agent-core/src/core/capability-resolver.ts` | 新增 `toolsRequiringConfirm()` | 新增函数 |
| `packages/agent-core/src/core/agent-engine.ts` | C 端装配过滤 + 日志 | 行为变更 |
| `packages/agent-core/src/core/agent-runner.ts` | runId 透传 | 透传 |
| `servers/ai-agent/src/agent/permission-broker.ts` | 越权即拒 + 返回码 | **行为变更** |
| `servers/ai-agent/src/agent/agent.controller.ts` | 心跳 + runId + scene + 确认接口返回体 | 行为变更 |
| `servers/ai-service/src/agent-log/agent-log.service.ts` | runId 作主键 | 行为变更 |
| `apps/admin/src/views/Agents/AgentPlayground.vue` | intent 消费 | UI（走原型门） |

### 3.2 风险分级

| 风险 | 等级 | 缓解 |
|---|---|---|
| C 端工具变少（被过滤）导致能力「缩水」 | 中 | 仅过滤 `config.requiresConfirm` 显式标记的工具；日志记录过滤数量；误配可查日志发现 |
| agent_runs 主键改传入值，历史数据不受影响 | 低 | 只影响新写入行；主键类型仍 CHAR(36)，兼容 |
| 越权即拒改变超时语义 | 低 | 失败提前≠语义反转；返回码只增不改 `ok` 语义 |
| keepalive 帧被旧前端当未知事件 | 低 | SSE 注释帧（`: ...`）不进事件解析，纯保活 |

### 3.3 兼容性

- **SSE**：注释帧（`: keepalive`）符合 SSE 规范，EventSource 自动忽略，旧前端零影响。
- **runId 字段**：只增不改，旧前端忽略。
- **permission 返回体**：`ok` 字段语义不变（true/false），新增 `code` 仅在 false 时出现。
- **agent_runs**：类型不变，仅 id 取值来源变。

### 3.4 是否灰度

否。改动集中在会话链路，dev 先发验证后再发 prod（走 web-system-deploy 发布 skill）。

## 4. 测试方案

### 4.1 单元测试

| 用例 | 断言 |
|---|---|
| `toolsRequiringConfirm` | 只收 `config.requiresConfirm===true` 的 tool/mcp ref；enabled=false 不计 |
| C 端过滤 | `scene:'c-end'` 时 banned 工具不在 toolSchemas；`scene:'admin'` 时不滤；缺省滤 |
| broker 越权 | 越权 → 返回 `{ok:false, code:'forbidden'}` 且挂起 Promise 立刻 resolve(false) |
| broker not_found | 不存在/已处理 → `{ok:false, code:'not_found'}` |

### 4.2 接口 / 集成测试

| 用例 | 步骤 | 断言 |
|---|---|---|
| 慢工具保活 | 挂 90s sleep 工具，抓 SSE 流 | 工具执行期间每 15s 一帧 `: keepalive`，连接不被掐 |
| 越权即拒 | 用户 A 发起需确认工具，用户 B 调 permission 确认 | B 立刻拿到 `forbidden`；A 的工具立刻失败（非 60s 后） |
| runId 反查 | 发起 run，记下 final 帧 runId | `SELECT * FROM agent_runs WHERE id = runId` 命中 |

### 4.3 功能测试用例矩阵

| 场景 | 端 | 期望 |
|---|---|---|
| 普通问答 | C | 全帧带 runId，最终 answer 正常 |
| 触发需确认工具 | C | 该工具**不在**工具清单，模型改用其他手段或明说做不到 |
| 触发需确认工具 | Admin | 工具在清单，弹确认框（既有行为不变） |
| 意图分类 | Admin | 调试台可见 intent 卡片 |

### 4.4 回归范围

- `selfcheck-ui-gate.sh`（若 N6 动 UI）
- SSE 契约扫描 `check-sse-contract.py`
- agent-core 既有单测
- C 端对话冒烟（一条普通问答 + 一条带工具调用）
