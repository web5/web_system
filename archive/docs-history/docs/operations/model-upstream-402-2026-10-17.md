> 状态：默认模型路由的 402 已复现，同一 Key 下其它模型调用正常；不能认定整个账号未开启后付费。网站尚未切换模型配置。
> 本轮未修改 dev/prod 配置、模型定义或密钥，未重启服务，未开启付费或执行充值。

## 1. 结论

dev 和 prod 的通用助手调用均被 TokenHub 返回 HTTP 402，业务码均为 `401008`，类型为 `permission_error`。

上游返回的中文原因是：本次命中的服务免费体验额度已经用完，而且没有启用后付费，因此不能继续调用。该描述必须限定为本次请求命中的服务，不能推断整个账号都没有开通后付费。

用户确认后付费已经开启后，进行了同 Key 对照：hy3、deepseek/deepseek-flash、deepseek-v4-flash-0731 都返回 200 且有正文；只有网站当前绑定的 deepseek/deepseek-v4-flash 返回 402/401008。prod 也复验了 deepseek/deepseek-flash，可正常返回正文。因此撤回“账号整体未开启后付费”的过度结论，当前问题已收窄到指定模型 ID/服务路由的行为差异。

这不是 GitHub 连接问题，也不是本次请求 API Key 鉴权失败。改变 GitHub 认证方式、重启全部服务、反复重试同一对话，都不是已经证实的修复办法。

## 3. 与本地工具、Token Plan 的区别

- 服务器实际请求没有使用本地另存的 TOKENPLAN_API_KEY；本地工具可用不能直接证明网站使用的普通推理服务还有额度。
- 本地 llm.env 的 TOKENPLAN_BASE_URL 当前仍指向普通 /v1。腾讯云当前 Token Plan 接入文档使用专属 /plan/v3 兼容入口，并要求匹配套餐支持的模型 ID。
- 因而即使决定使用已有 Token Plan，也必须同时核对专属 Key、接入地址、套餐类型、可用模型及适用范围，不能仅复制一个 Token 或直接套用现有本地地址。
- 本轮未测试另一把套餐 Key，未切换网站计费路线，没有自动借用 WorkBuddy 的账号凭据。

## 4. 恢复前需要的动作

### 核对当前模型对应的服务

不要求用户重复开启整个账号的后付费。先核对当前模型 ID 实际映射到的服务与已开通服务是否一致；如果用户确已为该具体服务开通，应携模型 ID 与错误信息进一步核查服务映射/生效状态，不凭通用错误文案再次开启计费。

### 使用另一份已开通、适用的配置

已有同 Key、同 Base URL 的可用 Flash 模型路由。若采用切换方案，需同时核对模型字典、Agent 注册清单及已发布定义，先验 dev 再经授权同步 prod，保留原配置回退；不要仅改一个显示名称。

更换模型 ID 可能改变实际版本/通道，不能把探针成功当作已获生产切换授权；本轮未批量覆盖凭据、切换模型或擅自降级到 hy3。

### 处理后复测

1. 用相同最小探针确认推理返回成功，不再出现 401008。
2. 检查实际响应模型 ID、正文、结束原因及用量，而非只看 HTTP 200。
3. 再验 dev/prod 各一条真实网站流式对话；如配置未变，不把重启列为必需修复动作。
