# 设计评审清单（Design Review Checklist）

> 用途：`design-reviewer` 评审时逐维度过。每条须给出**判据编号**（指向 `docs/ui/design-system.md`），判不到编号的意见降级为「建议」。
> 关口：D1 设计输入 / D2 原型规格 / D3 实现一致性。标注「仅 D3」的条目在其他关口不适用。
> 与 `ux-prototype-designer/references/ux-review-checklist.md` 的关系：那份是**出稿下限**（生产者自过），本清单是**独立复审水位**（第三方），不互相替代。

## A. 信息架构（判据：P1 / M1–M6）

- [ ] 页面清单完整，本次范围无缺页
- [ ] 每个入口可达、有返回路径，无死链、无跳转环
- [ ] 导航层级 ≤3 层，符合任务心智
- [ ] 页面类型已判定（列表 / 详情 / 表单向导 / 仪表盘 / 例外），骨架未自创 —— admin 系另查 `docs/ui/design.md` §1

## B. 任务流闭环（判据：P3 / P6）

- [ ] 主路径从入口到完成全程可走通
- [ ] 同操作的 空 / 错 / 超时 / 无权限 分支都有明确去向（不吞错）
- [ ] 跨页面流程衔接正确（上一步产出 = 下一步输入，状态可预期）
- [ ] 需求未定义的路径**已显式标注待确认**，未自行脑补（P6 / X7）

## C. 状态矩阵（判据：S1–S9）

- [ ] 加载中可见，且**无假 loading**（S1 / S2）
- [ ] 空态 = 原因 + 出路（S3）
- [ ] 失败 = 问题 + 怎么办 + 可重试路径（S4）
- [ ] **无权限**态有显式说明与唯一出路（S5）
- [ ] 禁用态有原因说明（S7）
- [ ] 进行中锁重复提交（S8）
- [ ] 弹窗不嵌套（S9）

## D. 操作与确认（判据：E6 / E8 / S6 / M5）

- [ ] 一屏 primary ≤1（E6）
- [ ] 破坏性操作二次确认，文案写明后果与影响面（S6）
- [ ] 行内操作 >3 已折叠（E8）
- [ ] 非破坏性操作未被无谓确认拦截（M5）

## E. 视觉层级与密度（判据：E1–E9）

- [ ] 层级由字号+字重+色阶组合表达，非加粗堆叠（E1 / X3）
- [ ] 一屏只有一个主视觉焦点（E2）
- [ ] 字重仅 400/500/600（E3）
- [ ] 字号均取自字阶，无阶外自定义值（E4）
- [ ] 标题层级不跳级（E5）
- [ ] 行高/表头字号/同屏条目数与同端参照页同量级（E7 / P5）
- [ ] 数据密集区无装饰模块（E9 / P1）

## F. 间距与对齐节奏（判据：F1–F5）

- [ ] 间距取自阶梯，无阶外随意值（F1）
- [ ] 同级等距、组间距 > 组内间距（F2）
- [ ] 卡片内边距四周相等；列表行左右同一基线（F3）
- [ ] 数字列 tabular-nums；端口/ID/路径/代码等宽（F4）
- [ ] 无空行 / 多个换行撑间距（F5）

## G. 色彩语义、对比度与表面（判据：G1–G9）

- [ ] 无裸 hex / rgba，无新增 `!important`（G1 / X4）
- [ ] 颜色只编码语义，类型/枚举未配色（G2 / X6）
- [ ] 正文对比度 ≥4.5:1、大字 ≥3:1（G3）
- [ ] 品牌橙作文本/选中态时用深档，未用 #F97316 写正文（G4）
- [ ] hover / active 走既定阶梯，无自定义灰（G5）
- [ ] 语义色未被挪作"强调好看"（G6）
- [ ] 圆角取档且同层级一致（G7）
- [ ] 分隔优先 hairline，未靠阴影堆层级（G8 / G9）

## H. 排版与文案语气（判据：H1–H6）

- [ ] 按钮动词开头（H1）
- [ ] 无冗余敬语 / 客套（H2）
- [ ] 副标题一句话说明用途，非宣传腔（H3）
- [ ] 错误文案含"出了什么问题 + 怎么办"（H4）
- [ ] 术语全文一致（H5）
- [ ] 无 lorem / TBD 占位堆砌（H6）

## I. 品牌与端一致性（判据：I1–I5，串端即阻塞）

- [ ] 目标端已确认（admin 系 / 品牌端），判据源按端取用
- [ ] 未串端：token 名、页面底、圆角、单位（px / rpx）与目标端匹配（I2 / I4）
- [ ] 主色与文本档符合该端（I1 / G4）
- [ ] 图标为 SVG，**无 emoji**（I5 / X5）
- [ ] 平台原生能力（分享/授权/支付/订阅消息）为占位 + 标注真机语义，未伪装已实现（I5 / X8）
- [ ] 非 Web 端稿未混入落地代码（WXML / 原生页）

## J. 可访问性基线（判据：G3）

- [ ] 文字对比度达标，字号不小于端内基础值
- [ ] 可点击元素键盘可达（原型阶段标注即可）
- [ ] 可点击区用按钮/链接语义而非裸 div（原型阶段可标注）

## K. 与规格 / 需求一致性

- [ ] 与 page-spec 的字段、状态、操作清单一致，无漏项
- [ ] 满足需求 spec 的验收判据（不满足即为阻塞）
- [ ] 业务必显字段齐全（金额 / 状态 / 时间 / 操作者等）

## L. 目标端一致性

- [ ] 壳与宿主元素匹配目标端（桌面壳 / 竖屏手机壳 / 小程序胶囊 TabBar / 原生导航）
- [ ] 多端需求时本次主目标端明确，未混壳、未做跨端响应式（落地页双视口并置需显式分区）
- [ ] 品牌端已适配安全区（`env(safe-area-inset-bottom)`）

## M. 未定义项显式标注（判据：P6）

- [ ] 所有"需求未定义、本稿假设了方案"的交互路径都已标注待确认
- [ ] 无静默发明的降级行为

## N. 实现一致性（仅 D3，判据：A1–A4 / X9）

- [ ] 原型锚点 `data-dr="<key>"` 在实现中**全部存在**且同语义（A1 / A3）
- [ ] 新增/改名锚点已在评审报告登记（A3 / X9）
- [ ] 可机检条目通过：无裸色 / 无 emoji / 无新增 `!important` / 字重未越界 / 间距未出阶梯
- [ ] 原型截图 vs 实现截图并置（存 `docs/ui/baselines/`），E/F/G/H/I 各维度差异已逐条列出
- [ ] 存量页面：若尚未回填锚点，标注"锚点未回填，本轮跳过比对"（不判为漂移，见方案 §3.7.1）

---

## 反模式（评审看到即记阻塞）

- 拿「产品已确认方向」跳过评审 —— 产品确认 ≠ 设计合格
- 只画主路径，异常分支全缺（X1）
- 空/错态一句灰字无出路（X2）
- 用加粗堆叠表达层级（X3）
- 裸 hex / 新增 `!important`（X4）
- emoji 当图标（X5）
- 类型 / 枚举配色（X6）
- 需求未定义自行脑补且不标注（X7）
- 多端串壳 / 原生能力伪装已实现（X8）
- 实现删掉或改名原型锚点且未登记（X9）
- 评审意见无判据编号（= 个人偏好，须降级为建议并标注）
