# UX 交互质检清单（UX Review Checklist）

> 本角色（`ux-prototype-designer`）交付前的**独立交互质检**——不等同于产品价值确认，也不等同技术/代码评审。
> 用途：原型稿产出后、交用户确认前逐条自检；质检通过的项与遗留项随稿交付，供产品/技术评审复用。
> 使用对象：任何「可点击交互 HTML 原型稿」交付，无论层级（低保真 / 高保真）都须过本清单（低保真只覆盖架构类条目并显式标注未覆盖项）。
> 与产品确认的关系：产品确认拍板「这是不是我们想要的产品」；本清单把关「这份稿本身作为交互设计是否合格」。两者不能互相替代。

## A. 信息架构

- [ ] 页面清单完整：本次范围的所有页面/屏幕都有，无缺页。
- [ ] 每个入口可达、有返回路径，无死链（所有跳转都能点、能回）。
- [ ] 导航结构符合用户任务心智（层级不超 3 层 / 语义清晰的惯例），无跳转环。

## B. 任务流闭环

- [ ] 主路径闭环：核心任务从入口到完成全程可走通。
- [ ] 异常分支覆盖：同一操作的 空 / 错 / 超时 / 无权限 分支都有明确去向（不吞错）。
- [ ] 跨页面流程衔接正确（上一步的产出是下一步的输入，状态可预期）。

## C. 状态矩阵

- [ ] 加载中：骨架屏或进度可见（关键异步流程有模拟时序）。
- [ ] 空态 / 错误态 / 无权限：可见且有唯一恢复入口（重试 / 返回）。
- [ ] 完成态反馈：提交/操作成功有明确反馈（Toast / 页面跳转 / 状态变化）。

## D. 操作与确认

- [ ] 主操作一屏 ≤ 1（primary 视觉不打架）。
- [ ] 破坏性操作有二次确认（写明后果与影响面）。
- [ ] 禁用 / 进行中状态正确（重复提交被锁、无效操作被禁）。
- [ ] 表单校验有错误文案 + 字段级提示（不只整页报错）。

## E. 视觉与 Token 一致性

- [ ] Token 化：无裸 hex/rgba（除 `:root` 定义处）；语义色经 `--danger/--warn/--ok` 表达。
- [ ] 主色与目标端匹配（admin 平台主色 / 品牌产品色），深浅二选一不混用。
- [ ] 无 emoji 图标；图标为内联 SVG；间距取 8 的倍数。
- [ ] 字号三级表达层级，不靠加粗堆叠。

## F. 可访问性基线

- [ ] 可读性：文字对比度达标、字号不小于基础值。
- [ ] 键盘 / 焦点：可点击元素可被键盘到达（原型阶段标注即可，不要求完整实现）。
- [ ] 语义：可点击区用按钮/链接语义而非裸 div（原型阶段可标注）。

## G. 内容与真实性

- [ ] 文案真实业务文案（无 lorem / 无「测试」「TBD」占位堆砌）。
- [ ] 信息展示完整：无关键信息缺漏（金额/状态/时间/操作者等业务必显字段）。

## H. 目标端一致性（多端定义专用）

- [ ] 目标端已确认并回显（桌面 Web / 移动 H5 / App / 小程序 / 定制落地页；未定时已列为待用户拍板，非静默选定）。
- [ ] 壳与宿主元素匹配目标端：桌面壳、竖屏手机壳、小程序胶囊/TabBar、原生导航等各归各位，无跨端元素混入。
- [ ] 平台原生能力（分享/授权/订阅消息/支付/下拉刷新等）为占位 + 标注真机语义，未伪装成已实现。
- [ ] 非 Web 端稿未混入落地代码（WXML/原生页）；定制落地页双视口并置有明确分区与视口标注。

## I. 未定义项显式标注（不脑补）

- [ ] 所有「需求未定义、本稿假设了方案」的交互路径，都在设计决策记录中显式标注待确认。
- [ ] 无静默发明的降级行为（无业务定义的分支不自行定死）。

## 反模式

- 拿「产品已经确认方向」跳过本清单——产品确认 ≠ 交互设计合格
- 只画主路径、异常分支全缺
- 空态/错误态用一句灰字带过，没有恢复入口
- 用 lorem / 占位文案交差，评审看不出真实内容层级
- 需求未定义的交互路径自行脑补默认行为且不标注
- 多端原型串壳（桌面稿冒胶囊、H5 稿冒充原生能力、未定目标端直接开画）
