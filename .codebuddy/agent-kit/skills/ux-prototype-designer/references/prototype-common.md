# UX 原型交互设计师 · 通用原型稿生成方法（prototype-common）

> 定位：`ux-prototype-designer` 角色的**通用原型稿生成方法**——把「文字需求」变成「可点击交互 HTML」的标准执行方法。不绑定技术栈与项目。
> 与项目层的关系：**本文件只写通用方法**。骨架模板、目标端壳容器 class/基准宽、具体色值 token、文件目录与命名、页面类型参照页、落地技术栈均为项目层提供（项目 UI 规范 / 工程 skill 如 fe-developer）。
> 加载顺序：通用方法（本文件）→ 项目层（先取项目模板与数值，再执行）。
> 前置关联：原型稿「是否产出」由**人拍板**（见 `skills/rd-plan` §3.5：UI 大改 / 新功能 / 跨模块 → 建议产出；小改动 / 简单 CRUD → 可省）。判定产出后按本文件执行，产物须过 `references/ux-review-checklist.md` 独立交互质检，再交**人确认**后才进入规格化与编码。

## 一、定义与分层

原型稿是「需求对齐工具」——介于文字需求与最终代码之间、可点击交互的 HTML。它是**沟通产物，不是最终代码**：零构建、零依赖、单文件，浏览器双击即开，用于给产品/用户快速确认信息架构与关键交互，确认后即销毁或按项目约定留档。**HTML 只是模拟壳**——不论目标端是网页、App 还是小程序，原型都统一用 HTML 承载（见 §三），差异体现在壳的宿主元素与可用交互集，而非落地技术。

| 层级 | 目的 | 投入 | 特征 |
|------|------|------|------|
| 低保真（线框） | 确认信息架构 / 页面流程 | ~5 min | 灰块 + 占位文字，无真实配色，只画跳转关系 |
| 高保真（可交互） | 确认视觉与交互细节 | ~30 min | 真实 Token + 真实文案 + 可点击跳转 + 模拟加载 |

默认出**高保真**；仅当架构完全未定时先用低保真对齐，再升级。

## 二、触发决策（何时生成）

- **必生成**：新功能/新页面、信息架构多方案、跨页面流程、用户明确要求先「看」交互。
- **可选**：现有页面改造做 A/B 对比稿。
- **不生成**：纯样式微调、字段明确的简单表单——直接走规格书，不走原型。

生成时机在「判类型 → 填规格书 → 用户确认」**之前或并行**，确认后再回填规格书。

**目标端确认**：生成前先与用户对齐本稿面向哪类目标端（桌面 Web / 移动 H5 / 移动 App / 小程序 / 定制落地页）。用户未提时，UX 按需求场景给出建议（如「管理后台 → 桌面 Web」「手机打开的营销页 → 移动 H5 / 定制落地页」）并标注为待用户拍板项，不自行静默选定后不告知。

## 三、基础框架约定（方法，具体数值随项目模板）

1. **单文件**：`<style>` + 结构 + `<script>` 全内联，无外部 CSS/JS/字体/CDN，无构建步骤。
2. **目标端与视口**（替代旧的「移动/桌面」二选一）：
   - 按 §三·A 目标端矩阵确认**目标端**；一次原型聚焦**一个主目标端**，禁止把多端宿主元素混进同一壳。
   - 视口由目标端决定：移动 H5 / App / 小程序 → 竖屏手机壳（逻辑宽约 390px）；桌面 Web → 宽屏桌面壳；定制落地页 → 按需求确认的视口（可双视口并置，见 §三·B-5）。
   - 骨架优先**复制项目提供的 scaffold 模板**（含各目标端壳），删掉不用的那种，不从零写结构。
3. **`:root` Token 化**：颜色/圆角/阴影全部 CSS 变量；业务样式只引变量，裸 hex/rgba 只允许出现在 `:root` 定义处。
4. **页面骨架**：随目标端（见 §三·B 各端小节），通用不变式为——移动系 `状态栏 → 导航栏 → 多屏(默认隐藏，激活显) → 底部导航`；桌面系 `侧边栏 → 顶栏 → 内容区多屏`。
5. **图标**：内联 `<svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2">`，颜色继承文字色；**禁 emoji 图标**（与通用图标规则一致）。
6. **字体栈**：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Helvetica Neue", "Microsoft YaHei", sans-serif`。

### 三·A 目标端矩阵（速查总览）

| 目标端 | 典型场景 | 主视口/壳 | 壳内可见系统元素 | 主导航骨架 | 落地承接（示例，以项目为准） |
|--------|---------|-----------|------------------|-----------|------------------------------|
| **桌面 Web** | 系统/后台/管理台 | 桌面壳（侧边栏+顶栏+内容区） | 菜单、面包屑、（可选）顶栏用户/通知 | 侧边栏菜单 ↔ 内容区多屏 | 桌面组件栈（如 Vue3 + Ant Design Vue） |
| **移动 H5** | 手机浏览器网页、App 内 WebView | 竖屏手机壳 | 浏览器环境（状态栏、无胶囊、无系统返回键） | 栈式导航 + 底部 Tab | 移动 Web 栈 |
| **移动 App** | iOS/Android 原生客户端页面 | 竖屏手机壳 | 原生导航栏（标题+返回）、安全区、原生底部 Tab | 栈式 push/pop + 底部 Tab | Flutter / RN / 原生 |
| **小程序** | 微信内小程序页面 | 竖屏手机壳 | **右上角胶囊**（…/转发，占位即可）、导航栏标题、底部 TabBar、可下拉刷新 | 页面栈 + TabBar 切换 | 小程序栈（原生 WXML / TDesign-miniprogram / uni-app 等按项目） |
| **定制落地页** | 品牌官网/活动/营销/专题 | 按确认视口（桌面宽屏 或 竖屏手机壳；双视口并置见 §三·B-5） | 无系统导航；品牌头/页脚 | 单页长滚动 / 分节 / 锚点 | 项目品牌技术栈 |

> 分类非封闭：项目可在 §八 契约处叠加自有目标端或覆盖默认骨架。拿不准目标端 → 列为待确认项，交用户拍板。

### 三·B 目标端细化（骨架与端特有交互）

#### B-1 桌面 Web（系统 / 后台 / 管理）
- **骨架**：`侧边栏 → 顶栏 → 内容区多屏`。侧边栏按信息架构分组菜单，顶栏含当前页名与全局操作，内容区为本次范围的多屏（默认隐藏、激活显）。
- **系统元素**：菜单选中态、面包屑、空/错态与返回/重试、表格列筛选排序（如需）。
- **端特有注意**：桌面端没有移动手势/下拉刷新语义；悬停态可作为状态表达（原型阶段标注即可）。

#### B-2 移动 H5（手机浏览器 / App 内 WebView）
- **骨架**：`状态栏 → 导航栏(含返回) → 多屏 → 底部 Tab`。
- **系统元素**：浏览器环境——无胶囊、无系统返回键；导航栏由页面自带返回入口承担返回路径。
- **端特有注意**：下拉刷新只在需要时画（H5 原生不默认有，需引入库/手势才成立，原型勿静默假设）。

#### B-3 移动 App（iOS / Android 原生客户端）
- **骨架**：同 H5（状态栏/安全区 → 原生导航栏 → 多屏 → 原生底部 Tab），但**宿主按原生语义**：返回走导航栏返回/边缘滑动手势，Tab 切换是原生 TabBar，无浏览器元素、无胶囊。
- **端特有注意**：ActionSheet/弹窗/Toast 按各端惯例表达；iOS 与 Android 差异（如安全区、返回方式）若影响设计，在设计决策记录里标注取哪一端为基准。

#### B-4 小程序（如微信小程序）
- **骨架**：`小程序导航栏(标题居中 + 右上角胶囊占位) → 多屏 → TabBar`；Tab 对应的页面才是 Tab 切换，详情等子页走页面栈 push。
- **系统元素**：**胶囊占位**必须画入导航栏（约 87×32px、贴屏幕右上，具体以真机 `getMenuButtonBoundingClientRect` 为准，原型为占位视觉）；列表页可下拉刷新（`enablePullDownRefresh` 语义）、上拉加载更多。
- **端特有注意**：转发/分享、授权（手机号/位置/隐私）、订阅消息、调起支付等是**平台原生能力**——HTML 无法真实触发，原型以「占位入口 + 点击 Toast『[小程序] 转发分享，落地以真机为准』」表达，并在设计决策记录标注「此能力在原型为模拟，真机行为以小程序规范为准」。默认标准导航栏；若页面采用自定义导航（`navigationStyle: custom`），需显式说明并保证安全区/胶囊避让。

#### B-5 定制落地页（品牌 / 活动 / 营销 / 专题）
- **特征**：无后台模板、无系统导航，**重视觉、结构不固定**；主路径通常是从首屏到 CTA（报名/下单/跳转）的转化流。
- **骨架**：品牌头 → 首屏主视觉（Hero）→ 内容节（图文/卡片/表单按内容）→ CTA 区 → 页脚。锚点导航/平滑滚动按页长可选。
- **桌面与移动双视口**：落地页常需桌面版 + 移动版都确认。允许**同一文件内两个独立视口容器**（容器各自固定宽度、互不影响、不做跨端响应式），在容器外标注各自视口；或按项目约定拆两份文件。若本次只确认一个视口，明确写出当前稿覆盖的视口，另一视口列为待确认。
- **端特有注意**：动效（首屏渐入/视差）属视觉表达，原型用 CSS 简单模拟并标注「终版动效以设计稿为准」，不写重逻辑。

## 四、设计 Token 方法（不绑定具体色值）

```css
:root{
  --primary:〈项目主色〉; --primary-dark:〈深一档〉; --primary-soft:〈浅底〉; /* 主色三态 */
  --bg:〈页面底〉; --card:〈卡片底〉;         /* 背景/卡片（暗底端改深） */
  --text:〈主文字〉; --text-2:〈次文字〉; --text-3:〈弱文字〉; /* 文字三级 */
  --danger:#E5484D; --danger-soft:#FDEBEC;   /* 语义色可用通用默认 */
  --warn:#E8833A;  --warn-soft:#FFF3E6;
  --ok:#2E9E5B;    --ok-soft:#E7F5EC;
  --border:〈分隔线〉; --radius:〈大圆角〉; --radius-sm:〈小圆角〉;
  --shadow:〈卡片投影〉;
  --gap:8px;  /* 间距栅格基准（8px 体系） */
}
```

- **主色取值**：admin/内部工具用平台主色；品牌/产品端（含 H5/App/小程序/落地页）用产品品牌色——具体值从项目设计系统取，不在通用层定死。
- **暗底/亮底**：随目标端与产品基调定（如品牌端可用深色、后台默认亮色），单稿内不混用；暗底端只改 `--bg/--card/--text/--text-2/--border`，主色不变。
- **字号阶梯**：标题 / 正文 / 次要 三档，靠 `font-size` + 三级文字色表达层级，不用加粗堆叠。
- **间距**：所有 padding/margin 取 8 的倍数（8/12/16/20/24）。
- **语义色**：危险/警告/成功只经 `--danger/--warn/--ok` 表达，不裸写红绿黄。

## 五、交互模式库（概念清单，实现随项目 scaffold 取用）

| 模式 | 作用 | 适用端 | 说明 |
|------|------|--------|------|
| 栈式导航 `go`/`back` | 多屏切换 + 返回栈 | 移动 H5 / App / 小程序 | 移动系主路径 |
| 底部 Tab `switchTab` | 主 Tab 切换 | 移动 H5 / App / 小程序（TabBar） | 全局导航 |
| 桌面菜单 `desk` | 侧边栏 + 内容屏联动 | 桌面 Web | 桌面端主路径 |
| 弹层 `openModal`/`closeModal` | action sheet / 确认框 | 全部（形态随端惯例） | 二次确认载体 |
| Toast `toast(msg)` | 轻提示 | 全部 | ~1.5s 自动消失 |
| 手风琴 `toggle(el)` | 展开/收起 | 全部 | 信号卡 / FAQ |
| 表单校验 `.field.err` + `.msg` | 错误态展示 | 全部 | 配合校验文案 |
| 异步模拟 `simulate` / `setTimeout` | 加载中 → 完成 | 全部 | 让评审感知真实时序 |
| 下拉刷新 / 上拉加载 | 移动列表刷新与分页 | H5（按需）/ App / 小程序 | 小程序为原生语义，H5 勿静默假设 |

- 列表四类状态必须可在原型体现：**骨架屏**（loading）、**空态**、**错误态**、**加载更多**。
- 关键异步流程用 `setTimeout` 模拟进度，让评审感知真实时序。
- **平台原生能力占位**：转发/分享、授权弹窗、订阅消息、调起支付、拨号/定位等 HTML 无法真实模拟的原生能力，一律「可见入口 + 占位反馈 + 决策记录标注真机语义」，不假装已实现。

## 六、页面类型最小结构（通用分类，与目标端叠加使用）

> 页面类型决定**内容组织**，目标端决定**壳与导航**，两者正交：同一「列表页」在小程序是 TabBar 页内列表 + 下拉刷新，在桌面 Web 是侧边栏内表格页。

| 类型 | 原型最小结构 |
|------|--------------|
| 列表页 | 搜索/筛选条 + 卡片×N 列表项 + 底部分页/加载更多 + 空/错态 |
| 详情页 | 顶部 Hero/标题 + 信息分组卡片 + 主操作按钮（≤1） + 关联入口 |
| 表单页 | 字段×N（含校验态）+ 提交按钮（loading 态） |
| 仪表盘 | 指标卡网格 + 图表占位块（灰块标注「图表：XXX」）+ 时间筛选 |
| 例外页 | 空/错/无权限占位 + 唯一返回/重试入口 |

> 页面类型判定与骨架顺序若项目有 design/页面规范，以项目规范为准（如 web_system `docs/ui/design.md` §1）。

## 七、与规格书 / 最终代码的关系

- 原型确认 → 填项目规格书模板（如 `page-spec-template`）→ 用户确认 → 按项目 UI 规范编码。
- 落地技术栈随项目与目标端：如 web_system admin 系 Vue3 + Ant Design Vue，品牌端 portal/mini-app 走品牌视觉规范，小程序端按项目小程序栈。
- 原型 Token 与项目 tokens 对齐，但原型**内联 CSS 变量，不 import 业务包**。
- 规格书需继承原型稿声明的**目标端**与**平台能力占位项**，避免规格化时丢失端约束。

| 规格书模板 | 项目（如 `page-spec-template.md`） |

## 九、不做什么

- 不把原型当最终产物提交进应用代码目录（只活在约定文档目录）。
- 不引外部依赖 / 框架 / CDN。
- 不在原型里写裸 hex（除 `:root` 变量定义）、不新增 `!important`。
- 不用 emoji 图标。
- **一稿一主目标端**：不把多端宿主元素混进同一壳（如桌面壳里出现胶囊、H5 稿冒充原生能力）；定制落地页的双视口并置需显式分区标注，不做跨端响应式自适应。
- 不跳过 `references/ux-review-checklist.md` 独立质检直接宣布「原型完成」。
