# 设计原则（通用）

适用于任何系统、文档结构或流程的设计评审。

## 拆分与边界

- 按领域 / 职责域拆分，而非按技术层拆分。
- 每个单元有单一职责，边界清晰。
- 单元间通过明确契约通信，不共享内部状态。
- 避免过早拆分（一个功能一个单元）与过度耦合（共享内部）。

## 信息与设计

- 结构规范为基础，再按检索 / 复用模式优化。
- 设计结构时同步设计分类 / 标签 / 检索路径。
- 用约定层保证一致性，避免隐式耦合。
- 大体量内容提前规划分类 / 归档策略。

## 对外交付物

- 交付物命名用名词，语义稳定。
- 版本化对外交付物，避免破坏性变更。
- 格式统一。
- 操作可重复执行且结果一致（幂等）。

## 结构原则

- 模块 / 单元驱动：整体 = 局部组合。
- 共享定义上提，集中管理。
- 按需加载，避免一次性全量。
- 样式 / 配置隔离，避免相互污染。
