# 写作与交付规范（通用）

适用于任何以文字/文档为产出的工作：方案、报告、文档、邮件、文案。

## 命名与文件

- 文件与章节用描述性名称，避免 `tmp`、`test1`、`func1` 之类无意义命名。
- 术语全称优先；缩写首次出现时给出定义。
- 固定值/常量集中声明，并注明来源或理由。

## 结构组织

- 结论先行：先给结论或摘要，再展开论证。
- 同级标题层级一致，不跳级。
- 长文档用编号或目录分层，便于定位。
- 引用顺序由远及近：外部依赖 → 内部模块 → 局部。

## 表达规范

- 主动语态、具体动词；避免「东西」「一些」「相关」等模糊词。
- 数字与事实标注来源；观点与事实分开陈述。
- 说明面向决策理由（为什么），而非复述内容（是什么）。

## 版本与变更

- 成稿保留修订版本，不以后一版覆盖全部历史。
- 重大变更在文档内以「变更记录」标注：时间、变更点、原因。
- 提交信息一句话说明「做了什么、为什么」。

## 产出前自检

- [ ] 命名/术语无歧义
- [ ] 结构结论先行、层级一致
- [ ] 事实有来源、观点独立于事实
- [ ] 保留版本与变更记录
