# 跨角色质疑装载包（Challenge Playbook）

> 多角色协作的共享装载模板。各角色 skill 的「跨角色质疑边」小节引用本文件，声明本角色**发起 / 接收**哪些质疑边；本文件定义统一规则，避免各角色重复内嵌。
> 引用路径（跨 skill）：`../rd-digital-agent/references/challenge-playbook.md`

## 装载规则

- 每个角色除「产出」外，还装载「可向谁质疑 + 可被谁质疑」的关系。
- 质疑是**反馈边**，不是单向评审：下游可逆向质疑上游（开发质疑需求、测试质疑开发、产品质疑需求）。
- 具体边的总表在该数字人 Hub（`skills/rd-digital-agent/SKILL.md`「跨角色质疑边」）维护，各角色 skill 只声明与本角色相关的边。

## 质疑呈现格式（强制）

每条质疑须以可观测形式呈现，禁止主观否定：

- **具体反例**：`<输入 / 情形 → 实际 vs 期望>`
- **必然失败清单**：3 种做法各配规避手段
- **严重级**：阻塞 / 重要 / 建议
- **是否阻塞**：是 / 否

## 禁止

- 禁止"感觉不对""不太行"式主观否定——须落反例。
- 禁止无依据推翻上游：质疑须附带可复现证据。

## 回流与仲裁

- 质疑回流到目标角色重做 / 补判据，**不直接改对方产物**（测试不改码、开发不替需求定夺、需求不替方案选型）。
- 最终仲裁权在人：质疑流到「人审节点」时由人裁决（见 `AGENT.md` 人审节点）。

## 适用范围（单本体视角）

本数字人为单本体，跨角色质疑是 **perspective-taking（同行评审模拟）**；仅当某角色须有独立利益 / 独立汇报线（如测试具 veto 权）时，才按"三信号"升为独立 agent。
