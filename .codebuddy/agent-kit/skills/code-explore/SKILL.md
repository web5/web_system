# 🗺️ Code Explore（代码库探索）

## 职责

用最小上下文消耗建立对代码库的正确理解，为后续修改提供依据。

## 触发条件

- 进入陌生项目 / 陌生模块
- "X 在哪定义/实现"、"谁调用了 X"、"这个项目怎么组织"
- 修改前需要理解上下文

## 探索原则

1. **先索引，后细节**：先看目录结构 / 符号列表（symbol 索引、文件大纲），再深入具体实现；禁止一上来全文通读大文件。
2. **语义优先，文本兜底**：找定义/引用/调用关系优先用语义导航（定义跳转、引用查找）；仅日志、配置、未知模式才用全文匹配。
3. **由外及内**：入口 → 模块边界 → 关键路径 → 细节实现。
4. **批量并行**：多个独立的读取/搜索合并为一批执行，不逐个串行。
5. **按需加载（Just-in-Time）**：只保留路径、签名等轻量标识，需要时再加载全文；探索结论落盘，不依赖对话记忆。

## 工作流

```
目标（理解什么 / 改什么）
  ↓
1. 全局结构扫描（目录树 / 入口 / 配置）→ 形成模块地图
  ↓
2. 符号定位（workspace 符号搜索 / 定义跳转）→ 找到相关定义
  ↓
3. 关系确认（引用 / 调用链）→ 谁用它、它用谁
  ↓
4. 精读关键实现（只读相关段落，非全文件）
  ↓
5. 输出影响面清单（要改哪些文件、波及哪些调用方）
```

## 输出格式

```markdown
## 探索结论

### 模块地图（与目标相关部分）
> 结构图或列表

### 关键发现
- <符号> 定义于 <file:line>，被 N 处调用：<调用方摘要>

### 影响面
- 修改 <X> 需同步检查：<文件 / 调用方清单>

### 建议路径
> 改动的切入顺序
```

## 反模式

- ❌ 通读整个文件找一处定义（应用符号导航）
- ❌ 串行逐个读文件（应批量并行）
- ❌ 只看手头文件就动手改（漏掉全量同类调用点）
- ❌ 探索结论只留在对话里（应落盘供后续阶段使用）
