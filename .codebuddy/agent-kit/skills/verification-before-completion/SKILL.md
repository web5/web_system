# ✅ Verification Before Completion（完成前验证）

## 职责

把「看起来完成了」变成「验证过完成了」。完成声明 = 验证证据。

## 触发条件

- 准备说"完成"、"搞定"、"修好了"、"已通过"
- 交付产物给用户之前
- execute / debugging / refactoring 任何工作流的收尾

## 验证清单（按产物类型）

### 代码类
- [ ] 实际运行了受影响的测试（不是"测试应该会过"）
- [ ] lint / 类型检查通过
- [ ] 新功能按验收标准逐条对照过
- [ ] 无遗留调试代码（日志打印 / 临时代码）

### 文档/写作类
- [ ] 对照 spec / 大纲逐节核对
- [ ] 事实性陈述有来源
- [ ] 命名/格式符合约定

### 任何产物
- [ ] 验收标准逐条标注 ✅/❌，不许留空或含糊
- [ ] 未达成项显式列出；无业务定义的路径显式报错/提示，不静默降级或自行兜底

## 反模式

- ❌ "我修改了 X，现在应该没问题了"（未验证）
- ❌ 只跑了一个测试就宣称全绿
- ❌ 验收标准部分达成时宣称"完成"
- ❌ 用计划中的行为冒充已验证的行为

## 输出格式

```markdown
## 完成验证

### 验证手段
- 运行 <命令/测试> → 结果

### 验收对照
- [x] 标准 1：✅（证据）
- [x] 标准 2：✅（证据）
- [ ] 标准 3：❌ 未达成 → 已明确告知用户

### 结论
✅ 已验证完成 / ⚠️ 部分完成（差异如上）
```

## 与其他技能的关系

- 本 skill 是 `rd-execute`、`systematic-debugging`、`incremental-refactoring` 的收尾强制门
- 红线：跳过本验证的「完成」声明视为未完成
