# 前端开发通用技能与规则（fe-dev-common）

> 定位：技术产品型数字人的**通用前端开发能力包**——不绑定具体技术栈与项目，可移植到任何前端工程。用来指导开发、评审方案、自查交付。
> 与项目层的关系：**本文不含**具体设计系统、组件库选型、页面规范、工程架构（网关/微前端/发布）等组织级细节——这些在项目层，由具体项目维护其设计系统与工程架构规范。加载顺序：通用能力（本文）→ 项目规范。
> 用法：触发前端任务（新页面/功能/样式/交互/修复）时，先对照 §一 定位任务涉及的技能面，再按 §二 规则执行与自检；项目有更严规范时以项目为准，项目未规定处默认按本文。

## 一、技能清单（前端能力面）

| # | 技能面 | 核心要点（掌握到能评审也能实现） |
|---|--------|------|
| 1 | Web 与浏览器基础 | 语义化 HTML；CSS 布局（Flex/Grid/层叠上下文）；响应式断点；事件模型；渲染与重排成本；URL 语义与路由 |
| 2 | 语言与类型 | TypeScript 严格模式；用联合类型 / unknown 收窄建模，禁 `any`；async 错误路径显式处理 |
| 3 | 组件化与状态 | 组件职责单一、props 单向流；状态最小化（能派生不重复存）；受控组件；Effect 清理；避免全局可变状态泄漏 |
| 4 | 样式与主题化 | 颜色/间距/圆角/字号/阴影走语义 token（CSS 变量）；业务代码不写裸色值；light/dark 同 token 双值；组件库主题单出口 |
| 5 | UI 交互契约 | 一切会产生结果的操作覆盖状态矩阵：加载中/成功/失败/空态/禁用/破坏性；主操作 primary 一屏 ≤ 1；破坏性必二次确认；错误不静默 |
| 6 | 表单 | 受控 + schema 校验；提交锁防重复（saving）；打开编辑即回填；重置与脏值（dirty）管理 |
| 7 | 网络层 | 统一请求实例与拦截器；错误分类（网络/超时/4xx/5xx/业务码）；401 刷新与重放；超时分层；过期请求取消防竞态 |
| 8 | 前端安全 | 防 XSS（不 innerHTML 拼接用户内容）；敏感信息（token/密钥）不落前端代码与日志；遵循 CSP，无必要不内联 |
| 9 | 性能 | 路由级懒加载/代码分割；长列表 key 稳定 + 虚拟滚动；图片尺寸/格式/懒加载；避免不必要的重渲染；控制包体积 |
| 10 | 可访问性 | 语义标签优先；键盘可达与焦点管理；对比度达标；图标有可访问名；aria 只补语义不足 |
| 11 | 测试 | 组件/行为单测优先；端到端冒烟覆盖主链路；快照慎用；测试服务重构不服务表演 |
| 12 | 工程协作 | 同类修改先 grep 扫全量；lint/format 统一收口；提交按功能原子化；完成声明 = 实际运行验证证据 |

> 原型稿生成**不是前端技能面**：设计判断（信息架构 / 交互模式 / 分层 / 质检）归独立 UX 角色 `skills/ux-prototype-designer`，前端只消费确认后的页面规格书（page-spec）做落地实现，见 §三 分工表。

## 二、规则（可检查：正确做法 / 错误做法）

| 规则 | 正确做法 | 错误做法 |
|------|---------|---------|
| 颜色语义化 | 只引用设计 token / CSS 变量，新色先入 token 再引用 | 业务代码散写裸 hex/rgba、深浅随意 |
| 样式覆盖 | 从结构/组件级修复，或走主题单出口 | 新增 `!important` 硬压 |
| 图标 | 图标库 SVG，带语义名 | emoji 当图标、位图当图标 |
| 类型安全 | TS strict；未知用 unknown 收窄 | 手选关闭检查、`any` 偷渡 |
| 列表渲染 | 稳定唯一 key | 用数组 index 当 key（增删后状态错位） |
| 副作用 | Effect 内定时器/订阅/请求必须清理 | 泄漏定时器/订阅、卸载后 setState |
| 表单提交 | saving 锁/提交中禁用 | 连点重复提交 |
| 错误处理 | 展示 + 可重试入口 | 静默吞错、只 console 不提示 |
| 破坏性操作 | 二次确认并写明后果（影响面/可恢复） | 直接执行 |
| 请求竞态 | 过期响应作废（请求取消/序号比对） | 晚到的旧响应覆盖新状态 |
| 敏感信息 | token/密钥只存安全介质，不入前端代码/仓库/日志 | 明文进代码、打日志、塞 URL |
| 用户内容 | 文本节点渲染，需要富文本用白名单方案 | innerHTML 直接拼接 |
| 状态设计 | 能派生不重复存、能局部不全局 | 镜像 state、全局兜底放所有状态 |
| 横切改动 | 改组件/页面族先 grep 全量同类 | 只改手头一处 |
| 完成声明 | 实际运行验证 + 给出证据（截图/操作路径） | 「应该没问题」式口头完成 |

## 三、与项目层的分工（避免重复定义）

| 主题 | 归属 |
|------|------|
| 设计系统数值/组件外观/页面类型规范/颜色地图 | 项目层（团队维护的设计系统 / UI 规范文档，单事实源） |
| 原型稿：信息架构 / 交互模式 / 分层 / 触发决策 / 质检清单 | **UX 角色**（`skills/ux-prototype-designer`，通用；独立于产品与前端） |
| 原型稿：骨架模板 / 形态容器 / Token 值 / 目录命名 | 项目层（scaffold / 项目原型稿规范，ux 角色产出时叠加使用） |
| 工程架构：网关、微前端加载/版本、发布形态 | 项目层 |
| 具体栈选型与目录约定 | 项目层（README / 开发指南） |
| 上表 §二 的工程与质量规则 | **本文（通用）**，任何项目默认生效 |

> 原则：项目层只写"本工程独有"；凡业界通用规则不逐项目复制，统一在本文与关联通用文档维护，防止多源漂移。
> 触发原型稿请求 → 转 `ux-prototype-designer` 角色（该角色读项目 scaffold + 本文 §二 质量规则产出）；前端在规格确认（page-spec）后按项目 UI 规范落地实现，不在开发阶段重做交互设计。
