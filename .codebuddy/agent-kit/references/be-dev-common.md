# 后端开发通用技能与规则（be-dev-common）

> 定位：技术产品型数字人的**通用后端开发能力包**——不绑定语言/框架与具体项目，可移植到任何后端工程。用于指导开发、评审方案、自查交付。
> 与项目层的关系：**本文不含**组织级架构布局——网关/API 统一入口、微服务划分与端口、部署发布形态、具体库名等属项目层，由具体项目维护其架构与发布规范。加载顺序：通用能力（本文）→ 项目规范。
> 用法：触发后端任务（接口/数据/安全/服务修改）时，先对照 §一 定位技能面，再按 §二 规则执行与自检；项目有更严规范以项目为准。

## 一、技能清单（后端能力面）

| # | 技能面 | 核心要点（掌握到能评审也能实现） |
|---|--------|------|
| 1 | 分层与模块 | 入口/业务/数据分层清晰；依赖注入；模块边界单一职责；事务边界定在业务层 |
| 2 | API 设计 | REST 资源化与语义化状态码；统一响应与错误结构；版本策略；列表接口分页/过滤/排序/字段裁剪一致化 |
| 3 | 输入输出 | 入参 schema/DTO 全量校验（类型、边界、枚举、防注入）；出参显式裁剪（不泄露内部字段/敏感值） |
| 4 | 错误与可观测 | 全局异常兜底；错误分级（参数/权限/不存在/服务器）；结构化日志（含请求标识）；生产环境脱敏；关键路径有指标 |
| 5 | 安全 | 认证（JWT 校验含过期/吊销语义）、授权（RBAC/资源级）；CORS 白名单；速率限制；密码哈希存储；敏感配置经环境注入 |
| 6 | 数据层 | ORM 与迁移；事务与隔离级别取舍；索引匹配查询；N+1 消除；大数据量分页一致性；枚举/状态机持久化口径；并发写冲突处理 |
| 7 | 并发与异步 | 写操作幂等（重复提交/重试安全）；分布式锁语义；队列消费幂等与死信；显式超时；未处理异步异常必兜底 |
| 8 | 配置与秘钥 | 环境变量注入；启动校验关键配置非空；密钥不入代码/仓库/日志；示例配置不给危险默认值 |
| 9 | 服务间与网络 | 内部调用设超时与重试上限；错误不裸传内部细节；统一网络出口（超时/重试/熔断语义一致） |
| 10 | 测试 | 单测覆盖业务规则；集成测试用可控替身；数据库测试隔离与回滚；对外契约测试 |
| 11 | 部署与运维（通用） | 健康检查端点；优雅停机（排空/超时强杀）；日志级别可调；CI 跑测试与静态检查；回滚 = 上一可发布版本，可复现可验证 |

## 二、规则（可检查：正确做法 / 错误做法）

| 规则 | 正确做法 | 错误做法 |
|------|---------|---------|
| 类型安全 | 语言严格模式开启；领域建模用显式类型 | 关闭严格检查、`any`/动态类型偷渡 |
| 入参校验 | 所有对外接口入参走 DTO/schema 校验 | 裸 map/任意对象直接使用 |
| 异常处理 | 全局异常兜底；生产环境统一返回「服务器内部错误」 | 把异常内部 message 直接抛给客户端 |
| 日志 | 统一 Logger + 请求标识；日志脱敏 | `console.log` 裸打、打印密码/token/完整请求体 |
| 认证 | 每个用 JWT 的服务启动校验密钥非空；校验过期与吊销语义 | 只验 token 存在、密钥可为空 |
| CORS | 白名单来自配置（明确域名列表） | `*` 或无参全开 |
| 密钥管理 | 环境变量注入；示例文件给占位与安全默认值 | 明文写进代码/仓库/日志/镜像 |
| 注入防护 | ORM 参数化 / 预编译 SQL | 字符串拼接 SQL |
| 密码 | 用 bcrypt/argon2 等专用哈希 | 明文、md5、自研哈希 |
| 幂等 | 写接口/消费端可安全重放（幂等键/去重） | 重复提交造成重复数据/双写 |
| 超时 | 每次外部/内部调用都设显式超时；长任务单独放宽 | 无限等待默认超时一锅端 |
| 异步异常 | unhandled rejection / 未捕获异常有兜底 | 异步错误静默丢失 |
| 事务 | 事务边界在业务层；事务内不做长外部调用 | 事务跨网络调用、连接不释放 |
| 数据查询 | 先查执行计划再建索引；N+1 用 join/批量取数消除 | 无索引全表扫、循环查库 |
| 横切改动 | 改 CORS/异常过滤器/日志/校验等先 grep 全部服务 | 只改被「刚好触及」的一个服务 |
| 配置收口 | 同类配置单一来源（共享包/配置中心） | 各端复制、魔法数字散落 |
| 完成声明 | 实际验证（跑测试/调接口）并给证据 | 「应该没问题」式口头完成 |

## 三、与项目层的分工（避免重复定义）

| 主题 | 归属 |
|------|------|
| 网关/API 统一入口、微服务划分与端口、库/中间件实例布局 | 项目层（项目的工程架构文档 / 部署手册，单事实源） |
| 发布流水线、版本表、灰度/回滚机制、监控大盘 | 项目层 |
| 具体框架/ORM/目录约定、命名规范 | 项目层（README / 开发指南） |
| §二 工程与质量规则（安全/校验/日志/幂等/超时…） | **本文（通用）**，任何项目默认生效 |

> 原则：项目层只写"本工程独有"；业界通用规则不逐项目复制，统一在本文维护，防止多源漂移。加载到具体工程时，以"通用本文 + 项目补充"双层工作。
