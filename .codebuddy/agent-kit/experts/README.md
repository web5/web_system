# experts/ · 专家实例层

> ⚠️ **这里的每个专家都是某个项目里的实战实例，不是通用方法论。要找通用方法，请看 `skills/`。**

---

## 这是什么

`skills/` 提供**方法论**（通用、抽象、不含技术栈、判据留白由项目填）——教 AI 怎么思考。

`experts/` 提供**专家实例**（完整、自带判据、**不脱敏**、可直接上岗）——把某个项目里跑通的成熟能力整个搬过来，让别的项目不用从零重建。

两者是**两种粒度，不是两级**。双向流动：

```
experts/  ──引用──▶  skills/ 的方法论
experts/  ◀──提炼──  skills/（成熟实践上浮为方法论条目）
```

> 不要理解为「skills 是草稿、experts 是毕业」。一个能力走哪边，取决于**判据是否是它的价值主体**：
> 判据是主体 → 走 `experts/`（脱敏就废了）；方法是主体 → 走 `skills/`。

## 目录结构

```
experts/<expert-name>/
├── PROFILE.md      七维画像（人 + AI 双面）
├── SKILL.md        可执行部分
├── ADOPT.md        ★ 独有：接入指南（需提供什么 / 判据怎么换 / 门禁怎么接）
├── references/     判据、清单、模板（可用 *.local.md 覆盖）
├── RATIONALE.md    设计理由与返工教训（人面，不在执行路径）
└── CHANGELOG.md    版本变更（下游据此判断何时重新 adopt）
```

**`ADOPT.md` 是本目录的灵魂** —— 没有它，专家搬过去就是个跑不起来的空壳。

## 准入标准（硬）

一个能力要进 `experts/`，**四条全中**：

| # | 标准 | 判据 |
|---|---|---|
| 1 | ≥3 次真实使用 | 有落盘的产出物，不是纸面设计 |
| 2 | 有完整判据源 | 条目级可裁决，不是形容词层 |
| 3 | 有机器或人工门禁 | 能拦住违规，不是靠自觉 |
| 4 | 至少一个项目在用 | 每日在跑，不是一次性实验 |

> 四条不全 → 先放 `skills/` 走方法论路线，或留在原项目继续验证。
> **宁缺毋滥**：这个目录一旦变成杂物间，就失去了「经过实战验证」的意义。

---

## 门禁事实

`scripts/check-structure.sh` 的检查作用域是 `skills/*/`，因此**本目录不受以下约束**：

| 约束 | 是否适用 |
|---|---|
| S2 孤儿检查 / S3 `name` / S8-1 `version` / SKILL.md ≤150 行 / S5 路由登记 | ❌ 不适用 |
| S4 占位残留（扫 `skills/` 之外） | ✅ **适用** → 本目录内不得出现 `<your-team>` / `<your-project>` |

> 这个「低摩擦」特性符合定位：成熟实例不该再走一遍从零评审流程。

---

## 定制与覆盖

上游同步时，**`*.local.md` 永不覆盖**（`scripts/sync-to-target.sh` 保护清单）。

所以定制判据的正确做法：**建 `references/<name>.local.md` 覆盖**，不要改原文件。改原文件会在下次同步时被冲掉。
