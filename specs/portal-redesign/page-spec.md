### 2.1 消息排版契约（v2 · 2026-09-21 重设）

> 背景：v1 是「AI 白底气泡 + 纯文本 `pre-wrap`」——长回答的段落 / 编号 / 法条全糊在一个框里，
> 气泡宽度又随内容撑满、左右边界参差，用户反馈「不规整、像段落」。本节为修订后的排版契约，原型已按此实现。

**栅格与对齐**

- **对话中栏 v4 定稿（2026-09-21 第五轮反馈）**：**消息 + 输入 = 同一个浅暖大面板**（`--page-bg`、16px 圆角、占据标题行以下全部空间、底部贴合）——回答与输入永不分离；**AI 回答反转为白底卡片**浮在面板上（浅暖底上白卡，层级清晰），输入框同为白底描边（与回答卡同层级语言）；用户消息品牌橙气泡。**标题行（chead）在面板外白底区，通栏对齐面板左右边缘**：18px 标题**左对齐** + agent 徽标跟随、右端「新对话」——不缩在 720 阅读列内（标题悬在居中列里观感差，2026-09-21 拍板）。
- **演化记录（防回翻）**：v2 带边框窗体卡（否：割裂）→ v3 三段通栏底色（否：割裂）→ v3.5 单轴贯穿 + AI 浅暖块（否：回答块与输入块之间隔白底，仍是两个岛）→ v4 面板一体化 + 白卡反转（定稿，截图评审通过）。
- 消息列限宽 **720px** 居中（与输入区同宽、同左右边界）；头像列 32px，头像顶部对齐（`align-items:flex-start`），长回答时头像不漂移。
- 用户：**唯一气泡形态**（品牌橙底，圆角 `16px 16px 4px 16px`），**限宽 78%**，右对齐。
- AI：**无边框、无底色**；正文 `max-width:660px` / `14.5px` / `line-height:1.8`——靠排版分主次，不靠容器。

**AI 结构化块（`blocks`）**

| 块类型 | 用途 | 视觉 |
|---|---|---|
| `p` · `p.lead` | 段落；**lead = 结论先行**（15px / 500） | 段间距 12px，末段不落间距 |
| `h` | 小标题（如「建议争取两处修改」） | 14px / 600 + 品牌橙 3px 竖条前置 |
| `ol` | 有序建议 | 序号圆盘（品牌橙弱底），项间距 10px |
| `law` | 法条 / 依据引用 | 左侧 3px 品牌线 + 弱底块，13px 次级色，来源名加粗前置 |
| `cmp` | 方案对比表 | 表头弱底 12px；建议列用品牌橙（500） |
| `copybox` | 可直接复制的文案 | 品牌橙弱底卡片，标题行带「复制」 |
| `srcs` | ~~原文来源 chip~~ | **对话侧本期不做（Q10 已拍板）**；原文联动仅保留在合翻报告 + 右栏合同原文 |
| `sugs` | 下一步建议 | 32px 圆角按钮，点击即发送 |

**节奏**

- 一轮 = 一条用户消息 + 紧随的 AI 回答：轮内 12px、轮间 24px。
- **日期分隔线只在有日期 gap 处显示，且标注具体日期**（2026-09-22 再修正）：相邻消息跨天时，在边界（较早那组末尾）插一条线，文字为**具体日期**（`M月D日`，如「9月21日」），不用「今天 / 昨天」相对词；单天会话无线、**最后一轮末尾也无线**。
  - 消息时间戳 `ts`（B6）为**必填**，不做向后兼容；存量无 ts 数据用 `scripts/migrate-message-ts.mjs` 一次性回填（会话 createdAt 近似）。前端按轮首条消息 ts 分天、跨天边界插线。
  - 演化：2026-09-21 拍板「组尾线恒显示」→ 2026-09-22 改「仅跨天会话显示 + 今天/昨天/MM-DD」→ 2026-09-22 再改「只在 gap 处 + 具体日期」。
- 消息操作条（复制 / 重新生成 / 查看原文）**固定 26px 占位**，hover 显形——不产生布局跳动；AI 左对齐、用户右对齐。
- 流式等待：头像下方「思考动点 + 正在思考…」独立一行，不塞进正文容器。

**元信息**

- AI 消息头（agent 徽标 + 时间）独立一行置于正文之上，**不占用正文首行**；「已停止」以 tag 标注。

### 2.2 长回答折叠与内容卡片（Q9 拍板 · 2026-09-21）

**折叠**

- AI **纯文本**回答超过阈值收起，底部「展开更多 ▼ / 收起 ▲」（文案与小程序一致）。
- **截断方式（PC 定稿）**：**按块边界截断**（累计约 90 字止）+ 底部 64px 渐隐——不用行数 clamp（会把法条 / 列表块拦腰切断，2026-09-21 截图评审否决）。
- 阈值：PC **160 字**，小程序窄屏 140 字（同为 5 行）。
- **卡片不参与折叠**——与小程序 `is-card` 互斥规则一致（卡片气泡 `padding:0; overflow:hidden`，不受字数规则约束）。
- 展开态是本地状态（`S.exp[msgId]`），不持久化、不随会话保存。

**卡片**：AI 回答按**识别出的内容类型**渲染对应卡片，两类均对齐小程序实现。

| 识别结果 | 卡片 | 结构（对齐小程序） | 交互 |
|---|---|---|---|
| 翻译 | 翻译卡片 | 「推荐译文」tag + 方向 meta（中文 → 英语）+ 主文（16px / 600）+ **注解折叠区**（直译对照 · 委婉版 · 语气要点，**默认收起**）+ 操作行 | 展开 / 收起、复制、朗读（三态：朗读 → 请稍候… → 停止）、收藏 |
| 音乐 | 音乐卡片 | 「为你推荐 · 共 N 首」+ 每首歌名 / 歌手 / 推荐理由（**最多 3 首**）+ 操作行 + 底部说明 | 换一批、不感兴趣、去 {渠道}听（渠道未就绪 → 降级为复制关键词） |

- **流式三态**（翻译卡片）：T0「翻译中 + 动点」骨架 → T1 主文流式追加带光标 → T2 注解生成完毕出操作行（与小程序 `writeAiText` 共用同一视图构造，保证不跳版）。
- **类型识别**：翻译靠 `intent.agentId === 'translate'`（小程序 `CARD_AGENT_IDS`，intent 早于正文到达，先铺骨架）；历史消息用 `looksLikeTranslateReply` 补判。音乐靠 SSE `card` 事件 `kind === 'music'`。

**落码必读（小程序现存的坑）**

- 小程序 chat 页 `onEvent`（`pages/chat/index/index.ts:501-526`）**没有 `card` 分支**——后端 `card` 事件已下发、音乐卡组件已就绪，但实时对话里出不来卡片，只能从历史 `role==='tool'` 消息还原。
- **PC 落码必须自行补** `if (e.type === 'card' && e.card?.kind === 'music')` → 写入卡片态，否则音乐卡片只在历史回放出现。
