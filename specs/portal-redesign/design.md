## 1. 为什么是「换血」而不是「加法」

小程序规划文档（§3.1）已判定 16 页 legacy：`pages/index · draw · records · scan · bianbian×5`，并计划连带清理 `utils/CanvasEngine*`、`Brush.ts`。

这 16 页**恰好是 portal 当前的主菜**——`Create/Transform/Result/History`（变变创作流）与 `Draw`（画板）占了 portal 24 个 `.vue` 中的相当比例，且占据主导航 6 项中的 2 项。

因此本轮升级的实质是：**portal 从「图像玩法站」转型为「Agent 能力工作台」**，与小程序共用同一条执行链路 `POST /api/ai-agent/agent/run`（SSE）。

> 收益：后端几乎零改动（翻译 / 合同 / 对话三条链路在小程序侧已跑通），PC 端只需消费同一批 SSE 事件并做桌面化呈现。

## 2. 目标信息架构

### 2.1 三栏骨架

```
┌──────────────────────────────────────────────────────────────┐
│ 品牌   开始 对话 发现 翻译 合翻 实验室             ⌘K  头像▾ │ ← 顶栏（一级导航）
├──────────┬───────────────────────────────┬───────────────────┤
│ 会话/记录 │          主工作区              │   上下文面板       │
│ 列表     │                               │  （仅两处渲染）    │
│          │                               │  · 合翻→原文      │
│          │                               │  · 翻译→术语库    │
└──────────┴───────────────────────────────┴───────────────────┘
   240px               flex                  360px（可折叠）
```

设计要点（2026-09-21 第二轮反馈修订）：
- **一级导航放顶栏**（横向 tab，PC 惯例），左侧只承载**会话 / 应用记录列表**——不做「导航 + 列表合一」的两级侧栏。
- **左栏显隐规则**（2026-09-21 反馈「实验室设计不合理」推导）：左栏只在**有记录 / 信息语义**的视图显示（欢迎=最近对话、对话/翻译/合翻=会话、我的=账号信息锚点）；**入口网格视图（发现 / 实验室）隐藏左栏**、中栏撑满——避免「左栏列表与中间卡片完全重复」。
- **「我的」不放顶栏**，收进右上角**头像下拉菜单**（我的 / 退出登录）（2026-09-21 反馈「收到头像下面」）。
- 右栏是 PC 相对手机的**唯一结构性增量**，未启用时整体收起（非留白）。**仅在两处展示**：合翻报告（合同原文对照）与翻译工作台（术语库）；欢迎页与对话页**不渲染右栏**（2026-09-21 用户反馈：「概览」「引用与来源」对用户无感知价值，移除）。
- 顶栏：品牌标识 + 一级导航 + ⌘K 入口 + 用户头像菜单。
- **欢迎页 = 单列居中 landing 排版**（2026-09-21 第三轮反馈重排）：40px 大字问候 + 「开始对话」CTA + 20px 大字每日一句（带引号装饰、可换一句）整组居中；左上/右下品牌橙光斑（radial-gradient）撑起呼吸感；**不加信息、靠排版与视觉解决空旷**。最近对话由左栏列表唯一承载。

### 2.3 起始页（欢迎页）定位

**内容与小程序 `welcome` 逐项对齐**（2026-09-21 拍板，已查证 `pages/welcome/index` 源码）：

- 「Hello.」大字（句点品牌橙）+ 副文案「科豆 AI · 体验不一样的 AI」+ 「开始对话」主按钮。
- **今日一句中英对照**（cn/en 两行）：词库与小程序 `utils/daily.ts` 同源（7 条中英对照），B1 运营接口上线后两端共用同一数据源，不漂移；「换一句」为 PC 轻互动补充。
- 页脚合规声明：「内容由 AI 生成，仅供参考，不构成法律意见 / 已依法完成大模型与算法备案」。
- **不重复展示最近对话**——左栏列表已承载；不做输入框前置、不做能力 chip、不加定向行动按钮。
- 单列居中 landing 排版 + 品牌橙光斑背景（PC 排版层，非小程序内容）。
- 入口与返回路径：左栏首项「开始」+ 顶栏品牌标识 + ⌘K「回到开始页」，保证从任意页面都能回到起始页（无死链）。

> 注：早期「内容主题以翻译为主」的口径已被「与 `utils/daily.ts` 同源」取代（同源后主题即与小程序一致）。

## 4. PC 独占增强（已选三条）

### 4.1 合同报告 + 原文双栏联动

- 中栏：结构化报告（健康指数、风险信号列表、我的权益、权益最大化）。
- 右栏：合同原文全文，支持滚动与搜索。
- 联动：报告侧风险信号 hover 高亮 → 点击 → 右栏对应原文片段 `scrollIntoView` + 高亮标记；反向点击原文片段 → 定位到关联风险信号。
- 实现前提（Q1 已确认）：**当前产物无片段定位字段**——前端 `ContractSignal`（`services/contract-api.ts`）只有 `legalBasis.quote`（法条引用，非合同原文）；后端 `ContractReportSnapshot`（`servers/ai-agent/src/contract/contract-report.parser.ts`）对 signals 仅透传，且合同原文不落库。因此：P3 先用**关键词回查**兜底（用 signalTitle/plainText 关键词在原文中定位，找不到则不高亮不报错）；后端补 `excerpt` 字段后升级为精确定位（后端待办 B3）。

### 4.2 翻译并排对照

- 左：源文本；右：译文区，以 Tab 切换「自然版 / 直译版 / 委婉版」，或并排双列。
- 替代小程序 `result` 页的折叠区（折叠是窄屏妥协，PC 不该沿用）。
- 语气 / 风格 chips 置顶常驻（小程序是滚动到下方）。

### 4.3 快捷键与桌面级交互

| 快捷键 | 行为 |
|---|---|
| `⌘K` / `Ctrl+K` | 命令面板：搜索会话、跳转能力、执行动作 |
| `⌘N` | 新建当前能力的任务 |
| `⌘/` | 快捷键帮助浮层 |
| `Esc` | 关闭面板 / 抽屉 |

- 批量导出报告：合同记录列表多选 → 导出（PDF / Word），桌面端文件下载语义。
- **不做多任务并行**（本轮未选）：同一时刻一个主任务，切换靠左栏列表。

## 5. 技术落地约束

| 项 | 约束 |
|---|---|
| 微前端 | portal 是 gateway 子模块，构建用 `MF_FORMAT=system npx vite build --mode mf`；改完须走「构建→拷贝→更新 `deploy_deployments.current_version`」三步 |
| 主题 Token | 统一到 `packages/ui/src/tokens.css`：`--ws-brand-500:#F97316` / `--ws-brand-600:#EA580C`；**portal 现用 `#FF8C42` 需收敛**；禁裸 hex（原型 `:root` 除外） |
| 暗色 | 不做（对齐小程序一期只做浅色） |
| 组件库 | ant-design-vue 4 + `a-config-provider`；图标用 `@tabler/icons-vue` / 内联 SVG，**禁 emoji** |
| 字重 | 只用 400 / 500 / 600 |
| 执行链路 | 统一 `POST /api/ai-agent/agent/run`（SSE）；对话 `agentId=auto`，翻译 / 合同显式 agentId |
| 其他接口 | `/api/ai-agent/ocr/recognize`（合同图片）、`/api/ai/tts/speak`（朗读）、`/upload/*` |
| 鉴权 | 沿用 portal 现有 axios 拦截器（Bearer + refreshToken 重试 + 401 跳 `/login?redirect=`） |
