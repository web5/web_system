## 3 登录引导卡（登录墙）

- 结构：圆形品牌图标（56px，`--brand-soft` 底 / `--brand-txt` 图标）→ 标题「登录后继续使用」→ 一句说明 → 主按钮「微信一键登录」→ 底部小字（协议链接 + 真机语义说明）。
- 三处文案差异化：对话页「AI 对话、翻译与合翻都需要登录后使用」；发现页「发现页的能力与记录都关联你的账号」；我的页「口味记忆、生词本与手机号都跟着账号走」。
- 覆盖方式：绝对定位铺满 `.page`（`inset:0`，`z-index:22`，背景 `--page-bg`），**不销毁下层内容**，登录后直接 `toggle('show')` 复原，无需重建页面。
- **并锁定滚动**：显示登录卡时给对应 `.page` 加 `.locked`（`overflow:hidden`），否则我的页内容超过一屏可把登录墙滚出视野（D2 阻塞项 B2，判据 P3）。
- **导航栏同步拦截**：「新建对话」「对话记录」两个入口在 `.navbar` 上（不在 `.page` 内，登录墙盖不到），未登录时须一并隐藏；`navigateTo()` 加守卫，未登录只允许进 `p-agreement`（合规必读页），其余二级页 toast「请先登录」（D2 阻塞项 B1）。
- 交互：点「微信一键登录」→ loading 600ms → 登录态恢复 → 当前页卡片消失、内容原样呈现（不跳转、不刷新）。
- 协议链接在未登录态可点（协议属于合规必需，不应被登录墙挡住）。
- 真机语义：登录是 `wx.login` 静默换取，**没有授权弹窗、没有验证码**，故登录墙是一次点击即可脱离的轻障碍。

## 4 退出登录

- 两个入口：我的页底部红色文字按钮（`--red`）、小程序设置页「通用」分组列表项。
- 点击 → `wx.showModal`：标题「退出登录」，内容「退出后需要重新登录才能继续使用。服务端登录凭证会同时失效。」，按钮「取消 / 退出」。弹窗**蒙层不可关闭**（与真机同口径），取消只能走「取消」按钮 —— 保证「进行中锁」一定有释放路径。
- 确认后：三个 tab 的登录卡显示并锁滚动；导航栏需账号的入口隐藏；若当前在二级页则先退回所在 tab；toast「已退出登录」。
- 取消：无任何变化。
- 真机语义对应 `design-mp-account.md` §4.1 时序（调 `/api/auth/logout` → `clearToken()` → 置本地退出标志 → 清内存态）。

## 5 绑定手机号（三态）

| 状态 | 我的页 profile 副标题 | 个人信息页手机号行 | 点击行为 |
|---|---|---|---|
| 未绑定 | `已实名 · 未绑定手机号` | `未绑定 ›`（值用 `--brand-txt` 强调，可点） | 拉起微信手机号授权 |
| 已绑定 | `已实名 · 138****6688` | `138****6688 ›` | 弹「更换手机号」确认：需重新授权，且**当前号码将被新号码替换** |
| 授权中 / 合并中 | 不变 | 不变 | `wx.showLoading` |

- 授权弹窗（模拟原生半屏）：标题「微信手机号授权」，内容「微信将把你绑定的手机号提供给科豆 AI，仅用于账号打通。」+ 小字标注真机为 `button open-type="getPhoneNumber"` 原生半屏。
- **拒绝授权不提示**（`errMsg` 含 deny 时静默返回），额度不足（`errno 1400001`）才提示「服务暂不可用，请稍后再试」。

## 6 合并二次确认（Q15 = c）

- 触发：授权成功但号码已注册。
- 弹窗：标题「该手机号已注册」；内容「138****6688 已注册科豆账号。绑定后会把当前小程序的对话、生词本与口味记忆**合并**到该账号，**合并不可撤销**。」；按钮「取消 / 确认合并」。
- 确认后：loading → 成功 toast「已合并到该账号（凭证已重签）」，手机号行与我的页副标题同步更新为脱敏号。
- 必须明确表达两件事：**会合并数据** 与 **不可撤销**；不得静默覆盖。
- 真机额外动作（页面不可见但影响体验）：合并成功后凭证重签（sub = 目标账号），旧 token 立即失效 —— 前端须先 `setToken()` 再刷新身份，否则用户会看到「数据不见了」。

## 7 用户协议与隐私政策页（M4）

- 入口：我的页底部列表首行（原为不可点击占位，现跳 `p-agreement`）。
- 三段式正文卡片：① 我们收集什么（openid 静默获取 / 手机号仅主动授权 / 对话与学习数据）② 手机号怎么用（仅账号打通、只展示脱敏号、命中已注册会先征求同意且合并不可撤销）③ 你的控制权（绑定更换 / 退出登录 / 注销开发中）。
- 明确写「**不绑定不影响任何功能使用**」——对应微信运营规范红线（不得强制索要手机号）。
- 页脚标注「文案待运营 / 法务确认」与生效日期占位（原型不上假日期）。

## 8 风格与规则校验

- 色值全部走 token：`--brand` / `--brand-txt` / `--brand-soft` / `--red` / `--t1` / `--t2` / `--t3` / `--card` / `--page-bg` / `--line`；新增 `--on-brand`（主按钮文字色，深色主题取 `#1A1005`）避免裸 hex。
- 字重只用 400 / 500 / 600；正文行高 `--leading-normal`，说明文字 `--leading-relaxed`。
- 圆角与控件高度沿用既有 token（按钮高 `--control-lg`，胶囊圆角 20px）。
- 图标为 SVG（tabler 风格），无 emoji。
- 原型顶部「演示说明」区新增第 ⑥ 条，列出本次新增屏的操作路径与 `CONFLICT` 演示开关。

## 9 交互质检结论（ux-review-checklist）

| 项 | 结论 | 说明 |
|---|---|---|
| A 信息架构 | 通过 | 6 个屏/组件齐备；协议页与登录卡互相可达，层级 ≤3，无死链 |
| B 任务流闭环 | 通过 | 退出→登录→绑定→合并主路径可走通；取消、拒绝授权、额度不足、绑定失败均有去向 |
| C 状态矩阵 | 通过 | loading（绑定中/合并中）、空态（未绑定）、错误态（额度不足演示 + 绑定失败弹窗含「重试」）、完成态 toast 齐备 |
| D 操作与确认 | 通过 | 每屏仅 1 个主操作；退出与合并均有二次确认且写明后果；`ACCOUNT.busy` 防重复提交 |
| E 视觉与 Token | 通过 | 无裸 hex（新增 `--on-brand` 在 `:root`）；间距取 8 倍数；SVG 图标无 emoji；字重 400/500/600 |
| F 可访问性基线 | 通过（原型级） | `--brand-txt` 白底 4.9:1；可点击元素沿用原型既有 `div + onclick` 语义并标注 |
| G 内容与真实性 | 通过 | 全真实文案；仅协议页「生效日期」为占位，已标注待运营/法务确认 |
| H 目标端一致性 | 通过 | 小程序壳（胶囊 + TabBar）；授权弹窗与 `wx.login` 均标注真机语义，未伪装已实现 |
| I 未定义项标注 | 通过 | 合并不可撤销、注销「开发中」、协议文案待确认均已显式标注 |

遗留（不阻塞）：① 「拒绝授权」在原型中复用「取消」表达，真机为原生半屏的拒绝按钮；② 合并后凭证重签在原型仅以 toast 说明，页面无可见差异。

## 10 演示开关

`requestPhone()` 内 `var CONFLICT = true`：
- `true` → 走「已注册 → 合并」路径（默认，覆盖最复杂分支）
- `false` → 直接绑定成功（无冲突路径）
