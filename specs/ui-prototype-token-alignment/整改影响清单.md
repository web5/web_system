## 1. 判定口径（什么算不合规）

| 条目 | 判据（原型侧可执行） |
|---|---|
| G1 | 业务样式里的裸 hex / rgba（`:root` 与端 token 定义层**除外**） |
| E10 | 长文正文用 `--ws-text-primary` / `--t1`（近黑）而非 `--ws-text-body` / `--text-body` |
| E11 | `line-height` / `letter-spacing` 写字面值，未引 `leading-*`、`tracking-*` 阶梯 |
| E12 | 阶外字号（如 13.5px）无「字阶例外」登记注释 |
| E13 | 控件高度、图标尺寸写字面 px，未引 `control-*` / `icon-*`；图标 stroke 非 1.5 |
| G11 | 无 `:focus-visible` 焦点样式 |
| G12 | `transition` 时长写字面值（非 150/200/300ms）或缺失 |
| 圆角 | `border-radius` 写字面值，未引 `radius-*` / `--r-*` |

## 5. 边界与不做

- **不改落地代码**（`apps/**` 业务代码）：本清单只改原型稿；对应落码由各 UI 任务按动作门自行走。
- **不追求像素级重构**：原型是沟通产物，字面值"就近归拢"到阶梯即可，不要求全量返工（沿用 `design-system.md` §2.3 存量口径）。
- **与 `specs/admin-prototype-coverage/tasks.md` 分工**：那份是**补缺失原型**（P1 用户管理 → P5 例外页）；本清单是**存量稿按新规范回填**。两者互补，同一份稿若既缺失又需回填，以"先补齐、再回填"为序。

## 6. 附：整改中发现的「原型 ↔ 落地」结构漂移（非 token 问题）

> 2026-09-23 由负责人提出、排查确认。这类漂移比字面值问题更严重：原型是「当前对照源」，结构错了会直接误导落码。

| 项 | 事实 |
|---|---|
| 落地真相 | `apps/deploy-console/src/layouts/MainLayout.vue`（双域重构，2026-09-18 用户确认）：**顶部一级菜单 + 左侧二级菜单**，一级切换后左侧换为该域子项 |
| 主原型 | `deploy-console-domain-split.html` ✅ 已是两级导航（顶部一级横排 `DOMAINS` + 左侧 `#dcSubMenu` 动态渲染） |
| **漂移稿** | `deploy-console-version-deploy.html` ❌ 仍是**旧单级侧栏**：侧栏内用 `.side-group` 做分组标题（微前端/API 网关/流水线/基础设施）+ `.side-item` 菜单项，**无顶部一级菜单** |
| 影响 | 该文件在 `README.md`「一、当前有效」表内（即被当作对照源），但壳结构与落地不一致 |
| 处理口径 | 按 `README.md` §1「原型与落地不一致时，回写原型」→ **应回写原型**，不是改代码 |
| 修复范围 | 换壳：顶部一级（仪表盘 / 微前端 / API 网关 / 流水线 / 基础设施）+ 左侧二级（随一级切换）；各稿内容屏保留不动 |
| 状态 | ✅ **已修（2026-09-23，负责人选 A）**：两份均换为两级导航，菜单数据口径同落地 `MainLayout.vue` 的 `DOMAINS`（含「版本部署只挂微前端域」）；实跑验证联动生效 |

### 6.1 换壳后的口径（两份一致）

- 一级（顶部）：仪表盘 / 微前端 / API 网关 / 流水线 / 基础设施
- 二级（左侧，随一级切换）：
  - 微前端 → 应用管理、环境管理、版本部署
  - API 网关 → 服务管理（落地口径：**不含**版本部署）
  - 流水线 → 流水线列表、灰度管理、自助诊断、工具目录
  - 基础设施 → 主机管理、服务监控、审计日志、通知中心、配置中心、系统设置
  - 仪表盘 → 无二级
- `pipeline`：顶部一级沿用原深壳 `tb-item`，改为可点击联动；左侧改为 `#subMenu` 动态渲染
- `version-deploy`：新增顶部一级通栏 `.topnav`（深壳 `--dc-top-bg`），侧栏改为动态二级；原「侧栏分组标题」写法弃用
