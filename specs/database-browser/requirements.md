# 数据浏览器（Database Browser）· 需求与验收标准

> 版本：v1.0 ｜ 日期：2026-09-04 ｜ 状态：待用户确认
> 方案来源：brainstorm 选型 = **方案 B（结构化数据浏览）为主 + 方案 A（受限 SQL 控制台）为增强**
> 页面规格书：见 `../docs/ui/page-spec-template.md` 填写产出（已与用户确认批注）

---

## 1. 目标与非目标

### 目标
在 admin 后台提供只读的数据库查看能力，让排查线上数据问题不必开 MySQL 客户端。

### 非目标（明确不做）
- 不做数据编辑 / 删除（本功能全程只读）
- 不做 DDL（建表、改表、删表）
- 不做跨库查询（仅 `web_system` 业务库）
- 不做数据导出（二期再评估，需额外的脱敏与审计设计）

---

## 2. 用户故事

| 角色 | 故事 |
|------|------|
| super_admin | 作为超管，我要浏览任意业务表的结构与数据，并在需要时用只读 SQL 做关联查询，以便快速定位数据问题 |
| super_admin | 作为超管，我要能看到脱敏字段的明文，以便核对具体用户的真实信息 |
| admin | 作为管理员，我要浏览业务表数据排查问题，但不应看到凭证类字段、也不应能执行任意 SQL |
| 所有用户 | 我的每一次 SQL 执行都应被记录，以便事后追溯 |

## 3. EARS 验收标准

### 3.1 访问与权限

- **AC-1** While 未登录，when 访问 `/admin/database`，系统应重定向到 `/login`
- **AC-2** When 已登录但角色不含 `database:view` 权限，when 访问 `/admin/database`，系统应重定向到 `/403`
- **AC-3** When 用户角色不含 `database:query` 权限，系统应不渲染「SQL 控制台」Tab（非禁用态，直接不出现）
- **AC-4** When 后端收到 `/api/admin/db/*` 请求且调用者无对应权限码，系统应返回 403，不执行任何查询
- **AC-5** When 无有效 JWT 时调用 `/api/admin/db/*`，系统应返回 401

### 3.2 表列表（B）

- **AC-6** When 进入数据浏览页，系统应加载并展示 `web_system` 库中所有业务表的表名、行数、注释
- **AC-7** While 表数量 > 0，when 用户在搜索框输入关键词，系统应实时过滤列表（匹配表名或注释，不区分大小写）
- **AC-8** When 搜索无匹配，系统应展示空态「未匹配到表，调整关键词试试」
- **AC-9** When 表列表接口失败，系统应展示 `message.error` 并在列表区提供「重试」按钮
- **AC-10** When 调用者非 super_admin，系统应在表列表中隐藏命中敏感表名单的表

### 3.3 表结构（B）

- **AC-11** When 用户点击某张表，系统应默认选中右栏「数据」Tab 并加载首页数据；两个 Tab 标签上分别显示该表行数与字段数
- **AC-12** When 用户切换到「表结构」Tab，系统应展示该表字段清单（字段名、类型、可空、默认值、键类型、注释）
- **AC-12.1** When 字段命中脱敏规则，系统应在「表结构」Tab 内标注该字段为「敏感」并说明脱敏方式
- **AC-12.2** When 用户切换左栏的表，系统应保持右栏当前选中的 Tab（正在看表结构则继续看表结构），仅刷新内容

### 3.4 数据浏览（B）

- **AC-13** When 选中表后，系统应以分页方式加载数据，默认每页 50 条
- **AC-14** When 用户翻页或点击表头排序，系统应重新加载对应数据，并保持当前选中表
- **AC-15** When 单元格内容超过 40 字符，系统应截断显示，点击后在 Drawer 中展示完整内容
- **AC-16** When 字段值为 `NULL`，系统应以弱化样式显示 `NULL`
- **AC-17** When 字段命中「完全隐藏」规则，系统应显示 `***`，不返回原值
- **AC-18** When 字段命中「打码」规则且调用者无 `database:query`，系统应返回打码值（如 `138****8888`）
- **AC-19** When 表无数据，系统应展示空态「该表暂无数据」
- **AC-20** When 数据加载失败，系统应展示 `message.error` 并提供「重试」按钮

### 3.5 SQL 控制台（A）

- **AC-21** When 用户提交 SQL，系统应校验：仅允许单条 `SELECT` 语句，含 `;` / `INSERT` / `UPDATE` / `DELETE` / `DROP` / `ALTER` / `CREATE` / `TRUNCATE` / `GRANT` / `INTO OUTFILE` / `INTO DUMPFILE` 等关键词时拒绝并返回明确错误
- **AC-22** When SQL 通过校验，系统应自动附加 `LIMIT`（上限 200 行；若用户已写 LIMIT 则取较小值）
- **AC-23** When SQL 执行成功，系统应展示结果表格、返回行数、耗时（ms），并在超 200 行时提示「结果已截断至 200 行」
- **AC-24** While SQL 执行中，when 用户再次点击执行，系统应忽略（防重复提交）
- **AC-25** When SQL 执行失败，系统应展示后端返回的原因，不清空编辑区内容
- **AC-26** When 查询结果含脱敏字段，系统应同样应用脱敏规则（AC-17 / AC-18）
- **AC-27** When 每次 SQL 执行（成功或失败），系统应写入 `operation_logs`，记录操作人、时间、SQL 原文、返回行数、耗时

### 3.6 安全兜底

- **AC-28** When db-explorer 模块连接数据库，系统应使用**只读账号**连接，即使代码层校验被绕过也无法写入
- **AC-29** When 请求的表名不在当前 `information_schema` 表清单内，系统应返回 400，不执行查询

### 3.7 非功能

- **AC-30** When 表数据超过 10 万行，单页查询响应时间应在 2 秒内（依赖目标表主键索引）
- **AC-31** 页面在 light / dark 双主题下均无错位、无遗漏变量

## 4. 已确认的产品决策

| # | 决策项 | 结论 |
|---|--------|------|
| 1 | 页面布局 | **主从分栏**（左表列表 / 右上表结构 / 右下数据），不做两页式 |
| 2 | 脱敏策略 | 按方案：**凭证类完全隐藏，个人信息类打码** |
| 3 | SQL 控制台可见范围 | **仅 super_admin** |
| 4 | 敏感表处理方式 | **不整表屏蔽**，改为仅 super_admin 可见（其余角色在列表中看不到） |

## 5. 待实现阶段验证的风险

- **RISK-1**：现有 `Role` 类型只有 `admin | editor | viewer`，**不存在 `super_admin`**。需新增角色并设计存量用户升级路径。
- **RISK-2**：`system-service` 当前**零鉴权**（无 Guard，gateway 侧 `@Public()`）。加全局 Guard 会影响已有的 `settings` / `logs` / `bianbian` 三个模块，需同步补权限码并验证前端不受影响。
- **RISK-3**：本地 MySQL 未安装 `mysql` CLI，创建只读账号需走 docker 或 node 脚本。
- **RISK-4**：`system-service` 的 TypeORM 配置里 `type: dbType as 'postgres'` 是类型断言，实际跑的是 MySQL，新增第二个（只读）连接时需同样处理。
