# 页面规格 · 发布管线 cron 校验与调度状态

- 关联需求：台账 #8561（源自线上故障 #8557）
- 关联评审：`docs/ui/reviews/content-cron-validation-2026-11-06.md`
- 页面：admin → 内容 → 发布管线（列表页 / 编辑页）
- 日期：2026-11-06

## 1. 背景（为什么改）

`content_pipelines.ai_news` 曾被写成 `0 8 0 * *` —— 把「每周四」的 `4` 写进了**日**字段
（5 段式顺序是「分 时 日 月 周」）。当时的三道口子同时失守：

| 环节 | 旧行为 | 后果 |
|---|---|---|
| 编辑页输入 | 纯文本输入框，`submit()` 只 `trim()` + 判非空 | 任何字符串都能提交 |
| 后端接口 | `@Body() body: any`，全局 ValidationPipe 因缺 DTO 元类型直接跳过 | 校验等于不存在 |
| 调度注册 | 启动时 `logger.error` 一行，进程照常起、`/health` 照常 200 | 管线静默停摆 2 天 |

本规格只解决「让坏 cron 进不来 + 让它一旦失败就能被看见」，不改动管线执行逻辑。

## 2. 编辑页 · cron 字段的四种状态

字段下方常驻一行提示（`.field-hint`），按下表切换：

| 状态 | 触发条件 | 提示文案 | 颜色 |
|---|---|---|---|
| 空 | 输入框为空 | `5 段式「分 时 日 月 周」，如 0 9 * * *（每天 09:00）` | 次级灰 |
| 校验中 | 输入停止 350ms 后请求未返回 | `校验中…` | 次级灰 |
| 非法 | 接口返回 `valid:false` | `✗ <error>`，error 由后端给出（含字段顺序提示） | `#cf1322` |
| 合法 | 接口返回 `valid:true` | `✓ 接下来 3 次：11-12 08:00 · 11-19 08:00 · 11-26 08:00` | `#389e0d` |

规则：

1. **校验口径只能有一个**：前端不引 cron 库，一律调
   `POST /api/content/pipelines/cron-preview`，与调度器共用 `common/cron.util.ts`。
   前端另写一套必然出现「页面说没问题、调度器注册失败」的分裂。
2. **时间格式**：`MM-DD HH:mm`，时区固定 `Asia/Shanghai`（不显示年份与毫秒）。
3. **保存前二次校验**：点「保存」时同步再校验一次，不等防抖结果——
   否则「刚改完立刻点保存」正好绕过。
4. **接口不可用时不锁死**：预览请求失败 → 放行保存，由后端 DTO 硬校验兜底。
   网络抖动不该让运维连标题都改不了。

## 3. 列表页 · 调度失败红条

条件：`GET /api/content/scheduler/status` 返回 `failed > 0`。位置：表格上方（与「正在运行」提示同位级）。

```
[✗] 1 条管线的 cron 无法注册，不会按时运行
    ai_news（0 8 0 * *）：Field value (0) is out of range —— 5 段式顺序为「分 时 日 月 周」…
```

- 红条按 `code` 稳定排序，便于截图比对；
- 接口失败 → 不显示红条、不影响列表（状态是增强信息）；
- 这是「管线启用着却不跑」在界面上**唯一**的可见信号，不允许被折叠或隐藏。

## 4. 接口契约

### POST `/api/content/pipelines/cron-preview`

请求 `{ "cron": "0 8 * * 4" }`（DTO 只接受 `cron` 一个字段，多传即 400）

```json
{
  "valid": true,
  "normalized": "0 8 * * 4",
  "error": null,
  "next": ["2026-11-12T08:00:00.000+08:00", "2026-11-19T08:00:00.000+08:00", "2026-11-26T08:00:00.000+08:00"],
  "timezone": "Asia/Shanghai"
}
```

非法时 `valid:false`、`next:[]`、`error` 为人话原因 —— **预览接口本身不返回 4xx**，
它是「问一句」而不是「提交一次」。

### GET `/api/content/scheduler/status`

```json
{
  "timezone": "Asia/Shanghai",
  "checkedAt": "2026-11-06T02:00:00.000Z",
  "total": 3,
  "failed": 1,
  "jobs": [{ "code": "ai_news", "cron": "0 8 * * 4", "registered": true, "nextRun": "2026-11-12T08:00:00.000+08:00", "error": null }]
}
```

## 5. 保存后的副作用

`POST /api/content/pipelines` 与「`cron` / `enabled` 有变化的」`PATCH` 会触发
`SchedulerService.reload()` 全量重注册 —— 改完立即生效，不必重启进程。

- 只改标题模板 / 封面 / 发布模式 → **不重注册**（不搅动定时器）；
- 重注册失败不抛 500：数据已落库，抛错只会让人以为「没保存成功」而重复提交；
  失败信息进 `[ALERT]` 日志与 `scheduler/status`。

## 6. 不做什么

- 不做 cron 可视化编辑器（表达式 → 表单控件的双向转换，收益低、歧义多）；
- 不猜语义：`0 9 4 * *`（每月 4 号）语法合法即放行，歧义交给「接下来 3 次」预览暴露；
- 不自动修正历史脏数据：库里已有的非法 cron 保留原样，只让它在页面上红出来。
