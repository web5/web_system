## 1. 页面与路由

| 页面 | 路由 | 说明 |
|---|---|---|
| 流水线列表 | `/pipelines` | 顶部右侧只有 **「+ 新建流水线」**；**不再放「发起发布」**（发起发布按行上下文在模块/环境页做） |
| 流水线详情（实例） | `/pipelines/:id` | 只读，tab：实例详情 / 历史记录 / 参数 / 变量 |
| **编辑流水线** | `/pipelines/:id/edit` | **独立页面**（不是详情页内的编辑态切换） |
| **新建流水线** | `/pipelines/new` | 同一套页面的「新建形态」 |

**决策（2026-09-15）**：编辑 / 新建都是**独立路由页**，详情页不再内嵌编辑态（`editing` 开关整体移除）。
原因：内嵌编辑会让编辑页带着实例页的头部（重试 / 回滚 / 命名备注）与实例 tab，语义混乱。

## 2. 编辑 / 新建页结构

```
页头：流水线名 + 模块 tag + 环境 tag + key      [取消] [保存]
banner：终态 nodes 说明（只有 shell / approval 两类）
Tabs： 基本信息 | 流程编排 | 参数 | 变量
右侧：点节点 → 抽屉（节点 / 变量 / 参数）
```

**Tabs 规则**

| Tab | 内容 | 可编辑 |
|---|---|---|
| 基本信息 | 身份字段（见 §3） | 新建可编辑 / 编辑禁用 |
| 流程编排 | 四节点画布，拖拽重排、增删节点 | ✅ |
| 参数 | 只读查阅（平台内置 → 配置中心 → 全局变量 → 本条流水线，后者覆盖前者） | ❌ |
| 变量 | 本条流水线变量，可增删改 | ✅ |

- **没有「历史记录」Tab** —— 那是实例页的东西。
- **没有「保存顺序」按钮** —— 画布改动由页头「保存」统一提交。

## 3. 基本信息字段（收敛后）

| 字段 | 控件 | 新建 | 编辑 | 备注 |
|---|---|---|---|---|
| 流水线名 | input | ✏️ | 🔒 | |
| 流水线 key（slug） | input（mono） | ✏️ | 🔒 | 保存后不可修改 |
| 模块 | **select** | ✏️ | 🔒 | 选项来自模块注册表 |
| 环境 | **select** | ✏️ | 🔒 | 决定投递机器 |
| 启用 | checkbox | ✏️ | ✏️ | 运行开关，不算身份信息 |

**页头标识（模块 / 环境 / key）随表单实时联动**：选择即更新页头 tag，未选时显示「模块未选 / 环境未选 / 保存后生成」。

### 3.1 已下移 / 已删除的字段（重要）

| 原字段 | 去向 | 理由 |
|---|---|---|
| 投递目标（自动/本机/远程） | **删除** | **环境即投递目标**：local=本机，dev/prod=远程（取环境管理的服务器配置，脚本用 `${DEPLOY_HOST}`） |
| 审批（继承环境/始终/从不） | **审批节点**（发布确认）抽屉 | 审批语义由节点承载 |
| 审批人 | **审批节点**抽屉 | 同上 |
| 失败回滚（回滚上一版本/不回滚） | **节点上的 watchdog 标记** | 哪个节点失败触发回滚，是节点属性 |
| 适用模块 | 保留为 select（选项来自模块注册表） | 模块的**目录**由构建/发布脚本确定（`${MODULE_DIR}` / 产物路径），注册表是元数据真相源 |

> 结论：**基本信息只剩「身份 + 开关」，所有行为配置都在节点抽屉里。**

## 4. 新建流水线流程

1. 列表页「+ 新建流水线」→ 弹窗二选一：**前端（micro-frontend）** / **后台（backend）**
2. 按类型载入初始四节点：`拉取代码(shell) → 构建(shell) → 发布确认(approval) → 发布(shell)`
   - 前端构建预填：`npx vite build`（产物 → `publicPath`）
   - 后台构建预填：`npm ci + npx tsc -p tsconfig.json`（产物 → `dist/`）
   - 预填后可改
3. 进入新建页：模块 / 环境下拉可填，名 / key 可填，页头实时联动

## 5. 新建模块页（模块列表 → 「新建模块」）

独立页（非弹窗），类型决定目录与运行字段：

| 类型 | 代码目录 | 其他字段 |
|---|---|---|
| 前端（micro-frontend） | `apps/<key>` | **publicPath** = `/<key>/` |
| 后台（backend） | `servers/<key>` | **pm2 进程名** = `web-<key>` |

字段：模块名 / 模块 key（保存后不可修改）/ 类型 / 代码目录 / publicPath 或 pm2 / 默认环境。
**输入 key 时目录、publicPath、pm2 实时联动**；不相关字段自动隐藏。

> 模块是**元数据真相源**：目录 / publicPath / pm2 / 默认环境决定流水线脚本里的 `${MODULE_DIR}` 与产物路径。

## 6. 节点抽屉（点画布节点打开）

**三 Tab**：节点 / 变量 / 参数（写脚本时随手查键名）。

**「节点」Tab 按类型分流**：

| 节点类型 | 表单内容 |
|---|---|
| 执行（shell） | 节点名 / key / **脚本文本域** / 超时；底部有「语法校验」 |
| 审批（approval） | 审批人（不选 = 所有持权限者）/ 超时 / 超时未批（终止 / 自动通过）/ 拒绝后（终止 / 回滚）；**没有脚本编辑器** |

抽屉底部固定：取消 · 语法校验（仅 shell）· 保存。

**「变量」Tab**：检索框 + 按需展开的「新增变量」小面板（键 / 值 / 说明 / 密钥）+ 定宽表格（键/值/说明/密钥/操作，溢出省略 + `title` 悬停看全文）。
**「参数」Tab**：只读，按来源分组（平台内置 → 配置中心 → 全局变量 → 本条流水线）。

## 6.5 失败回滚语义（2026-09-15 收口）

| 层 | 真相源 | 当前状态 |
|---|---|---|
| 回滚**锚点**（哪个节点失败触发回滚） | 节点上的 **watchdog** 标记（`resolveRunStages` → `rollbackAnchor`） | **UI 已开放**：节点抽屉「失败自动回滚锚点（watchdog）」开关，全局至多一个（互斥）；**没有 watchdog → 永不自动回滚** |
| 回滚**开关** | 流水线级 `rollbackOnFailure`（`previous` / `none`） | 编辑页已移除该字段，payload 保持默认 `previous` |

即：**当前默认不会自动回滚**（终态四节点没有任何节点标 watchdog）。后续若要开放：
① 节点抽屉加「watchdog（失败自动回滚锚点）」勾选；② 或把 `rollbackOnFailure` 收敛进节点并弃用流水线级字段（需同步改引擎 `pipeline.service.ts` 的 `p.rollbackOnFailure !== 'none'` 判断）。
