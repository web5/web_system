# 页面规格 · 企微移动端「发布结果」S5（只读）

> 2026-11-06 · 14 号方案（`30-任务产物/2026-11-05-console企微审批开工/14-票据兑换整合进审批流-技术产品方案.md`）L1 闭环第五屏
> 路由 `/m/approve/:id/run` · 组件 `apps/deploy-console/src/views/m/RunMobile.vue`

## 1. 这一屏解决什么

S4 结果态只能说明「审批结果」，说不出「发布成没成」。改造前要回答这个问题只能
**换 30 分钟平台会话跳桌面 SPA** —— 为一个只读动作付一次提权，且手机上侧栏吃掉半屏。

本屏用**同一张审批票据**回答同一个问题，凭据不出审批域。

## 2. 屏结构（自上而下，390px 视口首屏尽量不滚动）

| 区 | 内容 | 判据 |
|---|---|---|
| 顶栏 | `企业微信 · 发布结果` | 与 S1/S4 同一视觉语言 |
| 状态头 | 状态标记（✓ / × / ●）+ 状态文案 + `模块 · 环境 · 模式` | 状态文案必须与后端 `status` 一一对应，不得自造 |
| 运行提示 | 仅 `live=true` 时出现：「每 5 秒自动刷新」 | 终态必须消失 |
| 关键信息卡 | 运行 id / 版本 / 分支 / 触发（人 · 来源）/ 开始 / 结束 / 耗时 | 缺值显示 `-`，不显示 `undefined` / `NaN` / `Invalid Date` |
| 失败原因卡 | 仅 `errorBrief` 存在时出现；下方固定一行「完整日志请到桌面控制台查看」 | 不得渲染日志正文 |
| 节点进度 | 节点名 + 四态（已完成 / 进行中 / 失败 / 未开始） | 状态由前端 `stepState` 推导，后端只给原始 `status/stage/stages` |
| 免责句 | 「审批通过不等于发布成功」 | 必现 |
| 底部操作 | 主：返回审批单；次：桌面控制台 | 桌面控制台必须弹确认层 |

## 3. 数据契约

`GET /console/api/wecom/approvals/:id/run`，`Authorization: Bearer <审批票据>`

- 成功：`{ code: 0, data: WecomRunSnapshot }`
- 票据过期：401 → 冷提示「链接已过期，请从企业微信重新进入」
- 非本单票据：403 → 冷提示「无访问权限」
- 通道关闭：404

字段定义见 `servers/deploy-console/src/wecom/wecom-approval.service.ts` 的 `WecomRunSnapshot`。

## 4. 硬约束（改代码时别拆）

| 约束 | 为什么 |
|---|---|
| 不展示日志正文 | 日志含内部路径与环境变量，卡② 脱敏边界不因换页面而放松 |
| 不提供重跑 / 回滚 / 改配置入口 | 高风险操作要在宽屏完整上下文里做，手机误触代价过高 |
| 桌面入口必须二次确认并写明「30 分钟后台权限」 | 把授权面扩大显式化，不让它藏在一次点击里 |
| 运行中轮询上限 5 分钟 | 手机端不做无限轮询；超时让用户主动刷新或重进 |
| 节点状态复用 `pipeline.stages.ts` | 后端复制一份展示状态机 → 桌面与手机两套判定必然漂移 |

## 5. 验收

| # | 场景 | 通过标准 |
|---|---|---|
| V1 | S4 点「查看发布结果」 | 落在 `/m/approve/:id/run`，**不出现登录页**，不写 localStorage |
| V2 | 运行中进入 | 5 秒后自动刷新，状态从「发布中」变「发布成功」 |
| V3 | 失败运行 | 失败原因卡出现，且**不含** `/home/` `/Users/` 等绝对路径 |
| V4 | 票据过期后进入 | 冷提示 + 「去桌面控制台查看」，不白屏 |
| V5 | 点「桌面控制台」 | 先出确认层；确认后才换会话并跳转 |
| V6 | 390×844 视口 | 无横向滚动条，底部按钮不遮挡内容 |
