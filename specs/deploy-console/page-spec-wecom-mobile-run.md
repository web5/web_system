> 理由：横向压缩的节点条在流程变长时必然挤压；手机上「看懂了就走」比「什么都能干」重要。

## 1. 这一屏解决什么

S4 结果态只能说明「审批结果」，说不出「发布成没成」。改造前要回答这个问题只能
**换 30 分钟平台会话跳桌面 SPA** —— 为一个只读动作付一次提权，且手机上侧栏吃掉半屏。

本屏用**同一张审批票据**回答同一个问题，凭据不出审批域。

## 2. 屏结构（自上而下，390px 视口）

| 区 | 内容 | 判据 |
|---|---|---|
| 顶栏 | `企业微信 · 发布结果` | 与 S1/S4 同一视觉语言 |
| **操作区（顶部）** | 左：`← 返回审批单`；右：`刷新` | 必须固定在流程上方，**不随流程滚动到底部**；流程再长也不用回头找按钮 |
| 状态头 | 状态标记（✓ / × / ●）+ 状态文案 + `模块 · 环境 · 用时` | 状态文案必须与后端 `status` 一一对应，不得自造 |
| 运行提示 | 仅 `live=true` 时出现：「每 5 秒自动刷新」 | 终态必须消失 |
| 失败原因卡 | 仅 `errorBrief` 存在时出现 | 不得渲染日志正文；**不再**出现「去桌面控制台看日志」的引导 |
| **流程（竖向时间轴）** | 一行一个节点：左侧圆点 + 连接线，右侧**节点名（上行）/ 状态（下行）** | 节点名与状态必须分两行，长名称只换行不挤压；状态由前端 `stepState` 推导 |
| 免责句 | 「审批通过不等于发布成功」 | 必现 |

**刻意不出现**：运行 id / 版本 / 分支 / 触发来源 / 开始与结束时间 / 桌面控制台入口 / 底部固定按钮栏。
这些属「排查与动手」场景，需要时再按移动端场景增量加，不在本屏一次性铺开。

## 3. 数据契约

`GET /console/api/wecom/approvals/:id/run`，`Authorization: Bearer <审批票据>`

- 成功：`{ code: 0, data: WecomRunSnapshot }`
- 票据过期：401 → 冷提示「链接已过期，请从企业微信重新进入」
- 非本单票据：403 → 冷提示「无访问权限」
- 通道关闭：404

字段定义见 `servers/deploy-console/src/wecom/wecom-approval.service.ts` 的 `WecomRunSnapshot`。
后端可继续返回 `versionTag / gitBranch / triggerSource` 等字段（契约向后兼容），**本屏不渲染**。

## 4. 硬约束（改代码时别拆）

| 约束 | 为什么 |
|---|---|
| 不展示日志正文 | 日志含内部路径与环境变量，卡② 脱敏边界不因换页面而放松 |
| 不提供任何写操作 / 提权入口 | 重跑、回滚、改配置要在宽屏完整上下文里做；手机误触代价过高。本屏零写操作 = 零授权面 |
| 流程必须竖排且节点名与状态分行 | 横向节点条在 8+ 节点时必然挤压；竖排只会往下延伸 |
| 操作区固定在顶部 | 流程长到需要滚动时，底部按钮会滚出视野或遮挡最后几个节点 |
| 运行中轮询上限 5 分钟 | 手机端不做无限轮询；超时让用户手动刷新或重进 |
| 节点状态复用 `pipeline.stages.ts` | 后端复制一份展示状态机 → 桌面与手机两套判定必然漂移 |

## 5. 验收

| # | 场景 | 通过标准 |
|---|---|---|
| V1 | S4 点「查看发布结果」 | 落在 `/m/approve/:id/run`，**不出现登录页**，不写 localStorage |

| V5 | 顶部操作区 | 两个按钮（返回审批单 / 刷新）在状态头之上，滚动后仍可见 |
