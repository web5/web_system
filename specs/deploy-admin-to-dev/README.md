## 这份 spec 在解决什么（一句话）

> 本机控制台选「环境 = dev」发布 admin，**过去只是打了个标签**（产物落本机、指针写本机）；
> 本次让它**真的发到 dev**：本机负责构建 + 投递 + 探活，dev 机负责写版本 + 切指针。

## 术语速查

| 术语 | 含义 |
|---|---|
| 发布目录 `RELEASE_WORKSPACE` | 各机器上用于发布的 git clone 目录（本机 `~/web_system_release`；dev 机 `/data/web_system`） |
| 版本引用 `default/<commit>` | 产物目录与 manifest 用的完整版本号：`<模板 key>/<短哈希>` |
| 指针 | `deploy_deployments` 表里"当前生效版本"，gateway 读它出 manifest |
| 复用产物 | 目标 commit 的产物已存在 → 跳过拉码 / 构建 / 投递 |
| 平台托管 / `locked` | 脚本存 DB 但接口拒写、页面只读（如 `git` 节点） |
| 4a / 4b | 4a = 复用远端 `POST /api/hooks/release`（本期选定）；4b = 另建"只写库"内部接口（不再考虑） |
