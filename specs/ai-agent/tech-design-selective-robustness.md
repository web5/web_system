# ai-agent 选择性鲁棒性改造方案
> 状态：方案设计中 ｜ 2026-11-11

## 1 背景与目标

**背景**：`web_system` 的 ai-agent（`packages/agent-core` + `servers/ai-agent`）里存在多处「LLM 决策点」——意图分类、记忆提取、记忆摘要、对话压缩、Agent 主循环的上下文组装。这些决策点对 prompt / 上下文的措辞敏感，历史上已出现过「换措辞 / 换参数就翻车」的事故（详见 §2）。

**方法论来源**：论文《A Framework for Context Enrichment and Selective Robustness in LLM Social Agents》（arXiv:2611.06914）提出的「选择性鲁棒性」双指标与「受控上下文富集」框架，其通用提炼见 `~/AiWorkspace/20-私域资产/LLM智能体选择性鲁棒性-论文分析结论.md`（本文不复制其正文）。

**目标**：把「选择性鲁棒性」从一个"事后偶然告警才能发现"的问题，变成一个**可测量、可回归、发布前就能拦住**的门禁。具体分三阶段（§4）。

**非目标**：本期不改业务行为本身（不调 prompt 措辞、不改模型），只补"测量与门禁"能力。

## 2 现状盘点：5 个 LLM 决策点

| # | 模块（绝对路径） | 论文对应 | 现状 | 已踩坑 |
|---|---|---|---|---|
| 1 | `packages/agent-core/src/core/intent-classifier.ts` | 表面不变性 + 世界响应性 | 三级快通道 + LLM 兜底；单测为固定断言 | 🔴 3 起（见下） |
| 2 | `servers/ai-agent/src/agent/user-memory-update.hook.ts` | 规范性锚定（EXTRACT_PROMPT） | 固定 prompt，无表面扰动测试 | 无 |
| 3 | `servers/ai-agent/src/agent/memory/llm-internal.controller.ts` | 通用社会背景（profile 注入源） | 摘要 prompt 固定；#8273 刚调过纯文本格式口径 | 无 |
| 4 | `packages/agent-core/src/memory/compaction.ts` | 表面不变性（摘要漂移） | SUMMARY_PROMPT 固定 | 无 |
| 5 | `packages/agent-core/src/core/agent-engine.ts` | 上下文富集组装 | systemPrompt = base + 技能目录 + profile + 历史摘要，未按功能标注 | 无 |

**意图分类器已踩的 3 坑**（均记录在 `intent-classifier.ts` 头注释）：
- 2026-09-28：硬编码 taxonomy 与注册表漂移 → 规则永不命中 → **100% 兜底**；
- 2026-10-08：思考 token 吃光输出预算 → 空返回 → **100% 兜底**；
- 2026-10-09：锁定后无规则命中时短路返回 locked → 会话永远无法逃逸（5 轮全 locked）。

**共性根因**：都是"上下文 / 参数的表层变化 → 行为漂移"，且都靠**别的模块偶然告警**才发现，缺一个前置的、系统化的鲁棒性校验。

## 3 核心概念（本文口径）

- **表面不变性**：固定世界下，同一意图 / 输入换 N 种等价表述（同义改写 / 口语化 / 加语气词 / 中英混 / 键值 vs 散文），LLM 输出应稳定。
- **世界响应性**：固定表述下，改变决策相关的输入（规则 / 描述 / 角色），LLM 输出应朝**预先指定**的方向变。

两个指标各自都不充分：只测稳定性会漏掉"木头人"，只测响应性会漏掉"脆皮"（如 Terra 换散文 0.9%→89.9%）。

## 4 改造方案（三阶段）

### 4.1 阶段 1：意图分类器双维回归测试（P0，最先做）

给 `intent-classifier.spec.ts` 补充两类用例，作为**发布前回归门禁**：

- **表面扰动测试**：同一意图换 4 种说法，断言分类到同一 agent；
- **世界对比测试**：改某个 agent 的 `description` / `keywords`，断言分类朝预先指定方向变。

详细骨架见 §5。这是最直接、性价比最高的一步——意图分类器是 5 个决策点里唯一已明确踩过坑的。

### 4.2 阶段 2：user-memory 链路表面不变性测试（贴合当前迭代）

针对正在做的 user-memory「明细 + 摘要双层」（#8229）：

- 记忆提取 `user-memory-update.hook.ts`：同一段对话，`EXTRACT_PROMPT` 换等价措辞，提取的 items 应稳定；
- 记忆摘要 `llm-internal.controller.ts`：同一组明细，摘要 prompt 换等价表述，profile 摘要应稳定。

这一步顺带回答论文悬而未决的问题：**profile 摘要到底是在"锚定决策"还是"填充噪音"**（论文实测"通用社会背景"单独加不一定有用，Terra 响应性甚至 −2.1）。

### 4.3 阶段 3：Agent 上下文块功能标注 + 受控 A/B（中长期）

给 `agent-engine.ts` 的上下文四块按论文功能打标：

| 块 | 论文功能类型 |
|---|---|
| `agent.systemPrompt` 基础 | 最小上下文 |
| 技能目录 `skillLoader.toCatalog()` | 描述性决策锚定 |
| profile `memory.loadProfile()` | 通用社会背景 |
| 历史摘要 `memory.load()` | 决策锚定 |

做一次受控 A/B，看哪块对"稳"和"懂"贡献最大，避免"多喂上下文"的拍脑袋优化。

## 5 阶段 1 测试骨架设计

### 5.1 表面扰动样例（意图分类器）

同一意图「我想查一下今天天气」，4 种等价表述：

| 扰动类型 | 示例输入 | 期望 |
|---|---|---|
| 原始 | 我想查一下今天天气 | tool（或命中关键词的 agent） |
| 同义改写 | 帮我看看现在外面天气怎么样 | 同上 |
| 口语化 | 哎今天天气咋样啊 | 同上 |
| 加语气词 | 你好呀，能不能帮我查查今天天气呀～ | 同上 |
| 中英混 | 帮我 check 一下 weather | 同上 |

**断言**：对每个 agent 的「意图样本组」，5 种表述应分类到**同一个** agentId（允许因规则关键词命中与 LLM 判定走不同 `via`，但最终 `agentId` 必须一致）。

### 5.2 世界对比样例

| 操作 | 预期方向（须预先指定） |
|---|---|
| 给 agent `bianbian` 新增关键词 `[生成图, 出张图]` | 含这些词的输入从 general 转向 bianbian |
| 修改某 agent 的 `description`（如把「情感陪聊」改为「合同风险审查」） | 相关输入的方向性变化（按新描述预期） |
| 删除某 agent 的关键词 | 原关键词命中的输入回落到 LLM / 兜底，不报错 |

### 5.3 断言模板与真模型接入

```
关键约束（与「改造不改断言 = 假绿」同源）：
1. 必须接真模型（ClientRegistry 注入真实 client），mock 会假绿；
2. 扰动样例的「语义等价」由人复核一遍（论文局限 2 的教训）；
3. 世界对比的「预期方向」必须在跑之前写死，不能跑完再解释。
```

接入方式：测试用 `ClientRegistry.getOrFallback('deepseek-v4-flash')` 注入真实 client，标记为**慢测 / 集成测**（默认跳过，CI 夜间 / 发布前手动跑），避免每次单测都打 LLM。

### 5.4 指标口径（对齐论文）

- **表面敏感性** = 各扰动表述分类结果与「规范表述」的平均不一致率（越低越稳）；
- **世界响应性** = 改世界前后分类结果在预期方向上的变化量（越高越"懂事"）。

两个指标都进测试报告，不只看"通过/失败"。

## 6 失败与降级

- 测试接真模型超时 / 不可用 → 标记 skip，不阻塞主链路（与意图分类器"绝不阻塞对话"同原则）；
- 门禁接入方式：先做**独立测试文件 + 手动触发**，跑通并验证稳定后，再考虑接 `研发硬门禁` 的机器门禁（届时需先量存量，只有 100% 通过的项才配做阻断，见 `~/AiWorkspace/20-私域资产/研发硬门禁跨智能体规范.md`）；
- 阶段 3 的 A/B 不改变线上行为，只出报告，供后续 prompt 迭代决策。
