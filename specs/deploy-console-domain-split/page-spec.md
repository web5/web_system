## 1. 页面规格 · 应用列表 `/apps`

| 2 | 应用表格 | `GET /api/dc/apps?kind=&q=` | `a-table` | "还没有应用，点右上「新建应用」注册第一个（如 portal）" |

## 2. 页面规格 · 应用详情 `/apps/:key`

- 页面类型：**详情页**
- 参照页：`ModuleDetail.vue`（保留其 tab 组织方式）+ `PipelineDetail.vue`
- 需求一句话：一个应用的三个面 —— 是什么（概览）、挂在哪（路由）、发到哪（部署）。
- **明确不含**（2026-09-18 用户确认）：「服务环境」（属服务域）、**「环境」Tab**（环境由「环境管理」统一维护，部署 Tab 已按环境展示版本）、前后端混用的「前端 / 后端」切换 Tab

### 页头

- 面包屑：应用管理 / `key`
- 标题：`key`（`.ws-mono`），右侧 `kind` 徽标 + 启用开关
- 副标题：`name` · `repoDir`（`.ws-mono`）
- 主操作：**部署**（primary，触发 `POST /api/dc/apps/:key/deploy`）

### Tab 结构（3 个：概览 / 路由 / 部署）

#### Tab 1 · 概览

| 序 | 模块 | 数据来源 |
|---|---|---|
| 1 | 基本信息卡（key/名称/类型/父应用/仓库目录/入口/publicPath/描述） | `GET /api/dc/apps/:key` |
| 2 | 各环境版本卡（env × 当前版本 × 发布时间 × 操作人） | `GET /api/dc/apps/:key/deployments` |

#### Tab 2 · 路由（shell 挂载）

| 序 | 模块 | 承载组件 | 空态 |
|---|---|---|---|
| 1 | 路由表格（挂载路径 / 激活规则 / 需鉴权 / 排序 / 启用） | `a-table` 可编辑行 | "该应用尚未挂载到 shell，点「新增挂载」配置入口（如 /admin）" |
| 2 | 批量保存条 | 底部 sticky primary 按钮「保存路由变更」 | — |

- 列：挂载路径（`.ws-mono`）/ 激活规则（`.ws-mono`）/ 需鉴权（switch）/ 排序（数字 `tabular-nums`）/ 启用（switch）/ 操作（删除）
- **冲突检测**：`mountPath` 与同 shell 已有路由重复 → 行内红色提示 + 保存按钮禁用 + tooltip 说明冲突方（FR-2.2）
- **FR-2.3**：保存只写配置，不触发发布；按钮文案明确为「保存路由变更」，成功后提示 "已保存，需到「部署」页签发布后生效"

#### Tab 3 · 部署（按环境展示版本）

| 序 | 模块 | 数据来源 |
|---|---|---|
| 1 | 环境版本表：行 = 环境（`dev`/`1`/`2`/`prod`），列 = 当前版本 / 发布时间 / 发布人 / 状态 / 操作 | `GET /api/dc/apps/:key/deployments` |
| 2 | 行内操作（**每行均提供**）：**部署** / 切换版本 / 回滚 | 见下 |

| 操作 | 触发 | 反馈 | 破坏性 | 完成后 |
|---|---|---|---|---|
| 部署 | 行内「部署」 | 带该环境发起发布（写 `taskId`） | 否 | 刷新 |
| 切换版本 | 行内「切换版本」 | **弹窗选目标版本**（下拉：`版本 · 时间 · 发布人`，排除当前版本）→ 确认 | 是（影响该环境加载版本） | 刷新 |
| 回滚 | 行内「回滚」 | **弹窗选回滚到的版本**（下拉，**默认预选上一版本**）→ 确认 | 是（覆盖该环境目录产物） | 刷新 |

- 空态："尚无部署记录，点「发布」发起首次部署"

- 副标题：`name` · `repoDir` · `healthPath`

### Tab 结构（5 个，用 `a-tabs`；**默认激活「接口」页签** —— Q 已确认「点服务进来就是接口列表」）

#### Tab 1 · 概览

- 基本信息卡（key/名称/类型/仓库目录/pm2 进程名/默认端口/探活路径/未登记接口策略 `unknownPolicy`/描述）
- 各环境状态卡（env × 运行时 × 主机 × 端口 × 最近部署版本 × 健康状态）

- 表格列：环境（全环境默认 / 指定 env）/ 路径前缀（`.ws-mono`）/ 剥离前缀 / 重写到 / 上游覆盖 / 超时 ms（`tabular-nums`）/ 鉴权模式 / 优先级（`tabular-nums`）/ 启用

- 交互：新增（drawer）、行内编辑、批量导入（UPSERT，**只补全空字段**，导入结果弹层显示"新增 N / 跳过 M / 补全 K"）、删除

### 5.1 环境详情 `/environments/:envId`（2026-09-18 用户确认新增）

- 页面类型：**详情页**
- 参照页：`AppDetail.vue`（同域详情页骨架）
- 需求一句话：环境是"一套完整运行上下文"——前端按 envId 加载产物目录，后端由该环境指向各服务地址。

| Tab | 内容 |
|---|---|
| 基本信息 | 环境 ID（不可改）/ 名称 / 归属站点 / 排序 / 前端产物目录 `/static/modules/<appKey>/<envId>/`；页头带启用开关 |

**后端服务指向 · 交互**

| 操作 | 触发 | 反馈 | 破坏性 | 完成后 |
|---|---|---|---|---|
| 修改指向 | 行内「修改」 | drawer/modal：目标主机 + 端口 + 上游地址（留空按 主机+端口 自动拼装） | 否（但影响该环境 API 走向） | 刷新表格 |
| 保存 | modal OK | success「已更新 X 在 Y 的指向」；注明网关缓存 ≤60s 生效 | — | — |

- 空态："该环境尚未配置任何服务指向，将使用服务默认地址"
- 边界：主机留空 → 保存前校验必填（防静默指向 localhost，对应 B4）
- 说明文案：「服务本身的注册（仓库目录 / 探活路径 / 接口清单）在『服务管理』内维护；此处只配该环境的指向」

- **切换环境 = 整页重载**（`location.reload()`）：环境改变整套产物与接口上下文，局部更新会造成新旧混杂；重载后停留当前路由。
- envId 规则与回退逻辑见 `environment-design.md` §2.2：系统自增数字、内置保留字、找不到回退 dev。

## 6. 页面规格 · 主机管理 `/hosts`

- 页面类型：**列表/管理页**
- 参照页：`ServiceManager.vue`
- 需求一句话：登记部署目标机器（含运行时类型），供服务环境引用。
- 页头：标题「主机管理」，副标题「部署目标主机与主机组，供服务环境引用」，主操作「新增主机」
- 列：主机组名（`.ws-mono`）/ 地址（`.ws-mono`）/ SSH 用户 / 部署根目录（`.ws-mono`）/ 运行时（pm2|docker 中性 tag）/ 标签 / 启用 / 操作
- 交互：新增/编辑（drawer）、删除（有服务环境引用时阻断并列出）、连接测试（loading → 结果）
- 状态：空态"尚未登记主机，服务环境将无法配置目标机器"

## 7. 跨域一致性约定（两个域必须一致）

1. **详情页骨架一致**：概览 /（路由|网关路由）/（接口）/ 环境 / 部署 —— 两域 Tab 顺序与视觉一致，降低学习成本。
2. **部署矩阵一致**：应用与服务都用「环境 × 实例」矩阵表达当前状态。
3. **主操作唯一**：每页 primary ≤ 1（列表页 = 新建，详情页 = 部署）。
4. **枚举不配色**：`kind`、`runtime`、`method` 全部中性徽标；只有状态（健康/失败/未知）用语义色。
5. **代码类字段统一 `.ws-mono`**：key、路径、端口、sha、主机、目录。
6. **数字统一 `tabular-nums`**：端口、超时、限流、优先级、副本、排序。
