> 状态：待用户确认原型后才进入编码（动作门第 3 步）

## 2 对话页 · 音乐卡片

### 2.1 触发与渲染
- SSE 新增 `card` 事件（`kind: 'music'`）→ 聊天流插入一条 `type='music-card'` 的 AI 消息。
- ⚠️ 现有 `ChatMsg.card` 字段**已被「推荐译文」卡片占用**（`pages/chat/index/index.wxml:57`），音乐卡片必须用**独立消息类型**区分，不能复用 `card` 布尔值。

### 2.2 卡片结构（宽 274px，与译文卡同一设计语言）

```
┌ 头部：[为你推荐] 按你的口味 · 安静        ← tag 用 --brand-soft/--brand-txt
├ 歌曲 1：七里香            周杰伦
│        你提过喜欢他，这首慢板最稳
├ 歌曲 2：…（1–3 首，每首一行标题 + 一句理由）
├ 操作行：[换一批] [不感兴趣] [去 QQ音乐听]   ← 主按钮唯一，占满剩余宽度
└ 脚注：跳转后进入 QQ音乐首页，歌名已复制，在搜索框粘贴即可；本小程序不提供音频播放
```

⚠️ **不能直达歌曲**：`wx.navigateToMiniProgram` 传未知 `path` 会被忽略或回落首页（官方口径 + 方案 §3.3.4），
所以原设计的 `search_template`（`pages/search?keyword={keyword}`）**一期作废**。
替代做法：点主按钮时**先把歌名写进剪贴板**，再跳转，弹窗文案写明「歌名已复制，进入后粘贴搜索」。

- 主按钮文案来自配置：`去 {provider.name}听`（一期 = QQ音乐）。
- 操作行次操作为描边 chip，不与主按钮争视觉权重。

### 2.3 状态矩阵

| 状态 | 表现 |
|---|---|
| 加载中（等待 card 事件） | 卡片骨架：3 行 `.sk` 骨架条 + 头部先出 |
| 正常 | 1–3 首歌曲 |
| 换一批进行中 | 骨架 900ms 后出新一批；期间「换一批」禁用 |
| 不感兴趣 | Toast「已记下：少推 {歌手}」+ 自动换一批 + 写入 dislikes |
| 跳转失败 / provider 不可用 | Toast「跳转失败，可手动搜索：{歌名}」，卡片保留 |
| 历史回看 | 按 `type='music-card'` 原样还原，不退化为纯文本 |

## 4 音乐口味页（新建二级页 · **已定方案 B 扁平列表**）

> 选型结论：**方案 B**（用户拍板）。方案 A 未采纳，保留在此备查。

### ✅ 方案 B · 扁平列表（采纳）
- 单一分组「全部标签」：喜欢类橙色 chip（`--brand-soft`），不想听类红色 chip（`--danger-soft`）并带「不想听」前缀，× 可删。
- 「手动补充」由 AI 自动归类（placeholder 说明「自动归入风格 / 歌手 / 场景」），一期前端先入场景池。
- 优点：页面短、增删快；缺点：类型信息弱化，分类靠 AI 兜底 —— 数据结构仍按 `user_taste_profiles.data` 三类存，只是前端不分组展示。

### 方案 A · 三类分组（未采纳，备查）
- 「喜欢的风格」「喜欢的歌手」「喜欢的场景」三个分组，橙色 chip（`--brand-soft`），× 可删。
- 有「不想听」数据时显示红色分组（`--danger-soft`）。
- 「手动补充」输入框默认归入「喜欢的风格」，placeholder 说明。
- 优点：结构清晰、AI 写入/前端渲染同构；缺点：分组多、页面偏长。

**方案 B · 扁平列表**
- 单一分组「全部标签」：喜欢类橙色 chip，不想听类红色 chip 并带「不想听」前缀。
- 「手动补充」由 AI 自动归类（placeholder 说明），一期前端入场景池。
- 优点：页面短、像标签云，随手增删快；缺点：类型信息弱化，分类靠 AI 兜底。

两方案共通：字段校验（空或 >12 字 → 字段级红框 + 文案）；「清空口味记忆」→ 底部弹层二次确认（写明后果）；空态（图标 + 「还没记住你的口味」+ 唯一恢复入口「去对话里说说」→ 跳对话页）。

## 5 视觉 Token（沿用 `app.wxss`）

- 主色 `--brand: #F97316`；文本/选中态 `--brand-txt: #EA580C`（AA 达标）；卡片底 `--card: #FFFFFF`；页面底 `--page-bg: #F7F4F0`；分隔 `--line: rgba(60,60,67,.12)`。
- 字重只用 400 / 500 / 600；字号三级（14 / 12.5 / 10.5）。
- 间距取 8 的倍数；圆角 8 / 12。
- 图标内联 SVG（tabler 风格），**禁 emoji**；禁裸 hex（色值一律走 token）。

## 6 平台原生能力占位（不伪装实现）

| 能力 | 原型处理 | 真机语义 |
|---|---|---|
| 跳转 QQ音乐小程序 | 「即将跳转…」确认弹窗 + Toast 占位 | 由微信客户端弹确认；**必须由用户点击触发**（基础库 2.3.0 起禁止自动跳转）；用户取消（`errMsg` 含 `cancel`）**静默处理，不提示、不重试** |
| appId 失效兜底 | 原型未体现 | 真机链路：appId 跳转失败（非 cancel）→ 用 `shortLink` 再试一次（基础库 2.18.1+，来源「小程序菜单→复制链接」）→ 仍失败才提示「已复制歌名」 |
| 连点防抖 | 原型未体现 | 1.2s 内重复点击只触发一次，避免多个确认框排队 |
| QQ音乐 appid / 定位 path | 原型不体现 | 走 `music_providers` 配置表；真机确认后填库，不硬编码 |
| 音频播放 | 卡片脚注显式声明「本小程序不提供音频播放」 | 一期不做 |
| 底部 TabBar | 原型三 Tab 常驻，便于评审导航 | 落地时对话页按现状隐藏 TabBar（`pages/chat/index/index.wxml:1` 注释），「我的」由「+」菜单承接；原型保留仅为避免死链 |
