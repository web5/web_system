# 迷你规格 · 朗读按钮「能力未配置」第 4 态

> 日期：2026-10-09 ｜ 模板：Quick（小改）｜ 配套：`specs/tts-continuity/design.md`
> 原型：`apps/portal/prototype/index.html`（commit `eba1ce6a`）

## 1. 定位

- **页面/组件**（四处接入，缺一处即事故形态在已覆盖场景内复现）：
  - `apps/portal/src/views/AiChat.vue` · ① 对话 AI 回答操作条 ② **对话内嵌翻译卡 `tcard` 的 ops 行**
  - `apps/portal/src/views/Translate.vue` · 翻译结果卡操作行
  - `apps/portal/src/views/Glossary.vue` · 生词本卡片
- **类型与参照**：不变（沿用各页现有操作条 / 操作行 / 卡片）
- **需求一句话**：朗读能力在服务端不可用时，把「不可用」信号**前移到点击之前**——按钮直接给出不可用形态并说明原因，替代「点一下才知道失败」。

## 2. 改动内容

| # | 项 | 内容 |
|---|---|---|
| 1 | 新增状态 | 朗读按钮由三态（朗读 / 请稍候… / 停止）扩为 **四态**，新增 `unavailable` |
| 2 | 不可用表现 | 文案改「朗读不可用」+ `.is-disabled` 视觉降级（`opacity:.5;cursor:not-allowed`）<br>+ `aria-disabled="true"` + `title`「朗读服务暂不可用，请稍后再试」+ 点击 toast 同文案 |
| 2.1 | ⚠️ **不用原生 `disabled`** | 桌面 Chromium 下 disabled 元素**不触发 `title`（tooltip 永不出现）**、**键盘不可达** → 退化成「无声禁用」，比点了报错更糟。用 `aria-disabled` + 点击拦截，保留可聚焦与反馈 |
| 2.2 | 文案不依赖 tooltip | 信息写在**按钮文案本身**；tooltip 只补「怎么办」（请稍后再试），不承担唯一信息 |
| 2.3 | C 端话术 | tooltip / toast **不暴露**「服务端 TTS 凭据缺失」内部细节；内部原因留给 runbook 与 `/ai/tts/health` |
| 2.4 | 不带喇叭图标 | 翻译卡启用态本无图标，禁用态凭空加图标会让「禁用态比启用态更重」；三处形态统一 |
| 3 | 数据来源 | `GET /api/ai/tts/health` → `{ configured, streamConfigured }`；`configured=false` 即置不可用 |
| 4 | 取值时机 | 进入含朗读按钮的页面时拉一次，结果存模块级变量（不每点一次拉一次） |
| 5 | **拉取中** | 按「可用」渲染 —— 避免禁用态闪烁与误伤；不新增骨架态 |
| 6 | **拉取失败** | **视为可用**（不因健康检查自身故障而误禁用）—— 沿用现有点击后报错路径 |

## 3. 交互影响

- 需补状态矩阵一格：**能力不可用**（区别于「加载中 / 空 / 错误」）
- 不影响播放中 / 合成中 / 结束复位的原有三态流转
- 不新增弹窗、不新增跳转
- 出路：不可用态给出「请稍后再试」；凭据补上后**需刷新页面**才恢复（见 §6）

## 4. 涉及 Token

- 视觉降级复用既有 `.btn:disabled` 的 `opacity:.5`，**不新增裸色值**
- hover 规则加 `:not(.is-disabled)`，避免禁用态 hover 仍变品牌橙（视觉暗示「可点」）
- 图标沿用现有 `I.vol` 内联 SVG（仅启用态），不新增 emoji

## 5. 状态覆盖自查

- [x] 加载中（合成中「请稍候…」）
- [x] 能力不可用（禁用 + tooltip 原因）← 本次新增
- [x] 失败可重试（点击后报错由 `tts.ts` 单次提示真实原因）
- [x] 禁用有 tooltip 原因
- [x] 无弹窗套弹窗

## 6. 风险 / 待澄清

| # | 项 | 处理 |
|---|---|---|
| 1 | `streamConfigured=false` 但 `configured=true`（只缺 AppId）的**半残态**是否也禁用？ | **不禁用**——整段仍可用，禁用会误伤；半残态由端侧自动回退（`tts.ts` 已实现） |
| 2 | health 端点是否需鉴权？ | 沿用现有 `AuthGuard`，与 speak/stream 一致（#261 已按此实现） |
| 3 | 小程序端是否同步？ | 本次**仅 PC portal**，小程序另议 |
| 4 | 凭据补上后按钮何时恢复？ | 需**刷新页面**（health 只在进页时拉一次）。这是服务端故障类不可用态的固有限制；本次不为此加轮询/重试按钮——判据上属「重要」不属「阻塞」，如要更即时反馈另开任务 |
| 5 | 禁用控件对比度 | `.is-disabled` 沿用既有 `opacity:.5`，与存量 `.btn:disabled` 一致（**不新增第二套透明度**）；WCAG 1.4.3 对 inactive 控件有豁免，且信息已由文案承载，不依赖颜色/对比度单独传达 |
