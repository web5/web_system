0一句话结论

意图识别在主对话里落地，是 1 个新服务 + 2 个新文件 + 5 处改动 + 1 条 migration， 核心动作只有一个：在 agent.controller.ts 启动 stream 之前，把 dto.agentId 从「客户端传死」变成「服务端解析出来的」，其余（agent 执行、SSE、记忆、埋点结构）全部不动。

1现状执行链：改动落在哪一段

先把真实链路摆出来，才知道插入点在哪。全部基于当前代码。

1
小程序 services/contract-api.ts
POST /api/ai-agent/agent/run，body 里 agentId:'contract-risk'（写死）
2
gateway 转发 → ai-service
3
servers/ai-service/src/agent/agent.controller.ts @Post('run')
鉴权 → 设 SSE 头 → agentRegistry.get(dto.agentId) 取快照（用于埋点）→ 启动 stream
4
agent-runner.ts → agent-engine.ts

5

每个事件 res.write 推给客户端，同时收进 steps；遇到 final 记答案

三个现状事实，直接决定实现方式 ① AgentRunDto.agentId 是必填（@IsString() 且没有 @IsOptional()）→ 要支持 auto 必须先放开。
② 埋点第 3 步就已经取了 agent 定义快照，用的是 dto.agentId；如果直接把 'auto' 传进来， 这里会 get('auto') 抛错被 catch 吞掉，导致 systemPrompt 快照为空 → 埋点静默降级。必须一起改。
③ ChatOptions 只有 temperature / maxTokens / topP， 没有 JSON mode / response_format（packages/agent-core/src/clients/base-ai.client.ts:81） → 分类器的结构化输出只能靠 prompt 约束 + 自己解析，必须写容错。

4分类器实现

放 agent-core（纯 TS），不碰 Nest、不碰 DB，方便单测和复用。

4.1 三级快通道

级别触发延迟成本说明
L1 显式@星座 … / 发现页进入 / 已锁定00最高优先级，直接返回
L2 规则关键词 + 正则~0ms0覆盖约 70–80% 日常输入
L3 LLM规则未命中150–400ms低必须用 flash 档模型
L4 兜底超时 / 解析失败 / 未知 agent00一律 general

4.2 核心代码

// packages/agent-core/src/core/intent-classifier.ts
import { BaseAiClient } from '../clients/base-ai.client';

export type IntentVia = 'explicit' | 'locked' | 'rule' | 'llm' | 'fallback';

export interface IntentResult {
  agentId: string;
  confidence: number;
  via: IntentVia;
}

export interface ClassifyOptions {
  /** 已知 agentId 白名单（从 AgentRegistry.list() 取，防止路由到未注册 agent） */
  candidates: string[];
  /** 会话已锁定的 agent（有则优先，除非显式切换） */
  lockedAgentId?: string;
  /** LLM 分类超时（ms），超时即兜底 */
  timeoutMs?: number;
}

const RULE_TABLE: Array<{ agentId: string; kw: RegExp; confidence: number }> = [
  { agentId: 'translate',  kw: /(翻译|翻成|译成|用(英|日|德|法|韩)文?怎么说|英文怎么讲)/, confidence: .92 },
  { agentId: 'horoscope',  kw: /(星座|运势|星盘|塔罗|八字|生肖|上升星座|水逆)/,            confidence: .93 },
  { agentId: 'tool',       kw: /(查一下|帮我算|汇率|天气|快递|股价|今天几号|单位换算)/,     confidence: .88 },
  { agentId: 'baike',      kw: /(是什么|为什么|原理|如何工作|介绍一下|区别是|科普)/,        confidence: .80 },
  { agentId: 'emotion',    kw: /(好累|难受|emo|焦虑|睡不着|想聊聊|心情不好|压力大)/,        confidence: .85 },
];

const CLASSIFY_PROMPT = `你是意图分类器。只输出一行 JSON，不要任何解释、不要 markdown 围栏。

可选 agent：
- emotion   情感陪聊、情绪倾诉、安慰共情
- baike     百科科普、知识问答、原理讲解
- horoscope 星座、运势、性格、塔罗（命理类，需免责）
- translate 语言翻译、润色、多语种互译
- tool      工具服务：查汇率/天气/快递/计算/实时信息
- general   以上都不是，或输入过短无法判断

输出格式：{"agentId":"xxx","confidence":0.9,"reason":"10字内"}
confidence 低于 0.6 时直接选 general。`;

export class IntentClassifier {
  constructor(
    private readonly client: BaseAiClient,   // ← 注入 flash 档，不要主对话模型
    private readonly timeoutMs = 1200,
  ) {}

  async classify(userInput: string, o: ClassifyOptions): Promise<IntentResult> {
    // L1-a 显式指定：@agent 前缀
    const at = userInput.match(/^@([a-z0-9-]+)[\s:：]*/i);
    if (at && o.candidates.includes(at[1])) {
      return { agentId: at[1], confidence: 1, via: 'explicit' };
    }

    // L1-b 会话锁定：已有 agent 且未显式切换 → 沿用（不做每轮重分类）
    if (o.lockedAgentId && o.candidates.includes(o.lockedAgentId)) {
      return { agentId: o.lockedAgentId, confidence: 1, via: 'locked' };
    }

    // L2 规则
    for (const r of RULE_TABLE) {
      if (r.kw.test(userInput) && o.candidates.includes(r.agentId)) {
        return { agentId: r.agentId, confidence: r.confidence, via: 'rule' };
      }
    }

    // L3 LLM 分类（超时/失败 → L4）
    try {
      const raw = await this.withTimeout(
        this.client.chat(
          [
            { role: 'system', content: CLASSIFY_PROMPT },
            { role: 'user', content: userInput.slice(0, 500) },
          ],
          { temperature: 0, maxTokens: 60 },   // ← 0 温度 + 限长，压成本
        ),
        o.timeoutMs ?? this.timeoutMs,
      );
      const parsed = this.parse(raw, o.candidates);
      if (parsed) return parsed;
    } catch { /* 落到 L4 */ }

    // L4 兜底
    return { agentId: 'general', confidence: .3, via: 'fallback' };
  }

  /**
   * 解析容错：ChatOptions 没有 JSON mode，模型可能输出围栏、前后废话、或非法 agentId。
   * 三道防线：提取首个 JSON → 校验 agentId 在白名单 → 否则 null。
   */
  private parse(raw: string, candidates: string[]): IntentResult | null {
    if (!raw) return null;
    const cleaned = raw.replace(/```(?:json)?/g, '').trim();
    const m = cleaned.match(/\{[\s\S]*?\}/);
    if (!m) return null;
    try {
      const j = JSON.parse(m[0]);
      const id = String(j.agentId ?? '').trim();
      if (!candidates.includes(id)) return null;          // 幻觉出未知 agent → 丢弃
      const c = Number(j.confidence);
      return { agentId: id, confidence: Number.isFinite(c) ? Math.min(Math.max(c, 0), 1) : .6, via: 'llm' };
    } catch { return null; }
  }

  private withTimeout<T>(p: Promise<T>, ms: number): Promise<T> {
    return Promise.race([
      p,
      new Promise<never>((_, rej) => setTimeout(() => rej(new Error('classify timeout')), ms)),
    ]);
  }
}
⚠️ 三个必须遵守的实现约束 ① 分类器必须用 flash 档。当前 agent.module.ts 已注册 TokenHubClient('deepseek-v4-flash')， 直接 clientRegistry.get('deepseek-v4-flash') 复用即可，不用新增模型、不用加 key。 若用主对话同档模型，每次对话 token 成本直接翻倍 —— 这是这套架构唯一持续烧钱的点。
② candidates 必须来自 agentRegistry.list() 实时取，不能写死数组。 否则 admin 后台新增/下线 agent 后，路由表和注册表会对不上。
③ 解析必须容错。没有 JSON mode，实测模型会吐 ```json 围栏或前后废话， JSON.parse 裸调用会抛 —— 上面 parse() 的三道防线是必须的，不是可选优化。

5会话锁定与切换检测

这是决定体验下限的一段。不做锁定的后果：追问「那第二种呢」被切走、同一话题前后人格不一致、成本翻倍。

// servers/ai-service/src/agent/intent/intent.service.ts
@Injectable()
export class IntentService {
  constructor(
    @InjectRepository(Conversation) private readonly convRepo: Repository<Conversation>,
    private readonly registry: AgentRegistry,
    private readonly clientRegistry: ClientRegistry,
  ) {}

  async resolve(params: {
    agentId?: string; userInput: string; conversationId?: string; userId: string;
  }): Promise<IntentResult & { switched: boolean; previousAgentId?: string }> {
    const candidates = this.registry.list().map(a => a.id);

    // 1) 显式传入（含 'auto' 之外的任何值）→ 直接走，不分类
    if (params.agentId && params.agentId !== 'auto' && candidates.includes(params.agentId)) {
      await this.lock(params.conversationId, params.agentId, 'explicit');
      return { agentId: params.agentId, confidence: 1, via: 'explicit', switched: false };
    }

    // 2) 读会话锁定
    let locked: string | undefined;
    if (params.conversationId) {
      const conv = await this.convRepo.findOne({ where: { id: params.conversationId } });
      locked = conv?.agentId ?? undefined;
    }

    const classifier = new IntentClassifier(
      this.clientRegistry.get('deepseek-v4-flash'),   // ← 复用已有 flash client
    );
    const r = await classifier.classify(params.userInput, { candidates, lockedAgentId: locked });

    // 3) 切换判定：只有【显式指定】或【高置信规则/LLM 且与当前不同】才允许切
    const shouldSwitch = !locked
      || (r.via === 'explicit')
      || (r.via === 'rule' && r.confidence >= .88)
      || (r.via === 'llm'  && r.confidence >= .75);
    const finalAgentId = shouldSwitch ? r.agentId : locked!;
    const switched = !!locked && finalAgentId !== locked;

    // 兜底：万一分类出未注册 agent（理论上已被 candidates 过滤）
    if (!candidates.includes(finalAgentId)) {
      return { agentId: locked ?? 'general', confidence: .3, via: 'fallback',
               switched: false, previousAgentId: locked };
    }

    await this.lock(params.conversationId, finalAgentId, r.via);
    return { ...r, agentId: finalAgentId, switched, previousAgentId: locked };
  }

  private async lock(conversationId: string | undefined, agentId: string, via: string) {
    if (!conversationId) return;   // 首轮无会话，由 final 事件回来后再写
    await this.convRepo.update(conversationId, { agentId });
    await this.convRepo.query(
      `UPDATE conversations
          SET intent_history = JSON_ARRAY_APPEND(
                COALESCE(intent_history, JSON_ARRAY()), '$',
                CAST(JSON_OBJECT('agentId', ?, 'via', ?, 'ts', NOW()) AS JSON))
        WHERE id = ?`,
      [agentId, via, conversationId],
    );
  }
}

切换阈值为什么这么定

来源切换阈值理由
explicit（@星座）无条件用户显式指令，必须服从
rule≥ 0.88正则误伤率不低（如「我想了解一下你」命中 baike），宁可不切
llm≥ 0.75LLM 判断更准，但会话中途切换代价大，仍要留余量
fallback不切没把握时保持现状，比乱切安全
