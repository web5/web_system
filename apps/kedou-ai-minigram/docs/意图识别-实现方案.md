# 意图识别在主对话链路的实现方案

> 日期：2026-09-15 ｜ 范围：`servers/ai-service` + `packages/agent-core` ｜ 状态：待评审
> 配套：`多Agent意图路由-架构设计.md`（架构层，回答"该不该做、放哪层"）
> 本文回答："具体改哪几个文件、代码怎么写、怎么测"。路径与字段名均取自 `~/web_system_release` 实际代码。

## 0. 一句话结论

落地成本是 **1 个新服务 + 2 个新文件 + 5 处改动 + 1 条 migration**。
核心动作只有一个：**在 `agent.controller.ts` 启动 stream 之前，把 `dto.agentId` 从「客户端传死」变成「服务端解析出来的」**。其余（agent 执行、SSE、记忆、埋点结构）全部不动。

## 1. 现状执行链：改动落在哪一段

1. 小程序 `services/contract-api.ts` → POST `/api/ai-agent/agent/run`，body 里 `agentId:'contract-risk'`（写死）
2. gateway 转发 → `ai-service`
3. `agent.controller.ts` `@Post('run')`：鉴权 → 设 SSE 头 → `agentRegistry.get(dto.agentId)` 取快照（埋点用）→ 启动 stream
4. `agent-runner.ts` → `agent-engine.ts`：生成 runId，按 agentId 取定义，装配记忆/工具，流式产出 `StreamEvent`
5. controller 循环 `for await (const event of stream)`：`res.write` 推给客户端，同时收进 `steps`
6. `agentLog.recordRun(...)` 异步落库

### 三个现状事实，直接决定实现方式

| # | 事实 | 影响 |
|---|---|---|
| ① | `AgentRunDto.agentId` 是必填（`@IsString()` 且**没有** `@IsOptional()`） | 要支持 auto 必须先放开 |
| ② | 埋点在第 3 步就取了 agent 定义快照，用的是 `dto.agentId` | 直接传 `'auto'` 会 `get('auto')` 抛错被 catch 吞掉 → `systemPrompt` 快照为空，**埋点静默降级**。必须一起改 |
| ③ | `ChatOptions` 只有 `temperature / maxTokens / topP`，**没有 JSON mode**（`base-ai.client.ts:81`） | 分类器结构化输出只能靠 prompt 约束 + 自己解析，**必须写容错** |

### 3.3 时序（关键约束）

1. POST `/ai/agent/run`（body 无 agentId）
2. 服务端解析意图（目标 ≤300ms；规则命中则 ~0ms）
3. **推 `{type:'intent', …}` —— 必须在第一个 token 之前**
4. 正常 token 流（与现状一致）
5. `final` 事件带 conversationId

> ⚠️ **前端必须配合**：小程序侧 `conversationId` 要**每轮回传**。漏传会导致每轮都被当新会话重分类，表现为"同一话题两句由不同 agent 回答"——这是最容易出的线上事故，列 P0 验收项。

## 4. 分类器实现

### 4.1 三级快通道

| 级别 | 触发 | 延迟 | 成本 | 说明 |
|---|---|---|---|---|
| L1 显式 | `@星座 …` / 发现页进入 / 已锁定 | 0 | 0 | 最高优先级 |
| L2 规则 | 关键词 + 正则 | ~0ms | 0 | 覆盖约 70–80% 日常输入 |
| L3 LLM | 规则未命中 | 150–400ms | 低 | **必须用 flash 档** |
| L4 兜底 | 超时 / 解析失败 / 未知 agent | 0 | 0 | 一律 `general` |

### 4.2 核心代码

```ts
// packages/agent-core/src/core/intent-classifier.ts
import { BaseAiClient } from '../clients/base-ai.client';

export type IntentVia = 'explicit' | 'locked' | 'rule' | 'llm' | 'fallback';

export interface IntentResult { agentId: string; confidence: number; via: IntentVia; }

export interface ClassifyOptions {
  candidates: string[];        // 白名单：来自 AgentRegistry.list()
  lockedAgentId?: string;      // 会话已锁定的 agent
  timeoutMs?: number;
}

const RULE_TABLE: Array<{ agentId: string; kw: RegExp; confidence: number }> = [
  { agentId: 'translate', kw: /(翻译|翻成|译成|用(英|日|德|法|韩)文?怎么说|英文怎么讲)/, confidence: .92 },
  { agentId: 'horoscope', kw: /(星座|运势|星盘|塔罗|八字|生肖|上升星座|水逆)/,            confidence: .93 },
  { agentId: 'tool',      kw: /(查一下|帮我算|汇率|天气|快递|股价|今天几号|单位换算)/,     confidence: .88 },
  { agentId: 'baike',     kw: /(是什么|为什么|原理|如何工作|介绍一下|区别是|科普)/,        confidence: .80 },
  { agentId: 'emotion',   kw: /(好累|难受|emo|焦虑|睡不着|想聊聊|心情不好|压力大)/,        confidence: .85 },
];

const CLASSIFY_PROMPT = `你是意图分类器。只输出一行 JSON，不要任何解释、不要 markdown 围栏。

可选 agent：
- emotion   情感陪聊、情绪倾诉、安慰共情
- baike     百科科普、知识问答、原理讲解
- horoscope 星座、运势、性格、塔罗（命理类，需免责）
- translate 语言翻译、润色、多语种互译
- tool      工具服务：查汇率/天气/快递/计算/实时信息
- general   以上都不是，或输入过短无法判断

输出格式：{"agentId":"xxx","confidence":0.9,"reason":"10字内"}
confidence 低于 0.6 时直接选 general。`;

export class IntentClassifier {
  constructor(
    private readonly client: BaseAiClient,   // ← 注入 flash 档，不要主对话模型
    private readonly timeoutMs = 1200,
  ) {}

  async classify(userInput: string, o: ClassifyOptions): Promise<IntentResult> {
    // L1-a 显式指定
    const at = userInput.match(/^@([a-z0-9-]+)[\s:：]*/i);
    if (at && o.candidates.includes(at[1])) {
      return { agentId: at[1], confidence: 1, via: 'explicit' };
    }
    // L1-b 会话锁定：不做每轮重分类
    if (o.lockedAgentId && o.candidates.includes(o.lockedAgentId)) {
      return { agentId: o.lockedAgentId, confidence: 1, via: 'locked' };
    }
    // L2 规则
    for (const r of RULE_TABLE) {
      if (r.kw.test(userInput) && o.candidates.includes(r.agentId)) {
        return { agentId: r.agentId, confidence: r.confidence, via: 'rule' };
      }
    }
    // L3 LLM（超时/失败 → L4）
    try {
      const raw = await this.withTimeout(
        this.client.chat(
          [
            { role: 'system', content: CLASSIFY_PROMPT },
            { role: 'user', content: userInput.slice(0, 500) },
          ],
          { temperature: 0, maxTokens: 60 },
        ),
        o.timeoutMs ?? this.timeoutMs,
      );
      const parsed = this.parse(raw, o.candidates);
      if (parsed) return parsed;
    } catch { /* 落到 L4 */ }
    // L4 兜底
    return { agentId: 'general', confidence: .3, via: 'fallback' };
  }

  /** 解析容错：无 JSON mode，模型可能吐围栏/废话/非法 agentId。三道防线。 */
  private parse(raw: string, candidates: string[]): IntentResult | null {
    if (!raw) return null;
    const cleaned = raw.replace(/```(?:json)?/g, '').trim();
    const m = cleaned.match(/\{[\s\S]*?\}/);
    if (!m) return null;
    try {
      const j = JSON.parse(m[0]);
      const id = String(j.agentId ?? '').trim();
      if (!candidates.includes(id)) return null;   // 幻觉 agentId → 丢弃
      const c = Number(j.confidence);
      return { agentId: id, confidence: Number.isFinite(c) ? Math.min(Math.max(c, 0), 1) : .6, via: 'llm' };
    } catch { return null; }
  }

  private withTimeout<T>(p: Promise<T>, ms: number): Promise<T> {
    return Promise.race([
      p,
      new Promise<never>((_, rej) => setTimeout(() => rej(new Error('classify timeout')), ms)),
    ]);
  }
}
```

### ⚠️ 三个必须遵守的实现约束

1. **分类器必须用 flash 档。** 当前 `agent.module.ts` 已注册 `TokenHubClient('deepseek-v4-flash')`，直接 `clientRegistry.get('deepseek-v4-flash')` 复用即可，不用新增模型/加 key。用同档模型会让每次对话 token 成本翻倍——这是唯一持续烧钱的点。
2. **`candidates` 必须来自 `agentRegistry.list()` 实时取**，不能写死。否则 admin 后台增删 agent 后路由表与注册表对不上。
3. **解析必须容错。** 没有 JSON mode，模型会吐 ```json 围栏或前后废话，`JSON.parse` 裸调用会抛。

## 5. 会话锁定与切换检测

不做锁定的后果：追问"那第二种呢"被切走、同话题人格不一致、成本翻倍。

```ts
// servers/ai-service/src/agent/intent/intent.service.ts
@Injectable()
export class IntentService {
  constructor(
    @InjectRepository(Conversation) private readonly convRepo: Repository<Conversation>,
    private readonly registry: AgentRegistry,
    private readonly clientRegistry: ClientRegistry,
  ) {}

  async resolve(params: {
    agentId?: string; userInput: string; conversationId?: string; userId: string;
  }): Promise<IntentResult & { switched: boolean; previousAgentId?: string }> {
    const candidates = this.registry.list().map(a => a.id);

    // 1) 显式传入 → 直接走，不分类
    if (params.agentId && params.agentId !== 'auto' && candidates.includes(params.agentId)) {
      await this.lock(params.conversationId, params.agentId, 'explicit');
      return { agentId: params.agentId, confidence: 1, via: 'explicit', switched: false };
    }

    // 2) 读会话锁定
    let locked: string | undefined;
    if (params.conversationId) {
      const conv = await this.convRepo.findOne({ where: { id: params.conversationId } });
      locked = conv?.agentId ?? undefined;
    }

    const classifier = new IntentClassifier(this.clientRegistry.get('deepseek-v4-flash'));
    const r = await classifier.classify(params.userInput, { candidates, lockedAgentId: locked });

    // 3) 切换判定：仅显式 / 高置信规则 / 高置信 LLM 才允许切
    const shouldSwitch = !locked
      || (r.via === 'explicit')
      || (r.via === 'rule' && r.confidence >= .88)
      || (r.via === 'llm'  && r.confidence >= .75);
    const finalAgentId = shouldSwitch ? r.agentId : locked!;
    const switched = !!locked && finalAgentId !== locked;

    if (!candidates.includes(finalAgentId)) {
      return { agentId: locked ?? 'general', confidence: .3, via: 'fallback',
               switched: false, previousAgentId: locked };
    }

    await this.lock(params.conversationId, finalAgentId, r.via);
    return { ...r, agentId: finalAgentId, switched, previousAgentId: locked };
  }

  private async lock(conversationId: string | undefined, agentId: string, via: string) {
    if (!conversationId) return;   // 首轮无会话
    await this.convRepo.update(conversationId, { agentId });
    await this.convRepo.query(
      `UPDATE conversations
          SET intent_history = JSON_ARRAY_APPEND(
                COALESCE(intent_history, JSON_ARRAY()), '$',
                CAST(JSON_OBJECT('agentId', ?, 'via', ?, 'ts', NOW()) AS JSON))
        WHERE id = ?`,
      [agentId, via, conversationId],
    );
  }
}
```

### 切换阈值为什么这么定

| 来源 | 切换阈值 | 理由 |
|---|---|---|
| explicit（`@星座`） | 无条件 | 用户显式指令，必须服从 |
| rule | ≥ 0.88 | 正则误伤率不低（"我想了解一下你"会命中 baike），宁可不切 |
| llm | ≥ 0.75 | LLM 更准，但中途切换代价大，留余量 |
| fallback | 不切 | 没把握时保持现状，比乱切安全 |

## 6. 落库：migration

`conversations` 表目前**没有 agentId 字段**，这是会话锁定的硬前提。

```sql
-- migrations/0010_conversation_intent_routing.sql
-- 背景：主对话接入多 Agent 意图路由，需要把「本会话当前由哪个 agent 负责」持久化，
--       否则每一轮都会重新分类（人格割裂 + 成本翻倍）。
-- 目标库：web_system（ai-service）
-- 适用：NODE_ENV=production（TypeORM synchronize 关闭）的环境必须手动执行。

ALTER TABLE conversations
  ADD COLUMN agent_id VARCHAR(64) NULL COMMENT '当前会话锁定的 agentId（意图路由）' AFTER title,
  ADD COLUMN intent_history JSON NULL COMMENT '意图判定流水：[{agentId,via,ts}]' AFTER agent_id;

ALTER TABLE conversations
  ADD INDEX idx_conversations_agent (agent_id);
```

```ts
// conversation/entities/conversation.entity.ts —— 同步加字段
@Index()
@Column({ type: 'varchar', length: 64, nullable: true, comment: '当前会话锁定的 agentId' })
agentId: string | null;

@Column({ type: 'json', nullable: true, comment: '意图判定流水' })

```

存量会话 `agent_id` 全为 NULL，等价于"未锁定" → 下一轮走正常分类后写入。**不需要刷历史数据。**

## 8. 灰度开关与降级

```bash
INTENT_ROUTING_ENABLED=false        # 默认关。未配置 agent 时不能开
INTENT_MODEL=deepseek-v4-flash      # 分类器模型
INTENT_TIMEOUT_MS=1200              # 分类超时
```

| 故障场景 | 表现 | 降级行为 |
|---|---|---|
| 分类器模型不可用 | `chat()` 抛错 | catch → `general`，对话不中断 |
| 分类超时（>1.2s） | Promise.race reject | → `general`，首字延迟不受影响 |
| 模型吐非法 agentId | 不在 candidates | → `general` |
| `agent_id` 列未加 | SQL 报错 | 开关关闭时完全不触碰该列，安全 |
| registry 里没有 general | candidates 不含兜底 | 启动期自检告警，须先建 general agent |

> **为什么默认关闭**：意图路由强依赖 admin 后台那 6 个 agent 已配置并 publish。agent 没配好时开开关，结果是所有输入都落 `general`——比不开更糟。开关应与"agent 配置完成"绑定上线。

| 输入 | 期望 agent | 期望 via | 说明 / 易错点 |
|---|---|---|---|

## 10. 验收清单

- [ ] `agentId` 省略时，SSE **第一个**事件是 `intent`
- [ ] 同一 conversationId 连续追问，`intent.via` 为 `locked` 且 agentId 不变
- [ ] `agent_log` 里 `agent_id` 是具体 agent，**不是 'auto'**
- [ ] 埋点 `system_prompt` 非空（验证第 7 节 ③ 改对了）
- [ ] 分类器耗时 P95 < 400ms；整体首字延迟增加 < 300ms
- [ ] 关掉 `INTENT_ROUTING_ENABLED`，行为与改动前完全一致
- [ ] admin 后台下线某 agent 后，`candidates` 同步移除，不再路由到它
