三 Tab 骨架落地实现方案

把已验证的 HTML 原型（对话 / 发现 / 我的）落成真实小程序代码 · 2026-09-15

0. 结论先行先给方案、给范围、给工作量，细节后面

推荐路径：低改动「新增 + 改写」，不做大规模搬迁 利用现有 pages/contract/chat 这套已跑通的对话 UI 与 SSE 管线，新增 2 个页面、改写 3 个页面， app.json 换 tabBar 指向。现有 pages/translate/、pages/assess/ 路径一律不动， 只把它们从 tabBar 移到「发现」里作为二级入口 —— 避免大批量 git mv，也避免碰 pages/draw、pages/bianbian 这批历史页面。
优先级事项工作量阻塞
P0app.json：tabBar 换为 对话/发现/我的 + 去掉蓝主题0.1 人日无
P0pages/chat：从 contract/chat 抽通用对话首界面0.5 人日后端 agentId
P0pages/discover：发现页（翻译官 / 合同评估入口）0.3 人日无
P1pages/mine：设置分组收敛（三套设置合一）0.4 人日无
P1pages/welcome：对齐 Hello. + 今日一句 + 开始对话0.3 人日无
P1services/agent-stream.ts：SSE 管线参数化（去掉写死 agentId）0.5 人日后端配合
P2历史页面清理（draw / bianbian / scan / records / contract/*）1～2 人日无

工作量是粗估区间，只用于排优先级，别当排期用。

1. 现状盘点原型目标 vs 仓库真实状态，逐项对齐

原型里的东西仓库里现在是什么状态
tabBar：对话 / 发现 / 我的 app.json 还是「翻译 / 合同评估 / 我的」，selectedColor 蓝色 #1E6FFF 未做
对话 = 默认主界面 无独立对话页。pages/contract/chat/chat 是「合同追问」专用版本，顶部写着「基于本次合同上下文回答」 改造
发现页 不存在，需新建 未做
我的 = 收纳所有设置 pages/mine/index/index.wxml 已存在，但设置是三条平铺：小程序设置 / 翻译设置 / 合同评估设置 —— 只是并列，没收敛 改造
欢迎页 Hello. + 今日一句 + 开始对话 pages/welcome/index/index.wxml 还是旧版：品牌头 + 「欢迎进入科豆 AI」+ 两个入口卡片 + 最近使用列表 未做
橙色主题 app.json 导航栏 #1E6FFF（蓝），tabBar selectedColor 同为蓝；app.wxss 只有 26 行，没有设计变量层 未做
语言翻译官 pages/translate/* 齐全，但 index.ts 里请求是半成品：const res = null; + // TODO: 结果落本地缓存后跳转结果页 断链
合同评估 pages/assess/* + services/contract-api.ts（881 行，含 SSE 流式、会话列表、追问）——这是全项目最完整的真连水管 可用

顺带扫出来的两个暗雷（不在本次范围，但得记一笔）

  • app.json 里 28 个页面，其中 pages/draw/（Canvas 画板，带 5 个 behavior 文件）、pages/bianbian/、pages/scan/、pages/records/、pages/contract/ 是历史堆积，和「科豆 AI 对话助手」的定位无关。这次不动，但列为 P2 —— 它们依赖 utils/CanvasEngine*、utils/Brush.ts，真删的时候得整套 eval。
  • pages/translate/index/index.ts 的翻译请求没接后端。所以「语言翻译官」目前只有 UI，点进去转一圈返回 null 结果。这是发现页最需要先补的一环。

2. 唯一硬阻塞：写死的 contract-risk原型要的是「通用对话」，管线现在是「合同专用」

services/contract-api.ts 顶部三个常量决定了它只能服务于合同：

const AGENT_RUN_URL = '/api/ai-agent/agent/run';
const AGENT_ID      = 'contract-risk';   // ← 写死，通用对话用不了
const CONVERSATIONS_URL = '/api/ai-agent/agent/conversations';

导出的 7 个函数里，sendContractFollowUp / sendContractFollowUpStream 已经是一套完整的通用多轮追问能力（带 SSE 增量、缓冲切行、会话持久化），只是被合同语义绑住了。
换句话说：对话 tab 的后端能力其实已经有了 80%，只是没对外通用化。

选项做法代价结论
A 复制 拷一份成 services/chat-api.ts，只改 AGENT_ID 881 行双人发行人维护；后续改 SSE 逻辑要改两处 否
B 参数化 抽出 services/agent-stream.ts 的工厂 createAgentApi(agentId)，合同版 = createAgentApi('contract-risk')，对话版 = createAgentApi('kedou-chat') 一次性 ~0.5 人日重构；需要后端提供通用 agent 推荐
C 先 mock 对话页先用本地假数据跑通 UI 与交互，后端 ready 后换数据源 无 并行
建议：B + C 同时走 前端按 C 先开工（对话页 UI / tabBar / 发现页不依赖后端），同步和后端口头确认 B 里 kedou-chat 这个 agent 能否排期。两条线不互相阻塞 —— 前端在 agent-stream.ts 就绪前用 mock adapter，接口签名保持一致，后端上线当天换一行 import 即可。

3. 目标结构新增 2 页、改写 3 页，其余路径原地不动

页面路径动作说明
pages/welcome/index/index改写换成 Hello. + 今日一句 + 「开始对话」 → switchTab('pages/chat/index/index')
pages/chat/index/index新建通用对话首界面，UI 抄 contract/chat，去掉合同上下文提示条
pages/discover/index/index新建「语言翻译官」「合同评估」两个入口，navigateTo 跳既有页面
pages/mine/index/index改写三条并列设置 → 收敛为「应用设置」分组

app.json 关键改动

{
  "pages": [
    "pages/welcome/index/index",   // 启动页（非 tab），保持首位
    "pages/chat/index/index",      // ← 新增
    "pages/discover/index/index",  // ← 新增
    ...其余保持不变
  ],
  "window": {
    "navigationBarBackgroundColor": "#FFFFFF",  // ← 从 #1E6FFF 改白
    "navigationBarTextStyle": "black",          // ← 从 white 改黑
    "navigationBarTitleText": "科豆 AI"
  },
  "tabBar": {
    "color": "#9AA1AD",
    "selectedColor": "#C2410C",              // ← 蓝 #1E6FFF → brand-txt
    "backgroundColor": "#FFFFFF",
    "list": [
      { "pagePath": "pages/chat/index/index",     "text": "对话" },
      { "pagePath": "pages/discover/index/index", "text": "发现" },
      { "pagePath": "pages/mine/index/index",    "text": "我的" }
    ]
  }
}
selectedColor 用 #C2410C 而不是 #F97316 同上轮原型里踩的同一个坑：橙色 #F97316 在白底对比度只有 2.9:1，tabBar 选中文字会糊； 深色档 #C2410C 是 5.4:1，刚好过 AA。tabBar 这种地方不宜用纯品牌橙。

4. 实施步骤按依赖顺序，前四步和后端口径无关

  1. 设计变量层（0.2 人日）— 把原型那套 --brand / --brand-txt / --accent / --page-bg 落到 app.wxss（现在只有 26 行）。所有新页面统一从这里取色，杜绝硬编码色值到处飞。
  2. app.json 换骨架（0.1 人日）— tabBar 三个 tab + navigationBar 去蓝改白。此时暂时指向尚未存在的 pages/chat，编译会报错，所以紧接着做第 3 步。
  3. 新建 pages/chat（0.5 人日）— 从 pages/contract/chat/ 复制一份改：
    • 删掉 chat-head 那条「基于本次合同上下文回答」
    • 首屏注入「今日一句」作为 AI 首条消息（与欢迎页同文案，形成连续感）
    • SSE 数据源先接 mock adapter，接口签名按 agent-stream.ts 预留
  4. 新建 pages/discover（0.3 人日）— 两个入口卡片，navigateTo 到 pages/translate/index/index 与 pages/assess/index/index。预留后续插入新技能的槽位。
  5. 改写 pages/welcome（0.3 人日）— 对齐 Hello. + 今日一句 + 「开始对话」。今日一句抽到 utils/daily.ts 统一维护，欢迎页与对话首条共用同一份，避免两处文案漂移。
  6. 改写 pages/mine（0.4 人日）— 三条并列设置改成一个「应用设置」分组进入同等层级，翻译/评估各自的设置作为二级页。
  7. services/agent-stream.ts 参数化（0.5 人日，依赖后端）— 抽工厂 + 通用 agentId，contract-api.ts 改为工厂调用，现有合同评估链路行为不变。
  8. 冒烟 + 提交（0.2 人日）— tsc --noEmit 通过 + 开发者工具可编译 + 三 tab 可切 + 欢迎页跳对话。顺带把这条分支 117 个未提交文件清了。

5. 验收清单逐条打勾，别只看「能编译」

功能
  • 启动进 welcome（非 tab 页，底部无 tabBar）
  • 点「开始对话」→ switchTab 进对话，且不可后退回欢迎页
  • 对话 tab 为默认选中项
  • 发现页两个入口都能 navigateTo 抵达
  • 「我的」里三套设置全部可达，无死链
视觉 / 规范
  • 导航栏已去蓝；tabBar 选中色为 #C2410C
  • 无硬编码 #F97316 / #1E6FFF 残留在新增页面
  • 胶囊按钮不被导航栏遮挡（getMenuButtonBoundingClientRect）
  • 底部文案：AI 生成声明 + 备案号，各页一致
  • tsc --noEmit 零错误
