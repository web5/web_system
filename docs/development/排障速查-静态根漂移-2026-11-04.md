### 场景一：页面 HTTP 200，却只有一行 `index.html not found for shell`

**判据**（按顺序执行，1 分钟内定位）：

```bash
# 1) 确认是基座兜底文案，不是前端模块报错
curl --noproxy '*' -sS https://<host>/portal/chat | tail -c 120
# → <body>index.html not found for shell</body> = IndexHtmlService.readHtml() 的 catch 吞了读文件失败

# 2) 判断请求落在哪一层
curl --noproxy '*' -sS -o /dev/null -w '%{http_code}\n' https://<host>/shell/index.html
# 404 且 body 是 {"statusCode":404,"message":"Cannot GET ..."} = Nest ServeStatic 没找到文件，
# 不是 nginx alias 丢文件（nginx 会返 HTML 404）

# 3) 关键：打印进程「实际」静态根，而不是看 .env 里写了什么
cd /data/web_system/servers/gateway && node -e "console.log(require('./dist/static/public-root.js').PUBLIC_ROOT)"
PID=$(pm2 pid gateway); tr '\0' '\n' < /proc/$PID/environ | grep STATIC_PUBLIC_ROOT
# → 打印出 <home>/web_system_runtimes/.../public 或该目录不存在 = 静态根漂移

# 4) 产物是否完好（dev / prod 两个真源不同，别查错目录）
ls -l /data/web_system/servers/gateway/public/shell/index.html              # dev
ls -l /data/web_system_static/public/shell/index.html                       # prod
```

**易误判点**：

| 误判 | 真相 |
|---|---|
| 200 就是页面正常 | 兜底文案本身就是 HTTP 200，只看状态码必漏 |
| 文件都在，所以不是路径问题 | 产物完好但 `PUBLIC_ROOT` 指错，进程去的是另一个目录；先查进程实际取值再决定要不要重投产物 |
| 改 `servers/gateway/.env` 里的 `STATIC_PUBLIC_ROOT` 就行 | 该常量在 **import 期**求值，早于 `@nestjs/config` 加载 .env，写了不生效；必须注入进程 env（根 `.env.production` 或 `ecosystem.config.js` 的 gateway `env` 块） |
| dist 软链不影响路径推导 | Node 的 `__dirname` 走 realpath，dist 指向 runtime 版本目录时，`join(__dirname,'..','..','public')` 会漂到那个版本目录 |
| 回滚前端版本能修 | 与模块版本无关，回滚无效 |

**适用范围**：web_system gateway 微前端基座（dev / prod；`dev.kedouai.com`、`kedouai.com`）。`STATIC_PUBLIC_ROOT_STRICT=0` 可把启动自检降级为仅告警。

### 场景二：pm2 干净重启报 `Script not found: .../servers/gateway/servers/gateway/dist/main.js`

**判据**：

```bash
grep -nE "name: 'gateway'|cwd:|script:" /data/web_system/ecosystem.config.js | head -8
# gateway 同时有 cwd=<...>/servers/gateway 与相对 script='./servers/gateway/dist/main.js' 即中招
```

**易误判点**：以为 dist 被删了；实际是 `cwd` 与相对 `script` 叠加，pm2 把路径拼了两遍。历史进程用绝对路径启动，所以这个配置缺陷只在**干净重启**时暴露。

**处理**：`script` 改为 `${WEB_SYSTEM_DIR}/servers/gateway/dist/main.js` 绝对路径，保留 `cwd`。

**适用范围**：dev（master 版 ecosystem 带 `cwd`）；prod 发布目录停在旧版 ecosystem（无 `cwd`），但统一用绝对路径同样安全。

### 场景三：判断「临时止血」是否真的被根治取代

止血常用手段是在 runtime 版本目录补 `public` 软链。**验证 R1（env 注入）独立生效的正确做法不是重启，而是运行中删软链**：

```bash
unlink <runtime 版本目录>/public
curl -sS http://127.0.0.1:6000/portal/chat | grep -c 'not found for shell'   # 必须 0
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:6000/shell/index.html  # 必须 200
```

`PUBLIC_ROOT` 在 import 期求值一次，进程带显式 env 后与软链无关；若删了软链立刻白屏，说明 env 没注入，根治没做成。

**易误判点**：只看「重启后页面正常」就宣布修好 —— 软链还在时会掩盖 env 未注入的事实。

**适用范围**：全环境。
