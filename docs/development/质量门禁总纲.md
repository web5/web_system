> **v2.0 · 2026-10-23** · 定位：**一页入口**。只回答「有哪些门、在哪拦、什么级别、去哪查」。
> **维护纪律**：增删任何门禁，必须同 PR 更新 [gates/01-日常使用.md](gates/01-日常使用.md) 的环节表与 [gates/03-治理与索引.md](gates/03-治理与索引.md) 的编号索引；否则视为门禁变更未完成。

## 门禁在哪拦

```
写代码 ──▶ L1 编辑器层（IDE hook，只拦 AI）
            │
            ▼
         git commit ──▶ L2 本地 git 层（pre-commit 红线扫描，可 --no-verify）
            │
            ▼
         PR ──▶ L3 CI 层（quality-gate.yml 4 个 job）  ← 唯一硬门
            │
            ▼
         发布 ──▶ L4 发布层（release.yml + release_plan 不变量）
```

L1 是快反馈不是安全边界；L2 可被 `--no-verify` 绕过；**L3 的强制力来自分支保护配置，不是 workflow 文件本身**——「我加了 CI 检查」不等于「门禁生效」，必须验证一次「故意让它红，能不能拦住合并」。

| 类别 | 数量 | 含义 | 编号 |

| **体检项**（只提示） | **13** | PR 上恒绿，仅提醒 | R3弱 R5 R8 R9 R9b R10 R13 R14 R15 R16 R17 R18 · L6 |
