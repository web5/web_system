## 一之二、S2 到底解决了什么（用数说话）

| 指标 | bash | gate.ts |
|---|---|---|
| 135 commit 范围耗时 | **66.4s** | **2.2s**（30×） |
| 48 commit 范围耗时 | 22.1s | 2.0s（11×） |
| git 子进程次数（135 commit） | 门数 × commit × 2~6 ≈ **2000+** | **21** |
| 8 道 commit 凭证门的实现份数 | **8 份**（同一个骨架抄 8 遍） | **1 份**（差异全在 YAML） |
| 加一道凭证门要改 | 6 个代码文件 + 用例 + 7 处文档/模板 | **1 条 YAML** + 用例（文档自动生成） |

两件事都源自同一个结构问题：**bash 里「每道门各自遍历一遍 commit」**。
8 道门 × N 个 commit × 2~6 次子进程 = 成本随范围线性叠加，而且重复劳动 8 遍。
`gate.ts` 用一条 `git log` 拿全部 commit 的元数据与改动文件，门与门共用这份快照。


> 性能不是重构的**理由**（重写前实测过：正常 PR 范围 bash 也就几秒，能忍），
> 它是重构的**附带结果**。真正的理由是「13 处同步」与「8 份重复实现」——
> 前者让加规则变贵，后者让改规则容易漏。性能只是让 S3 切主更容易下决心。

## 一之三、影子比对第一次跑就抓到一个真实的 bug

`gate.ts` 第一版把 `credential.checks` 当字符串列表读，而 YAML 里它是「键值对列表」
（`- path_exists_in_commit_tree: true`）。结果 `checks` 全是空数组 →
**所有「报告路径是否存在」的校验被静默跳过**。

表现：`commit-r17-fake-path`（Test 指向不存在的路径）在新引擎下**通过了**。
不报错、不崩溃、退出码 0 —— 门禁只是变哑了。

这就是为什么必须有影子比对：黄金用例只跑 bash，对「新引擎少判一门」完全无感。
**一次全绿的影子比对和没有影子比对是等价的，所以它必须真的会红。**

### 这一轮真正抓到的东西

**① R2.secret-file 在 `gate.ts` 下完全不报（P0 真回归，切主后一直存在）**

bash 用 `[[ "$file" =~ (^|/)\.env($|\.) ]]`（**正则**），YAML 写成 `match_path` 后引擎按
**glob** 解释 → `(^|/)` 变成字面量 → `.env` 与证书文件一条都不报。

为什么 12 天影子期没抓到：R2.secret-file 当时**零用例**，在 `uncovered` 里躺着。
两个引擎在没人测过的分支上一样地错 —— 影子比对逐字节一致，绿得很。

修法不是改 bash，是补三件：把判据改成 `match_re`、引擎补 `triggerPathHit()` 认两种写法、
给 R2 补 3 个用例（`.env` / `server.pem` / `.env.example` 阴性）。`conventions.path_match`
现在把「哪个字段是 glob、哪个是正则」写成明文，防止下一个人再踩。

**② 观察日志被归档，采集静默失效 7 天**

`collect-gate-observations.sh` 指向 `docs/development/gate-observation-log.md`，
而该文件在 2026-11-04 的「活跃区零废弃副本」治理里被移进 `archive/`。
脚本的行为是「文件不存在 → 打印跳过 → exit 0」—— 7 天里每天的采集都成功退出、什么都没写。

修法：文件恢复到活跃区；脚本改成**文件缺失即 exit 1**。静默降级比报错更贵，
因为报错会被看见。

**③ 变异测试第一版永远「全捕获」（最危险的假绿）**

`gate.ts` 的 stdout 以换行结尾，`readExpected()` 解析期望文件时把尾部换行去掉了 →
两边**永远不相等** → 每个变异都被判成「捕获」。它先报 44/44 全绿，补完变异器后报 78/78 全绿。

发现手段：把 R1 的 evidence 故意换成无关场景（`line-r3-todo`），它**仍然报「5 捕获」**——
判据改坏、用例无关、还能捕获，只可能是比较本身失效了。

修法：比较前统一 `replace(/\n+$/, "")`。真相是 **42 捕获 / 38 未捕获**。

## 一之五、S5 删掉了什么，代价是什么（照实写）

**删掉 5 个文件、约 3800 行**：`scan-rules.sh`（64K bash 引擎）、`gate-shared.sh`（14K bash 判据库）、
`check-commit-msg.sh`（8K commit-msg 独立实现）、`mutation-test.sh`（变异 bash 源码）、
`cases/shadow.sh`（双引擎对拍）。

| 变化 | 改前 | 改后 |
|---|---|---|
| commit-msg 钩子 | `.githooks/commit-msg` → `bash check-commit-msg.sh`（自己重写 is_ui / exempt_parse / exempt_quality） | → `node gate.ts commit-msg`（判据仍从 YAML 读，只是换了参照物） |
| 「commit 前判哪几道门」 | 写死在 bash 里 | 声明在 `gates.yaml` 的 `local_commit_msg.gates`；gate.ts 对未接线的门**报错 exit 2** |
| 判据变异 | 8 条手写（mutation-yaml.sh）+ 16 条变异 bash 源码（mutation-test.sh） | 80 条生成式（mutation-gen.ts） |
| 双引擎对拍 | 34 场景逐字节 | **没了** |
| gates-lint 的「漂移」类 | 9 项 YAML↔bash 逐个比对 | 换成 4 项 YAML 自洽（scope 闭合 / 豁免对齐 / 档位接线 / commit-msg 清单） |

### 🔴 代价必须说清楚：丢掉的是一层**独立实现**的对照

`bash` 不只是「旧代码」，它是 `gate.ts` 的**独立实现**，所以「两边输出逐字节一致」能发现
「gate.ts 被改坏」「YAML 改了但代码没读」。删掉它之后：

- `gates-lint` 的静态检查只能证明 **YAML 自己说得通**，证明不了「代码真的读了它」；
- 只剩两层行为保证：**黄金用例**（34 场景逐字节 vs expected）与**生成式变异**
  （改坏判据必须红，80 个变异覆盖 14 类字段）。

这不是等价替换。要补回同等强度，只有两条路：① 引入第三个独立实现（成本极高，且会再长出一份手抄）；
② 把变异器覆盖的字段从 14 类补到 40 类（现状 26 类没变异器，见 `mutation-gen.ts --list` 末尾）。
**选的是 ②（2026-11-11 拍板）**：接受这层对拍损失，不再引入第三实现；
补变异器的工作归入技术债（台账 #8722 / #8723），与黄金用例一起在下轮清理，不阻断发版。

### 一处真实的行为变化：R10 在本地不再阻断

旧 `check-commit-msg.sh` 对「缺 Proto 凭证」硬编码 `exit 1`，而 `gates.yaml` 里 R10 是
**warning** —— 实现比自己的声明更严。删掉 bash 后本地与 CI 口径统一为 warning。

实测影响面很小（缺 Proto 的 UI commit 通常也缺 Design，被 error 级的 R11 拦住），
但**确实变松了**。

**拍板结论（2026-11-11）：维持 `warning`，不升 error。** 理由是 R11 已构成实际拦截，
把 R10 也升成 error 只会让「同一件事报两次红」，不增加拦截力。何时需要重新考虑：
出现「`Design: pass` 齐全但 `Proto` 缺失」被放行的实际案例。要改回去时，
`gates.yaml` 里 `R10.level` 与 `test-gate-hardening.sh` 的 L2 断言必须一起改
（现断言是「点名 `[R10]`」，不是「exit 非 0」）。

## 二、改判据的正确顺序（S3 切主后）

```bash
# 1) 改 gates.yaml —— 判据先成立（它现在就是唯一真相源）
# 2) 改用例与期望 —— 定义「改成什么算对」
bash scripts/redline/cases/run.sh --update   # ⚠ 生成后必须人工 review 每份 .txt
# 3) 重新生成文档 —— 门表 / 分组清单 / PR 模板
node scripts/redline/gen-docs.ts
# 4) 四件一起验
node scripts/redline/gates-lint.ts           # 结构 / 用例 / 接线 / 生成物是否过期
bash scripts/redline/cases/run.sh            # 行为逐字节
node scripts/redline/mutation-gen.ts         # 断言有没有真的管着判据
```

**顺序为什么还是不能反**：S1 阶段 YAML 单向跟随 bash（YAML 改了 bash 没改 = 声明撒谎），
切主后反过来 —— 改判据只改 YAML，bash 不再跟随。两种阶段的共同点不是「谁先」，
而是**同一时刻只能有一个权威**；一旦允许两边都能先动，漂移时没人知道该信谁。

`--update` 那一步必须人工 review：它是唯一能「用例跟着错的一起更新」的入口，
变异测试能抓到「判据被改坏」，抓不到「判据和期望一起被改错」。

## 五、豁免机制（横跨 9 道门）

| 维度 | 规则 |
|---|---|
| trailer | `Micro-exempt:`，行首锚定、大小写敏感、只取第一条 |
| 新格式 | `Micro-exempt: R11,R17: <理由>` —— **只豁免列出的门** |

## 七、自检能拦住什么（四种变异实证）

`gates-lint.ts` 不是「检查一下文件格式」的装饰品。2026-10-30 实测，注入四种真实会发生的漂移，全部被拦：

| 注入的漂移 | 拦住的输出 |
|---|---|
| 从 YAML 的 `contract_file` 删一条 glob（模拟改了 bash 没同步） | `[漂移] bash 有而 YAML 缺: servers/*/src/*/*.controller.ts` |
| 把 `evidence` 指向不存在的用例 | `[用例] R17: evidence「commit-r17-typo-path」在 scenarios.tsv 里不存在` |
| 删掉某道门的 `uncovered` 记录（留下没人验证的空门） | `[用例] R12: 既没有黄金用例，也不在 uncovered 清单里` |
| 让行级门声称可豁免 | `[接线] R1: 声明可豁免，但不在 exemption.eligible_gates` |

S4 又补了第五类检查（**生成物会不会过期**），同样注入两种漂移验证过：

| 注入的漂移 | 拦住的输出 |
|---|---|
| 改了 `gates.yaml` 的门表但没重新生成文档 | `[生成物] 过期区块：docs/development/gates/03-治理与索引.md  [gate-table]` |
| 把 `observations` 的列序调换（采集口径与声明不同序） | `日志表头与 observations 声明不一致 —— 实得 [...]，应为 [...]` |

它做的五类检查：

1. **结构** —— YAML 严格子集解析（flow mapping / 锚点 / plain scalar 含 `: ` 直接报错，不猜）+ 必填字段 + 枚举 + 引用完整性
2. **自洽**（S5 前叫「漂移」）—— scope 双向引用闭合（没有死配置、没有悬空引用）、`eligible_gates` 与门上 `exempt: true` 逐一对齐。**不再有 bash 可对拍**，这是能力降级，见 §一之五
3. **用例** —— 每道门要么有黄金用例，要么进 `uncovered` 并写原因；反向也查：每个场景都要有人认领（孤儿用例也是漏）
4. **接线** —— 声明可豁免的门，代码里真的接了豁免
5. **生成物** —— 三处 `gen:…` 区块与 `observations` 列序必须与 YAML 一致（调 `gen-docs.ts --check`）

```bash
node scripts/redline/gates-lint.ts     # 0=通过 1=有失败
```

## 九、别把它当第二份文档

`gates.yaml` 里写的每条 `message` / `hint` 都是**输出文案的原文**，不是概述。
理由是：S2 影子比对要求新引擎输出与老 bash **逐字节一致**，文案必须可复现；
写成「提示用户补充凭证」这种概述，重写时就得靠猜。

同理，`gates.yaml` 里刻意保留了踩坑注释（为什么要排除 `packages/ui/*`、为什么门号后必须紧跟冒号）。
这些是真实付过代价的知识，删掉它，下一个人会重踩一遍。
