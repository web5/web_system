## 1. 路由 / 接口层

### 场景：判断后端路由是否真的发布到位

- **判据**
  ```bash
  curl -s -o /dev/null -w '%{http_code}\n' --max-time 8 http://127.0.0.1:<port>/api/<path>
  ```
  | 码 | 含义 |
  |---|---|
  | **401** | 路由命中、被 auth guard 拦 → ✅ **路由存在（发布到位）** |
  | **404** | 路由不存在 → 后端/网关未发或路径错 |
  | **400** | 命中且参数校验生效（如 `parseId` 兜底） → ✅ 防御生效 |
  | **500** | 后端异常 → 见 §4 |
- **易误判**：拿 200 当「发布成功」。未登录时 guard 先返 401，**401 才是可靠信号**；
  另外 404 也可能是**正则约束生效**（如 `:id(\d+)` 让 `sources/abc` 直接不匹配），别一律当成「没发」。
- **适用**：全环境（本机需能连到目标机器端口，通常 ssh 到机器上用 127.0.0.1）

### 场景：确认接口是不是被「路由抢匹配」了

- **判据**
  ```bash
  grep -n "controllers:" <module>.module.ts      # 注册顺序 = 匹配优先级
  grep -rn "@Controller(" <module 目录>           # 找同前缀 controller
  git show <线上版本>:<controller 文件>            # 确认线上是否已是修复版
  ```
- **易误判**：把「静态子路径返回 500」当成该接口自己有 bug —— 实际可能是同前缀另一个 controller 的
  `:param` 路由先吃掉，参数变成 `NaN` 才炸。
- **适用**：NestJS 全项目

## 2. 产物 / 部署层

### 场景：前端产物是否真到位

- **判据**
  ```bash
  # 1) 看指针（软链指向的 commit 才是真凭据）
  readlink /data/web_system/servers/<svc>/dist
  # 2) 看产物是否 HTTP 可达
  curl -o /dev/null -w '%{http_code}\n' https://<域名>/static/modules/admin/<env>/<commit>/index.js
  ```
- **易误判**：相信 `versions` 读出来的**版本表**——它对前端滞后（曾显示 `005256fd` 而指针已是 `3a22972c`）。
- **适用**：prod 静态根实测 `/data/web_system_static/public/static/modules/<module>/<env>/<commit>/`
  （**不是** `/data/web_system/public/...`，那是后端产物）；dev 静态根不同，用
  `find /data /home /root -maxdepth 9 -type d -name '<commit>'` 定位。

### 场景：确认线上到底跑的是哪个版本

- **判据**：日志/堆栈里的 `node_modules` 路径带 commit 段，例如
  `.../web_system_runtimes/content-hub/content-hub-dev/<commit>/node_modules/...`
- **易误判**：看到「报错」就怀疑**没发上去**。跑的是最新版本却仍报错 = 代码 bug，不是发布问题。
- **适用**：全环境（能区分「发布问题」还是「代码问题」的第一刀）

### 场景：微前端改了 UI 但用户看不到

- **判据**
  ```bash
  grep -c 'CloudServerOutlined' <产物目录>/BasicLayout.*.js   # 产物里有没有新代码
  ```
  有 → 浏览器缓存，让用户 **Ctrl+Shift+R / Cmd+Shift+R** 强刷。
- **易误判**：产物里没有才去查构建；产物里有就是缓存，别重新发版。
- **适用**：admin 微前端

## 3. 数据层

### 场景：功能空转（列表为空 / 无内容）

- **判据**：查业务表行数与 seed 状态
  ```sql
  SELECT COUNT(*) FROM content_sources;   -- 期望：dev/prod 都是 8 源 2 管线
  ```
- **易误判**：当成「接口坏了」。表驱动功能没 seed 数据就是空转，接口是好的。
- **适用**：全环境；**流水线不同步 DDL，也不跑业务 seed**，必须显式执行

### 场景：菜单不显示（权限门控）

- **判据**
  ```bash
  git show <线上版本>:<常量文件路径> | grep '<权限前缀>:'   # 空 = 运行版本无此常量 → 必须发版
  ```
  发版后核对角色权限总数是否 +N。
- **易误判**：「重启服务让权限生效」——只在常量**已存在于运行版本**时成立；
  常量首次引入时重启只是重跑旧 seed。
- **适用**：全环境；必须在**前端发布之前**完成，否则菜单被门控过滤

### 场景：不可逆数据清理（如清理历史脏记录）

- **判据**：先全表备份再删，删完复核行数
  ```bash
  mysqldump -h"$DB_HOST" -u"$DB_USERNAME" -p"$DB_PASSWORD" "$DB_DATABASE" <table> > backup.sql
  # 删除用事务包裹，删完立即 SELECT COUNT(*) 复核
  ```
- **易误判**：以为「删了就完了」——业务数据**不可回滚**，备份是唯一恢复路径；
  备份要同时留**服务器 + 本地**两份。
- **适用**：全环境（生产环境删前必须列清单 + 备份）

## 4. 日志 / 进程层

### 场景：后端 500 怎么取日志

- **判据**
  ```bash
  ssh <机器> "pm2 logs <svc> --lines 600 --nostream > /tmp/<svc>-log.txt"
  scp <机器>:/tmp/<svc>-log.txt /tmp/<svc>-log.txt   # 拉回本地精读
  ```
- **易误判**：驱动层错误（如 `QueryFailedError: Unknown column 'NaN'`）**堆栈不含业务行号**，
  只能从代码反推 → 优先查「把变量送进列名位置」的地方（未校验的路径参数、动态字段拼接）。
- **适用**：全环境

### 场景：确认服务还活着

- **判据**
  ```bash
  pm2 jlist | grep -o '"status":"online"' | wc -l
  curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:6000/health   # dev gateway 是 6000，不是 3000
  ```
- **易误判**：记错端口 → 返回 000 就以为服务挂了（实际是端口不对 / 无该路由）。
- **适用**：dev gateway=6000、content-hub=6007；端口表见 skill `references/services.md`

## 5. 工具 / 环境层（只收稳定复现的）

### 场景：发布流水线在「上传阶段」失败

- **判据**：先 `df -h`，再查构建日志。空间不足的表现是
  `scp: write remote "/tmp/*.tgz": Failure`（构建其实成功了）。
- **易误判**：去查构建/脚本错误——**磁盘满才是真因**。
- **适用**：dev 机（根分区 50G）。清理模式：
  ```bash
  # /tmp 残留（先 list 再删，别用泛化通配）
  find /tmp -maxdepth 1 \( -name 'hook-dist-*' -o -name '*-dist-*' -o -name '*-clean-*' \
    -o -name '*-stale-*' -o -name '*-dirty-*' -o -name 'admin-*.tgz' \
    -o -name 'console-backend-*.tgz' \) -print0 | xargs -0 rm -rf
  # runtimes 旧版本：保留「dist 软链目标 + 最近 1 个回滚候选」，其余删
  readlink /data/web_system/servers/<svc>/dist     # 删前必查，绝不删软链目标
  ```
- **观测记录**：2026-10-23 dev 机 /tmp 清出 1.1G、runtimes 清出 1.3G，可用 1.7G → 3.7G

### 场景：ssh 偶发 `Connection closed by <ip> port 22`

- **判据**：隔几秒重试；把长命令拆成多次短连接（长命令 + `pm2 list` 更容易断）。
- **易误判**：以为服务/机器挂了 → 其实是连接层抖动，命令根本没执行。
- **适用**：dev 机（间歇性）
