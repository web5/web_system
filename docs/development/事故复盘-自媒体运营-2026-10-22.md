## 3. 根因（逐轮，附证据）

### 第一轮：非代码交付物漏发

| 症状 | 根因 | 证据 |
|---|---|---|
| dev 点进去 500 | **gateway 停在 `005256fd`**，不含 `/api/content-admin/*` 路由，请求到不了 content-hub | 该 commit 的 gateway 版本早于路由新增 |
| prod 无菜单 | **admin 前端产物仍在旧 commit `6e7b2690`** | 静态根下无 `3a22972c` index.js |
| prod 采集源空转 | **初始化 seed 没跑**，`content_sources` = 0 行 | 表驱动采集，无源即空转 |
| 无用例文档 | 工作流跳过测试设计阶段，红线不要求 | PR #378 描述无 `Test:` |

**共同病根**：方案只覆盖「代码维度」，漏掉全部**非代码交付物**（初始化数据、测试用例）与**分环境发布完整性**。

### 第二轮：设计期缺陷 + 跨服务常量依赖

| 症状 | 真根因 | 证据 |
|---|---|---|
| dev 采集源仍 500 | **跨 controller 路由抢匹配**：两 controller 前缀同为 `api/content`，`ContentController` 先注册，`@Get('sources/:id')` 吃掉 `sources/last-collect` → `Number('last-collect') = NaN` → TypeORM 把 NaN 当**列名** → `Unknown column 'NaN'` | 日志实证 500；改名为 `collect/last` 后恢复 |
| prod 仍无菜单 | **权限常量在 user-service**，prod 跑 `3f44edb3` 不含 `content:*` → **重启无效，必须发版** | 发版后 admin 权限 26 → 27，菜单出现 |

**共同病根**：发布清单能兜住「漏发」，兜不住**设计期缺陷**（路由冲突）与**跨服务代码依赖**（常量在别的服务）。

### 第三轮：代码 bug + 并发放大

| 症状 | 真根因 | 证据 |
|---|---|---|
| 采集明细 500 | `content.service.ts` 的 `itemStats()` 原生 SQL 笔误：`IN (:...qs`（缺右括号 + 多写 `...`）→ 未闭合 SQL → MySQL 语法错 | dev content-hub 日志两条 ERROR，**运行版本 `1e946126`（发布无误）** |
| 整页崩 | 页面 `Promise.all([listItems(), itemStats()])`，**装饰性统计接口 500 拖垮整页** | 列表数据其实一直是好的 |
| 图标看不到 | 产物 chunk 内已含图标代码（`grep -c 'CloudServerOutlined' BasicLayout.*.js` 有值）→ **浏览器缓存** | 强刷后可见 |

**共同病根**：原生 SQL 无形状测试 + 装饰性接口进主链路，两者叠加让局部故障放大成整页故障并掩盖真因。

| 三 | 前端健壮性 | 装饰性接口进 `Promise.all` 主链路 |

## 8. 二次 / 三次翻车对照（关键教训）

| 对照 | 结论 |
|---|---|
| 第一轮 → 第二轮 | 第一轮把「prod 无菜单」**单一归因于前端产物**，掩盖了权限这一层；第二轮才发现真根因是权限常量未发版 |
| 第一轮 → 第三轮 | 三轮根因**全不同**（漏发 → 设计缺陷 → 代码 bug），说明「补齐上一轮漏洞」不等于「不会再翻车」 |
| 共同放大器 | 两次都是**辅助接口 500 拖垮整页**，把局部故障伪装成「整个页面坏了」，误导归因方向 |

> **最该记住的一条**：页面报「服务器错误」时，**先分清是主链路还是装饰性接口**再归因；
> 否则会把路由冲突 / SQL 笔误误判成「数据源有问题」。
