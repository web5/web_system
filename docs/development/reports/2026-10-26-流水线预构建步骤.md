## 1. 背景与目标

### 1.1 要解决的问题

| # | 问题 | 现象 | 根因 |
|---|---|---|---|
| P1 | 后端发布产物吃到旧 `agent-core` 代码 | SSE final 帧缺 `runId`（T3 修复后仍复现）；改了 packages 不生效 | 后端打包 `executeBackendRuntime` 的 `copyWorkspaceOutputs` 直接 `cpSync` `packages/*/dist`，**不判陈旧、不重建**；`pull.afterSync` 预构建清单 `PREBUILD_SHARED_PACKAGES` 只有 `@web-system/shared`/`types`，漏 `@kedouai/agent-core` |
| P2 | 「改了 packages 不生效」排障成本高 | 现象是业务字段缺失，根因在构建产物 | 预构建散落在 `pull.afterSync` 硬编码清单，无独立可见步骤，无通用脚本 |

### 1.2 验收目标

| # | 目标 | 判据 |
|---|---|---|
| G1 | 流水线有可见 `prebuild` 步骤 | 发布日志出现 `prebuild` 阶段；位于 `pull` 之后 `build` 之前 |
| G2 | workspace 包 dist 陈旧时自动重建 | `packages/*` 的 src 比 dist 新 → 该包被 `npm run build`；全新时跳过（isStale 判定） |
| G3 | 后端产物不再吃旧 dist | 发新 commit 改 `packages/agent-core` 字段后，产物 dist 含新字段，**无需手动 rsync** |

### 1.3 Non-goals（明确不做）

| 不做 | 原因 |
|---|---|
| 改 `executeBackendRuntime` 打包逻辑 | 本期只保证打包前 dist 是新的；打包侧加固（isStale 防线）属下期 |
| UI/前端模块打包流程改动 | `build-module.mjs` 已有 `ensureWorkspaceDeps`，本步骤与之同源逻辑、不重复改 |
| 移除 `pull.afterSync` 的预构建 | 留作 nodes 模式 / 旧模板的兜底；脚本幂等，二次执行 isStale 即跳过 |

## 2. 方案设计九子项

### 2.1 架构与数据流

```
pull（拉码 + 依赖同步）
  └→ afterSync：依赖安装 + 预构建兜底（调同一脚本，幂等）
        ↓
prebuild（新增步骤，可见）  ← 本方案
  └→ scripts/prebuild-workspace-deps.mjs
       扫 packages/* → isStale(src>dist) → npm run build（带目录锁）
        ↓
build（模块构建：前端 vite / 后端 nest）
        ↓
upload / apply（后端 copyWorkspaceOutputs 拷 dist —— 此时 dist 已是新的）
```

**为什么放 pull 之后 build 之前**：build（模块自己的 tsc/vite）与打包（`copyWorkspaceOutputs`）都要消费 workspace 包的 dist，必须在两者之前完成重建。

### 2.2 页面清单（含菜单）

无（纯流水线内部步骤，无 UI）。

### 2.3 接口清单

无新增 HTTP 接口。

### 2.4 数据结构

无 DDL。`PIPELINE_STAGES` 常量数组插入 `'prebuild'`（代码常量，随 deploy-console 发布生效）。

### 2.5 配置清单

| 配置项 | 类型 | 改动 | 环境差异 | 发布关联 |
|---|---|---|---|---|
| `PIPELINE_STAGES` | 代码常量 | 插入 `'prebuild'` | 无 | 随 deploy-console |
| `STEP_SEMANTIC_ORDER` | 代码常量 | 增 `pull<prebuild`、`prebuild<build` | 无 | 同上 |
| `SKIP_WORKSPACE_PREBUILD` | 环境变量 | 沿用（脚本识别，=1 跳过） | 调试用 | — |
| `WORKSPACE_PREBUILD_FORCE` | 环境变量 | 沿用（=1 强制重建） | 调试用 | — |

### 2.6 依赖系统或接口

| 依赖对象 | 类型 | 强/弱 | 缺失后果 | 发布关联 |
|---|---|---|---|---|
| `packages/*` 的 `build` 脚本 | 内部 | 强 | 预构建失败（步骤 fail） | 随代码 |
| `npm`/`npx`、Node 运行时 | 中间件 | 强 | 脚本无法执行 | 部署环境已有 |

### 2.7 初始化数据 / 种子数据

无。

### 2.8 权限模型

无新增权限项（流水线步骤由既有 `deploy:pipeline:*` 权限覆盖）。

### 2.9 兼容与回退

| 场景 | 行为 |
|---|---|
| 存量模板 `steps` 显式数组（无 `prebuild`） | 不强制改模板；`pull.afterSync` 兜底调同一脚本（幂等） |
| v5 nodes 模式（git 节点脚本驱动） | `afterRun → afterSync` 兜底调脚本 |
| `SKIP_WORKSPACE_PREBUILD=1` | 脚本与步骤均跳过（兼容历史调试开关） |
| 回退 | revert 本 PR 即可；无 DDL、无数据迁移 |
