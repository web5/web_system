### 1. 背景与目标

**问题一（越权读）**：`GET https://kedouai.com/api/mcp/modules` 与 `https://dev.kedouai.com/api/mcp/modules` 均返回 **200**，
无任何凭证即可拿到全部 MCP 模块定义（含 `base_url`、`auth_type`、`auth_config` 明文）。成因：gateway 的
`ProxyController` 整体 `@Public()`，各后端微服务自行鉴权；而 mcp-gateway 的 `AdminController` **一处鉴权都没有**。

**问题二（敏感字段外泄）**：即便加了鉴权，`auth_config` 里的 token/账号仍会随列表接口进了浏览器内存与
（可能的）前端日志。运营后台不需要看到值，只需要知道「配没配」。

**问题三（数据破坏，已实测成灾）**：prod `mcp_modules` 表 `paper` 模块 `auth_type=''`、`auth_config=null`，
网关转发不带 `Authorization` → content-hub 返回 401。成因是 `AdminService.update()` 对未传字段无条件写
`?? ''` / `?? null`：前端只提交部分字段（如改个 description）就会把鉴权配置清空。

**验收目标**
1. 无凭证 / 非 admin 账号访问 `/api/mcp/*` → **401**；非 admin（portal C 端账号）→ **403**；admin → 200。
2. `GET /api/mcp/modules` 响应**不含** `auth_config`，改为 `auth_configured: boolean`。
3. `PUT /api/mcp/modules/:id` 只提交部分字段后，`auth_type` / `auth_config` / `tools` 与改前一致。

**Non-goals（明确不做）**
- 不改 nginx（`/api/mcp/modules` 不做 IP 限制——管理员在任意地点要用）。
- 不改 `POST /api/mcp/debug` 的契约与其可用 SSRF（另批处理），本次只把它一并纳入 admin 守卫。
- 不碰服务器 / `.env` / prod 数据 / content-hub 的 fail-open 策略。
- 不写台账 `~/AiWorkspace/30-任务产物/_待验证清单.md`。
- 不动 `/mcp/*` JSON-RPC 端点（走 client key，自己一套鉴权）。

### 2. 方案设计

#### 2.1 架构与数据流

```
浏览器(admin 前端)                     gateway :6000                mcp-gateway :6006
  │ Authorization: Bearer <JWT>            │                            │
  ├── GET /api/mcp/modules ───────────────►│                            │
  │                                        │ ProxyController            │
  │                                        │  @Public (class) ← 全局 AuthGuard 跳过
  │                                        │  + McpAdminGuard (新增, 方法级)  ← 本次加
  │                                        │   ├ 无 Bearer      → 401 ‘缺少登录凭证’
  │                                        │   ├ verify 失败    → 401 ‘登录凭证无效或已过期’
  │                                        │   ├ type!=='access'→ 401 ‘令牌类型不正确’
  │                                        │   └ systems 无 admin → 403 ‘该账号不属于运营后台（admin）’
  │                                        ├── 通过 ──► 转发（原样透传 Authorization）
  │                                        │                            │ AdminController.list()
  │                                        │                            │  脱敏：删 auth_config
  │                                        │                            │        加 auth_configured
  │◄────── { modules: [...] } ─────────────┴────────────────────────────┘
```

守卫放在 **gateway 层**而不是 mcp-gateway：mcp-gateway 同时也被内网 service-to-service 直接调用（如内容管道），
在 mcp-gateway 加用户 JWT 守卫会打断内网调用；gateway 是唯一对外入口，且 JWT_SECRET 与 auth-service 同源。

#### 2.2 页面清单（含菜单）

无新增页面、无菜单变更。前端只改 `apps/admin/src/api/mcp.ts` 的类型定义（`auth_config` → `auth_configured`），
已确认无组件读取 `auth_config`。

#### 2.3 接口清单

| 方法 | 路径（经网关） | 入参 | 出参 | 鉴权方式（改后） |
|---|---|---|---|---|
| GET | `/api/mcp/modules` | — | `{modules: [{..., auth_configured: boolean}]}`（无 `auth_config`） | admin JWT |
| POST | `/api/mcp/modules` | CreateModuleDto | `{id, message}` | admin JWT |
| PUT | `/api/mcp/modules/:id` | Partial（未传字段保留） | `{id, message}` | admin JWT |
| DELETE | `/api/mcp/modules/:id` | — | `{id, message}` | admin JWT |
| POST | `/api/mcp/modules/:id/toggle` | `{enabled}` | `{id, enabled}` | admin JWT |
| POST | `/api/mcp/debug` | `{base_url,method,path,params}` | 调用结果 | admin JWT |
| POST | `/mcp`（JSON-RPC） | — | — | **不变**（client key） |

#### 2.4 数据结构

无 DDL。`mcp_modules` / `mcp_tools` 表结构不变；仅写入口径从「无条件覆盖」改为「未提供则保留」。

> ⚠️ 存量数据不在本 PR 修：prod `paper` 模块 `auth_type=''` / `auth_config=null` 需运维单独按值回填
> （本 PR 只是止血，防止继续被清空）。

|---|---|---|---|---|
| `JWT_SECRET` | 环境变量 | 沿用（gateway 已有，且启动强校验非空） | 各环境同源 auth-service | 阶段1（缺失则网关根本起不来，非本次新增风险） |

| 依赖对象 | 类型 | 强/弱 | 缺失后果 | 发布关联 |
|---|---|---|---|---|

#### 2.7 初始化数据

无可写死的初始化数据。评测/演示用的 admin 账号由 auth-service 侧既有种子提供，本次不改。

#### 2.8 权限模型

| 主体 | 凭证 | 判定 | 结果 |
|---|---|---|---|
| 无凭证 | 无 `Authorization` | — | 401 `缺少登录凭证` |
| C 端 portal 用户 | access token，`systems=['portal']` | `hasSystem(...,'admin') === false` | 403 `该账号不属于运营后台（admin）` |
| refresh token | `type==='refresh'` | `payload.type && payload.type !== 'access'` | 401 `令牌类型不正确` |
| 运营后台管理员 | access token，`systems` 含 `admin` | 通过 | 转发到 mcp-gateway |
| 内网 service 调用 | 直连 mcp-gateway:6006 `/api/modules` | 不经 gateway，**行为不变** | 200 |

#### 2.9 接口设计约束

- 守卫**只挂两条路由**：`/api/mcp`（精确，`:556`）与 `/api/mcp/:path(*)`（通配，`:562`）。不写在 class 上（会波及 `/api/*` 全部代理）。
- 响应脱敏在 **controller 边界**做（展示层关注点），不改实体、不改 service 的 `list()` 返回类型（`mcp.service` 等内部调用方仍拿得到 `auth_config` 用于转发）。
- 脱敏取「**整字段摘除 + 布尔位**」，不逐键掩码 `"***"`——键名本身（如 `token` / `password` / `header_name`）在运营排障时有价值，值才敏感。
- `update()` 的「未提供则保留」以 `undefined` 为唯一「未提供」判据；`null` 视为**显式清空**（`auth_config: null` 有意义）。
- `auth_config: '__KEEP__'` 为前端「我只改了别的字段，别动鉴权」的显式哨兵，避免前端必须回传明文密钥。

### 3. 影响面与风险

| 改动点 | 面 | 风险级 |
|---|---|---|
| gateway `McpAdminGuard` 挂 2 条路由 | `/api/mcp/*` 全部请求 | **中**（本来无鉴权，现在要求 admin JWT；C 端 token 会被 403） |
| mcp-gateway `GET /api/modules` 脱敏 | admin 前端 MCP 管理页 | 低（前端无组件读 `auth_config`） |
| mcp-gateway `update()` 改为「未提供则保留」 | 模块编辑 | 低（语义朝「不破坏数据」方向变，不会更危险） |
| 新增 spec 文件 | 无运行时 | 无 |

**兼容性**：admin 前端 `apps/admin/src/api/mcp.ts` 的 axios 请求拦截器早已在自动加 `Authorization: Bearer <localStorage user-store 里的 token>`，
而后端此前从不校验 → **本 PR 是把「本来就在发的凭证」真正拿来校验**，前端无需改鉴权逻辑，只改类型。
**灰度**：不做灰度，后端与前端同一 PR 发布（前端改动是纯类型，向后兼容旧后端）。

### 5. 发布任务清单

- **阶段 0 pre-flight**：确认 prod/dev gateway 与 mcp-gateway 的 `JWT_SECRET` 与 auth-service 同源（不是本次引入，但守卫依赖它）。

### 6. 回滚预案

| 层 | 回滚方式 | 备注 |
|---|---|---|
| gateway | 回滚到上一版本（指针/流水线重发） | 立即恢复「无鉴权」，即回到当前线上状态 |
