## 1. 背景与目标
- **背景**: NCE 已随 `948d24fd` 发布 prod，但仅含 NCE2 全册 96 课。源数据 `lessons3.json`(NCE3/60)、`lessons4.json`(NCE4/48) 早已抓取就绪（markdown 在 `20-私域资产/新概念英语学习/课文/NCE3|NCE4/`，结构化 JSON 在 `30-任务产物/2026-11-05-新概念英语学习站点/data/`）。用户决策（2026-11-09）：立项做 NCE3/4，按"先 dev 接 UI 验证再同步 prod"开工，NCE4 收敛 48 课（L49–60 非正典已剔除）。
- **目标**:
  1. 后端接口支持 `?book=NCE3|NCE4`（默认 NCE2，向后兼容）
  2. admin / portal 加册别切换器，用户可浏览三册
  3. dev 库重导 NCE3(60)+NCE4(48)，dev 验证通过后同步 prod
- **验收目标**: 切到 NCE3/NCE4 后列表/详情/点词卡正确显示该册内容，不串册；不传 book 时行为同现状（NCE2）。
- **Non-goals**:
  - 小程序（minigram）不在本次 web 三端发布范围（走微信渠道单独发）；但其底层接口读同一 DB，DB 导入 NCE3/4 后即可读取，前端 `services/nce.ts` 硬编码 `NCE2` 放开为后续独立项
  - 不新增课文抓取（源已就绪）
  - 不改动点词卡交互逻辑（完全继承 NCE2 实现，对象绑定 `Map<string,NceWord>` 对齐 portal）

## 2. 方案设计

### 2.1 架构与数据流
- content-hub `NceLessonService`：用册别配置表替换原 `BOOK / BOOK_TITLE / TOTAL_LESSONS` 常量
  ```ts
  const BOOKS: Record<string, { title: string; total: number }> = {
    NCE2: { title: '新概念英语第二册 · 实践与进步', total: 96 },
    NCE3: { title: '新概念英语第三册 · 培养技能', total: 60 },
    NCE4: { title: '新概念英语第四册 · 流利英语', total: 48 },
  };
  ```
- `meta(book?)`：取 book 对应配置；`bookTitle` 取 DB 实际 `book_title`（保持前后一致）；`total` 取配置 `total`；`downloaded` 取该册 `repo.count({where:{book}})`。
- `list(book?)`：已支持 `q.book || BOOK`，沿用（默认 NCE2）。
- `detail(id, book?)`：改 `where { book, lesson_no }` 接受 book 参数（默认 NCE2）。
- 实体 `book` 列 + 唯一键 `(book, lesson_no)` 已就位，多册共存无冲突。
- 前端 admin/portal 维护册别状态（NCE2/3/4 标签或下拉），切换后透传 `book` 到 `getNceMeta / listNceLessons / getNceLesson`。

### 2.2 页面清单（含菜单）
| 页面 | 路由 | 职责 | 权限门控 |
|---|---|---|---|
| admin NCE 阅读器 | `/admin/content/nce-lessons` | 册别切换 + 列表 + 预览抽屉（中文/生词/习题） | `admin:view`（沿用） |
| portal NCE 页 | `/portal/nce` | 册别切换 + 发现卡入口 | `@Public` |

> 菜单为 router 代码声明，随前端模块发布；无 DB 菜单，无权限同步需求。

### 2.3 接口清单（契约）
| 方法 | 路径 | 入参 | 出参 | 鉴权 |
|---|---|---|---|---|
| GET | `/api/content-admin/nce/meta?book=NCE2\|NCE3\|NCE4` | `book?`（默认 NCE2，非法回退 NCE2） | `{book, bookTitle, total, downloaded}` | 用户 JWT |
| GET | `/api/content-admin/nce/lessons?book=&page=&pageSize=&keyword=` | `book?` | `{total, items[]}` | 用户 JWT |
| GET | `/api/content-admin/nce/lessons/:id?book=` | `id`(path, `@Max(96)`), `book?` | `NceLessonDetail` | 用户 JWT |

- **兼容性**：不传 `book` → 行为同现状（NCE2），旧调用方零改造。
- `@Max(96)` 对 NCE3/4 课号（≤60/48）仍兼容，**保留不动**（放宽到 200 为可选，本次不改）。

### 2.4 数据结构
- 表 `nce_lessons` 已存在：`book` 列 + 唯一键 `(book, lesson_no)` 已就位。
- **无 DDL 变更**（流水线不同步 DDL，此处确认无需）。
- 新增初始化数据：NCE3(60 行) + NCE4(48 行)，经 `import-nce-lessons.mjs --file` 幂等 UPSERT。

### 2.5 配置清单
| 配置项 | 类型 | 改动 | 环境差异 |
|---|---|---|---|
| 网关路由 | 沿用 | 无新增（复用 `/api/content-admin/nce/*`） | 各环境 |
| 部署路径 | 沿用 | 沿用 | 各环境 |

### 2.6 依赖系统或接口
| 依赖 | 类型 | 强/弱 | 缺失后果 |
|---|---|---|---|
| 网关路由 `/api/content-admin/nce/*` | 内部 | 强 | 整模块 404（已存在，沿用） |
| DB `nce_lessons` | 中间件 | 强 | 功能空转（需先重导 NCE3/4） |
| 源数据 `lessons3/4.json` | 外部文件 | 中 | 无法导入（位于 `30-任务产物/2026-11-05-新概念英语学习站点/data/`） |

### 2.7 初始化数据 / 种子数据
| 数据项 | 内容 | seed 方式 | 幂等 | 环境差异 |
|---|---|---|---|---|
| NCE3 课文 | 60 课（Lesson 1–60） | `import-nce-lessons.mjs --file lessons3.json` | UPSERT 唯一键 `(book,lesson_no)` | dev + prod 都跑 |
| NCE4 课文 | 48 课（Lesson 1–48） | `import-nce-lessons.mjs --file lessons4.json` | 同上 | dev + prod 都跑 |

### 2.8 权限模型
- 沿用现有 `admin:view` / `@Public`，**无新增权限项**，无权限同步需求。

### 2.9 接口设计约束
1. **静态/参数路径**：`/nce/meta`、`/nce/lessons` 为静态与列表；`/nce/lessons/:id` 已带 `:id(\d+)` 约束，无抢匹配。
2. **参数强校验**：`id` 走 `@Param` + `@Max(96)` + `ParseIntPipe`，非法 400；`book` 枚举校验（NCE2/3/4），非法回退默认 NCE2（不报错，避免前端卡死）。
3. **并发聚合**：`meta` 与 `list` 独立调用，无 `Promise.all` 装饰性拖累；`detail` 单查，无辅助接口。

## 3. 影响面与风险
- **改动范围矩阵**:
  - 后端：content-hub `nce-lesson.service.ts`（BOOKS 配置 / meta / detail）、`nce.controller.ts`（meta / detail 加 book）
  - 前端 admin：`NceLessons.vue`（加册别切换器）+ `api/nce.ts`（`getNceMeta` / `getNceLesson` 加 book）
  - 前端 portal：`Nce.vue`（切换器）+ `api/nce.ts`（同上）+ `config/capabilities.ts`（描述改多册）
  - 数据：dev + prod 重导 NCE3/4
- **风险**：低–中。默认 `book=NCE2` 保证向后兼容；多册切换若透传错 book 会串册（由 TC 覆盖）。
- **兼容性**：向后兼容（不传 book 同现状）。
- **灰度**：不分批，随三端发布整体生效。

## 4. 测试方案
- 4.1 单元测试：册别配置表取标题/总数；`detail` 按 `(book, lesson_no)` 取；边界 book 非法→默认 NCE2。
- 4.2 接口集成：meta / lessons / detail 对 NCE2/3/4 分别返回正确册；不传 book 回 NCE2。
- 4.3 功能测试用例矩阵：见 `测试用例-NCE多册.md`。
- 4.4 回归：NCE2 既有功能（点词卡 TC-02/05/06）不受影响；admin/portal 现有 NCE2 浏览不变。

## 5. ⭐ 发布任务清单
- **阶段 0 pre-flight**：`plan` 预演；dev vs prod 表结构比对（一致）；网关路由比对（沿用）；初始化数据确认（prod 仅 NCE2，需重导）；路由冲突自查（无）。
- **阶段 1 后端**：content-hub 提交流水线 `--commit <sha>`。
- **阶段 2 表结构 + 初始化数据**：无 DDL；dev 重导 NCE3/4 → 验证 → prod 重导 NCE3/4（dev→prod 管道同步，同 #8503 方式）。
- **阶段 3 前端**：admin + portal 发布（构建→上传→切指针）；校验产物 HTTP 可达。
- **阶段 4 验证**：按 §4.3 用例矩阵 dev + prod 逐条走查；接口探活；prod `verify_release` `verdict=verified`。

## 6. 回滚预案
| 层 | 回滚方式 | 限制 |
|---|---|---|
| 后端代码 | `rollback <env> content-hub <tag>` | 目标产物须在盘上 |
| 前端 | 指针切回旧 commit | — |
| 配置/路由 | 无变更 | — |
| 初始化数据 | **不可回滚**（seed 幂等可重跑；撤回需人工 `DELETE FROM nce_lessons WHERE book IN ('NCE3','NCE4')`，删前必须备份） | 🔴 删前备份 |

## 7. 验收标准
- 切 NCE3 → 列表显示 60 课、`bookTitle`=NCE3 标题、点词卡不串册
- 切 NCE4 → 列表 48 课
- 不传 book → 默认 NCE2（96 课，行为不变）
- prod 三端发布后 `verify_release` `verdict=verified`
