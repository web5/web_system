# 头像写侧净化方案（2026-11-11）

## 一、Bug 根因

D1 铁律：avatar 在 DB 永远存相对路径 `/api/uploads/avatars/<file>`，只在返回前端前
拼公网 URL（`resolvePublicUrl`）。

断点：upload-service `POST /api/upload/avatar` 现在返回完整 URL
（`servers/upload-service/src/upload/upload.controller.ts:124-126` 用了
`resolvePublicUrl`），小程序 `apps/dachengzi-minigram/pages/mine/profile/profile.ts:85-89`
拿到后 `updateProfile({avatar: url})` 原样 PUT 落库 → DB 写入
`https://dev.kedouai.com/api/uploads/avatars/xxx` 污染行。

已确认：portal（走 `/api/users/me/avatar`，服务端自己落相对路径）与 admin（只显示）
无污染；读侧（auth verify / user getMe / updateMe）拼 URL 全部正确，本次不动。

## 二、修复方案

1. **shared 新增剥前缀函数**：`packages/shared/src/public-url.ts` 新增
   `stripPublicBaseUrl(path, base)`：
   - 空值 → 空串；base 空 → 原样返回
   - `path` 以 `${base}/` 开头（base 先去尾斜杠）→ 返回剥掉 base 后的相对路径
     （保证以 `/` 开头）
   - 其它（含第三方 URL 如微信头像、相对路径）→ 原样返回
   - 从 `packages/shared/src/index.ts` 导出
2. **user-service 写侧净化**：`servers/user-service/src/user/user.service.ts` 的
   `create` 与 `update` 方法落库前，若 DTO 含 `avatar`，先
   `stripPublicBaseUrl(avatar, await this.publicBaseUrl.resolve())`。
   UserService 注入 `PublicBaseUrlService`（`user.module.ts` providers 已有，
   直接 constructor 注入）。不破坏现有方法签名与返回。
3. **单测**：
   - `packages/shared/src/public-url.spec.ts` 补 `stripPublicBaseUrl` 用例：
     空值 / base 空 / 命中剥前缀 / 第三方 URL 不动 / 相对路径不动 / 尾斜杠
   - user-service `user.service.spec.ts` 补写侧净化用例：avatar 带
     `https://dev.kedouai.com` 前缀 → 落库相对路径；外部 URL → 不动
4. **不改**：upload-service 响应形态、auth-service、前端任何文件。

## 三、微调豁免

微调豁免：bug 修复接线，非新功能，不改视觉 UI。
