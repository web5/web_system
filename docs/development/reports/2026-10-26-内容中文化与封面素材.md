## 1. 背景与目标

### 1.1 要解决的问题

| # | 问题 | 现象 | 根因 |
|---|---|---|---|
| P1 | AI 资讯里的英文内容没有中文化 | 采集到的英文标题原样出现在公众号与后台 | 标题从未本地化——只有正文摘要走翻译，`title` 直接透传原文 |
| P2 | 所有小预算 JSON 抽取静默失败 | 摘要质量不稳定，偶尔为空 | `hy3` 是 reasoning 模型，思考占满 `max_tokens` 后 `content` 为空 |
| P3 | 封面无法管理 | 只能用正文首图或硬编码兜底封面，换图要改环境变量 | 封面不是资产，是配置项；没有素材库 |

### 1.2 验收目标

| # | 目标 | 判据 |
|---|---|---|
| G1 | 英文标题有中文译名，原文不丢 | `title` 恒为原文，`title_zh` 为译名，展示层 `title_zh \|\| title` |
| G2 | 中文源零额外调用 | `looksChinese()` 判定 CJK 占比 >30% 时跳过翻译 |
| G3 | 封面可上传/管理/复用/AI 生成/微信同步/发布时选择 | 后台有素材库页；管线可设默认封面；成文记录封面快照 |

### 1.3 Non-goals（明确不做）

| 不做 | 原因 |
|---|---|
| 历史条目批量回填译名 | 一次性数据治理，与功能解耦；需要时单独跑脚本 |
| 封面在线编辑器（裁剪/加字） | 复杂度过高，AI 生成 + 人工上传已覆盖 90% |
| 多公众号封面隔离的 UI | 后端已按 `account` 隔离，UI 暂只服务默认号 |
| 正文图片素材库 | `kind` 字段已预留，本期只做 `cover` |
| 自动为每条成文生成封面 | 生图 10-40s，放进管线会拖长发布链路；保持"人工选/按需生成" |

## 2. 方案设计

### 2.1 架构与数据流

**中文化链路**

```
采集（RSS/API）
  → processNews/processPaper（LLM 抽取，含"标题"字段）
  → pipeline.localizeTitle()
       ① 源语言判定 detectLang / looksChinese
       ② 中文源 → title_zh = null（零调用）
       ③ 英文源 → 优先用 LLM 抽取出的中文标题
       ④ 缺失时 → translateTitle() 单独兜底
  → toRenderItem()（统一渲染出口，title = title_zh || title）
  → buildDailyMarkdown() → draft/add
```

**封面链路**

```
上传：admin → content-hub /api/content/media (multipart)
            → upload-store.client → upload-service（唯一写盘点，covers 分类）
            → 回写 file_url + width/height/bytes/mime

AI 生成：admin → /api/content/media/generate
            → cover-ai.service（标题+摘要 → 生图 prompt）
            → TokenHub MaaS submit + poll
            → 下载 → 转存 upload-service
            → 落 content_media（source='ai'，记 prompt 便于复现）

微信同步：/api/content/media/:id/sync-wechat
            → wechat-mp.client.uploadThumbFromUrl()（下载 URL → add_material image）
            → 回写 media_id + url（按 account 隔离）

发布：pipeline.service
            → 解析 default_cover_id → 确保 media_id 存在（无则同步）
            → 传给 publisher → draft/add 的 thumb_media_id
            → 成文记录 cover_media_id 快照 + use_count/last_used_at 累加
```

🔴 **不变量**：content-hub **不写盘**。图片二进制一律交 upload-service，本服务只存 URL 与元数据。

### 2.2 页面清单（含菜单）

| 页面 | 路由 | 职责 | 权限门控 |
|---|---|---|---|
| 封面素材库 | `/content/media` | 列表、上传、AI 生成、改名/标签、启停、软删、同步微信 | `JwtAuthGuard`（复用内容模块登录态） |
| 采集明细（改） | `/content/items` | 标题列展示 `title_zh \|\| title`，详情页显示双语 | 同上 |
| 内容详情（改） | `/content/items/:id` | 展示原文标题 + 译名 + 源语言标识 | 同上 |
| 发布管线编辑（改） | `/content/pipelines/:id/edit` | 新增「公众号封面」选择器（默认封面） | 同上 |

菜单：`PictureOutlined`，挂在内容管理下，**router 代码声明**（非 DB 菜单树）。

> 判定（§2.7 三问法）：菜单在 router 代码里 → 不算初始化数据，随前端发布生效。

### 2.3 接口清单

| 方法 | 路径 | 入参 | 出参 | 鉴权 |
|---|---|---|---|---|
| GET | `/api/content/media` | `keyword? tag? source? enabled?` | 素材数组（未删除，≤200） | 用户 JWT |
| GET | `/api/content/media/tags` | — | 标签聚合数组 | 用户 JWT |
| POST | `/api/content/media` | multipart：`file`(必填) `name?` `tags?` | 新建素材 | 用户 JWT |
| POST | `/api/content/media/generate` | `title`(必填) `summary?` `styleExtra?` `name?` `tags?` | 生成的素材 | 用户 JWT |
| PATCH | `/api/content/media/:id` | `name?` `tags?` `enabled?` | 更新后的素材 | 用户 JWT |
| DELETE | `/api/content/media/:id` | — | `{ok:true}`（被管线引用时拒绝） | 用户 JWT |
| POST | `/api/content/media/:id/sync-wechat` | `account?` `force?` | 含 `media_id`/`url` 的素材 | 用户 JWT |

**接口设计自查（§2.9）**

| 约束 | 自查结果 |
|---|---|
| ① 静态路径 vs `:param` 共存 | `GET /tags` 与 `PATCH /:id`、`DELETE /:id`、`POST /:id/sync-wechat` 同前缀，但**无 `GET /:id`**，不存在静态路径被 `:param` 抢匹配 |
| ② 路径参数强校验 | 全部经 `parseId(id, '素材')`，非数字抛 `BadRequestException`，不直接进 ORM |
| ③ 并发聚合降级 | 素材列表为独立页面，无 `Promise.all` 主链路耦合 |

### 3.2 风险分级

| 风险 | 等级 | 说明 | 缓解 |
|---|---|---|---|
| 译名污染 `title` | **高** | 一旦写错列，原文丢失不可逆 | `title` 永不覆盖；单测含 2 条反向断言 |
| 封面素材被删后历史成文失效 | 中 | 成文快照已存 `cover_media_id` | 软删除 + 被管线引用时拒删 |
| AI 生图超时 | 中 | 前端默认超时会掐断 | 前端放宽该请求超时；失败可人工上传 |
| `hy3` 空返回 | 中 | reasoning 吃满预算 | `chat()` 默认 `thinking: disabled` |
| TokenHub 间歇 401002 | 低 | 已知抖动 | 生产 `chat()` **仍缺重试**（见 §9 已知缺口） |

### 3.3 兼容性

- `title_zh` 为 NULL 时，展示层回落 `title` → **旧数据零影响**
- `default_cover_id` 为 NULL 时走旧封面逻辑 → **旧管线零影响**
- 新表 `content_media` 为新建，无迁移风险

### 3.4 是否灰度

否。后台管理功能，用户仅自己使用，全量发布。

## 6. 回滚预案
