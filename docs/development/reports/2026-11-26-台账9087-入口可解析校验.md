## 1. 问题（一句话）

`site-version` shell 切换 / 回滚时只校验「`<version>/index.html` 这个文件在不在」，**不校验它引用的 js / css 能不能找到**。于是「index.html 在、assets 不在」的版本能切成功 —— 页面 200 打开但脚本 404，表现为**白屏**（fail-open）。

线上真实样本：`6e7b2690` / `4ea6d64` 的 `index.html` 引用 `/static/modules/shell/shell-dev/…`，`shell-dev` 在 prod 落点不存在。

## 2. 目标 / 不做

| 做 | 不做 |
|---|---|
| 切换前校验 entry 引用可解析，不可解析 → 400 + 指针逐字节不动 | 不改 `resolveRollbackTarget`（选目标前置校验归 `#9106`） |
| 错误带机器可读码 `ENTRY_UNRESOLVABLE` | 不加「跳过不可用目标继续回退」的回落循环 |
| 只在 `site-version` shell 分支生效 | 不做回滚后健康检查 / 自动回退（方案 ③，另议） |
| 远端单次 ssh 批量判定 | 不改任何数据、不改 `env-dir`（`index.js`）路径 |

## 3. 现状代码事实（基线 `c22a29d8`）

| 位置 | 现状 |
|---|---|
| `apps/apps.service.ts:555-573` | `hasVersion(...'index.html')` → 文件存在即放行；不存在 → 400，指针不动（这部分正确，保留） |

> 注：源码侧「≠当前」自指守卫已于 `08675e64`（11-26 12:07）落地，与本单无关；本单只补「entry 可解析」这一层。

## 4. 设计

### 4.1 新增 `EnvArtifactService.assertArtifactResolvable(env, appKey, version)`

1. `resolveVersion(..., 'index.html')` 拿版本目录的**实际磁盘名**（复用既有 legacy 拼写容错，避免 `portal/<commit>` 这类脏值误判）。
2. 读 `<versionDir>/index.html`：本机 `fs.readFileSync`；远端 `ssh cat`（单次往返）。
3. 用纯函数 `extractEntryAssetRefs(html)` 抽 `src=` / `href=` 中**以 `.js` / `.css` 结尾**的引用（去 query/hash，去重），跳过 `http(s)://`、`//`、`data:`、`mailto:`、`#`。
4. 每个引用映射到磁盘路径（纯函数 `resolveEntryRefPath`）：
   - `/static/…` 绝对路径 → `<静态根>/static/…`（同一台落点机）
   - 其他 `/…` 前缀 → **跳过**（`/shell/…` 等由 gateway 拼装，不属版本产物，跳过避免误杀）
   - 相对路径 → 相对版本目录，`normalize` 后必须仍在版本目录内（拒绝 `..` 越界）
5. 存在性判定：本机 `fs.existsSync`；远端**一条 ssh 批量** `[ -e path ] || echo path`（单次往返，不逐文件往返）。
6. 有缺失 → 抛 `Error`，消息以 `ENTRY_UNRESOLVABLE` 开头并列出缺失的**磁盘路径**；远端读不到 html / ssh 失败 → 抛普通错误（文案区分「读不到」与「不可解析」，**不允许静默通过**）。

### 4.2 调用点：`apps/apps.service.ts` 在 `hasVersion` 之后、`setAppEnvPointer` 之前

```ts
if (siteVersionShell) {
  try {
    await this.artifacts.assertArtifactResolvable(envId, appKey, version);
  } catch (e) {
    throw new BadRequestException((e as Error).message);
  }
}
```

**语义变化**（本单唯一一处）：以前「能切成功然后白屏」→ 现在「切不动（400）+ 指针不动」。
既有「产物不存在 → 400」的语义与文案**逐字保留**。

### 4.3 为什么不做「跳过不可用目标」

那属于 `#9106`（回落不做产物存在性校验），会与 `#9078` 已定案交叉；本单只把 fail-open 改 fail-closed，不改变「选谁」的规则。

## 5. 影响面与风险

| 项 | 判断 |
|---|---|
| 触发面 | 仅 `app.kind==='shell' && deployMode==='site-version'`；`env-dir`（`index.js`）与 CDN 分支不受影响 |
| 对外行为 | 新增一种 400（`ENTRY_UNRESOLVABLE`）；成功路径返回体不变 |
| 远端成本 | 每版本切换 +2 次 ssh（`cat` + 批量 `test -e`），均为 15s 超时保护 |
| 误杀风险 | 只判 js / css（图片 404 不致白屏）；`/shell/…` 等平台前缀跳过；html 内无 js/css 引用时直接放行 |
| 数据 | 零写入、零 schema 变更 |
| dist | 仓库 `dist/` 未纳入 git（`.gitignore:14`），构建与部署另走发布流程（本 PR 不含） |
