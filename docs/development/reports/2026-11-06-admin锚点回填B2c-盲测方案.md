1. **V2/V3（运行时锚点命中 + 可见）**——最容易被 `grep` 假绿替代。§6.3 已经实证 6 类 antd 组件属性不落地，其中 `a-page-header` 的 `#backIcon` 甚至要 `@back` 才渲染。我预判 `detail-back` 与 5 个 `gen-params-*`（落在内部 `.ant-row`）是最先出问题的地方。
2. **V25（反向判据：阻塞项不得偷跑）**——这条最反直觉：别人都在查「锚点在不在」，我查「不该在的有没有在」。4 个 `gen-params-*-badge` 在原型里是 `.badge.hidden`，「元素存在」永远为真，**谁用它判回填成功，就会把 4 个阻塞项算成已完成**，直接导致 `admin` 缺口被少报 4。
3. **V27（锚点命中但语义未兑现）**——`crumb-list` 就是活样本，而且我**已静态确认它大概率过不了**：key 挂在 `layouts/BasicLayout.vue:120` 的 `a-breadcrumb` 上，扫描器全绿；但面包屑里只有「主页图标 + 当前页标题」**2 段、无可点元素**，而规格要「Agents / 定义管理 / `<id>`」3 段且「可回列表」。**「19 个 key 全命中」≠「19 个交互都兑现」**——这类缺口 R11b 永远扫不出来，只能靠点击验。
4. **C13（空值写成 0 / 0.7）**——不是 DOM 问题，是请求体问题。C7-c/C7-e 是契约明令，但它在**用户看不见的地方**：页面显示「留空」，请求里却是 `0.7`，任何 DOM 断言都抓不到，只有拦 payload 才能抓。

**规格里最没写清的两条**

1. **S3 计数时机**：§4 把「差异计数」定成「唯一表达」，却没定「什么时候算」。改成 `blur` 才算 → 用户填完还没离开输入框就看到「0 项未保存」，会以为丢了；改成输入即算 → 中间态 `1.` `1.2` 会闪。**必须拍板，否则 V21 无法判 pass/fail。**
2. **S7「保存后基线是否同步」自相矛盾**：§4 结果级写「保存成功后**基线同步为当前输出**」，§7 第 3 条又写「稿内保存**不**自动同步基线」。这不是细节——它决定「保存一次之后，用例表该显示 0 处差异还是仍有 N 处差异」，两个答案的用户心智完全相反。**需产品拍板，否则结果级验收没有基准。**
