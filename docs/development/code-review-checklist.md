# 代码评审判据清单（code-reviewer）

> 开关：CHANGELOG=off · HISTORY_NOTE=off · FAQ_KEEP=on
> 定位：`code-reviewer`（S5.2）的判据源 —— **独立于实现者**的代码评审（与 `rd-review` 实现者自查分层）。
> 关联：`specs/rd-process-model/design.md`（流程与角色）· `docs/development/release-review-checklist.md`（同族清单）· `scripts/redline/scan-rules.sh`（机器可检部分）

---

## 0. 本清单的边界（先读这条，否则会做无用功）

**只列机器查不出的。** 机器能查的一律交给 CI，不占评审者注意力：

| 已由机器覆盖 → **不在此列** | 规则 |
|---|---|
| 调试残留（`console.log` / `debugger`） | R1 |
| 敏感文件入库 / 硬编码凭据 | R2 |
| 占位残留（`TODO` / `FIXME` / `TEMP` / `HACK`） | R3 |
| TS 铁律（`@ts-ignore` / `: any`） | R4 |
| CORS 硬编码 / 无参启用 | R5 |
| 服务入口缺全局异常过滤器 | R8 |
| 重复造轮子（既有实现可复用） | R7（若启用） |

> **判据**：一条判据若能写成脚本检查，就**应该**写成脚本，不该写进本清单。
> 本清单只放「需要理解意图才能判」的项。

## 用法

| 项 | 内容 |
|---|---|
| 触发面（CI **R15** 拦截） | **新增**对外接口（`*.controller.ts` 新增文件） |
| 分级 | 新增对外接口 → **必须过**；改动既有实现 → 按需（接口敏感面优先） |
| 报告落盘 | `docs/reviews/<topic>-<YYYYMMDD>.md`（项目可另约定目录），头部机器可读两行 `阻塞: N` / `重要: N` |
| commit trailer | `Code: pass` 或 `Code: <报告路径>`；纯微调走 `Micro-exempt: <理由>` |
| 级别 | warning（`--strict` 下 error）—— 本门主观性最强、成本最高，先观察再收紧 |

## A. 接口与入参（新增对外接口必查）

| # | 判据 | 怎么验 | 不通过怎么办 |
|---|---|---|---|
| A1 | 入参有校验（DTO + class-validator / 全局 ValidationPipe），不裸接 `body` | 看 controller 签名与全局 pipe 配置 | 补 DTO 与校验 |
| A2 | 鉴权齐：除显式 `@Public()` 外必须有权限装饰器，且权限码已登记 | 对照 `packages/types` 的权限码与路由元数据 | 补装饰器；新增权限码走**契约面**（R13） |
| A3 | **数据归属校验（越权）**：按 id 读写他人资源时，查询条件含属主约束 | 追到 service 的查询构造 | 补归属条件（这是最高频的真实漏洞） |
| A4 | 新接口已登记契约（`specs/<svc>/api-design.md`） | 查契约文档是否含该方法 | 补登记（契约面 R13 也会拦） |

## B. 错误处理

| # | 判据 | 怎么验 | 不通过怎么办 |
|---|---|---|---|
| B1 | **不吞异常**：`catch` 里不能只有 log 而没有抛出或明确降级语义 | 逐个看 `try/catch` | 明确二选一：抛出，或降级 + 注释说明为何可降级 |
| B2 | 错误码 / HTTP 状态**有语义**（不用 500 兜住一切） | 看异常映射与既有错误码 | 用项目既有错误码语义对齐 |
| B3 | 失败路径有测试，或给出可复现反例 | 看测试用例 | 补测试或复现步骤 |

## C. 安全与敏感信息

| # | 判据 | 怎么验 | 不通过怎么办 |
|---|---|---|---|
| C1 | 日志**不打敏感字段**（token / 密码 / 身份证 / 完整手机号 / 密钥） | grep 日志语句里的变量 | 脱敏，或只打 id |
| C2 | 外部输入不进 SQL 字符串拼接（走 ORM / 参数化查询） | 看查询构造 | 改参数化 |
| C3 | 内部接口有内部鉴权（不是 `@Public()` 裸奔） | 看装饰器与既有内部 key 约定 | 补内部鉴权 |

> 与 R2 的区别：R2 查「**硬编码**凭据」，本条查「**日志/响应泄露**运行时敏感值」。

## D. 可观测

| # | 判据 | 怎么验 | 不通过怎么办 |
|---|---|---|---|
| D1 | 关键写操作有日志 / 审计（谁、做了什么、结果） | 看 service 的写路径 | 补日志或审计 |
| D2 | 外部调用失败时有可定位信息（不吞成笼统的 `request failed`） | 看 catch 内容 | 带上游返回片段与上下文 |

## E. 资源与副作用

| # | 判据 | 怎么验 | 不通过怎么办 |
|---|---|---|---|
| E1 | 多步写操作在事务内（或明确说明为何不需要） | 看 service | 补事务 |
| E2 | **可重入性**：重复调用是否安全（幂等键 / 去重） | 主动构造「同请求发两次」反例 | 补幂等键，或说明为何天然幂等 |
| E3 | 流 / 连接 / 定时器 / 订阅有释放路径 | 看 `finally` / 取消订阅 | 补清理 |

## F. 与既有约定一致

| # | 判据 | 怎么验 | 不通过怎么办 |
|---|---|---|---|
| F1 | 命名与分层与该服务既有代码一致 | 对照邻近文件 | 改名对齐 |
| F2 | 未引入第二套做法（同类问题项目已有解法时优先复用） | 搜既有实现 | 复用，或说明为何不复用 |
| F3 | 无跨层调用（controller 不直连 repository 等） | 看依赖注入 | 收口到 service |

## 报告格式（与 design / release / contract 三份清单同构）

```
阻塞: N
重要: N
```

正文每条须含：**反例（情形 → 实际 vs 期望）+ 判据编号（A1…F3）+ 严重级 + 是否阻塞**。
指不到本清单编号的意见 → 降级为「建议」并标注「无判据，属个人偏好」。

## 零摩擦边界（不触发本门）

改动既有实现且不属接口敏感面、纯文档、纯样式/文案、纯配置值。**作用域宁可窄**——本门是全套门禁里主观性最强的一道，摩擦过大必然被关掉。
