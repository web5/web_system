# 核心接口基线（抽样单测的常驻清单）

> **用途**：S7 测试环节走「抽样」时，**直接从这份清单里挑**，不必每次重梳（重梳三次就会退化成走形式）。
> **判据源**：`~/AiWorkspace/20-私域资产/研发流程SOP.md` §7.6（核心接口 5 判据）· §7.3（共享面）
> **维护**：新增对外接口 / 契约边界时补一行；**没有用例的「核心」要照实标 ❌** —— 它们是抽样时最该被挑中的，也是最该补用例的。
> **版本**：v1.0 · 2026-11-06 · 基线来源 = 全量单测实测口径（18 个带 test 脚本的包 / 239 个 spec 文件）

---

## 0 怎么用（30 秒版）

| 你的改动命中 | 从这张表挑 |
|---|---|
| 共享类型 / 常量（`packages/types`、`packages/shared`） | §1（全部）+ 消费方所在域的条目 |
| Agent 协议（`agent-core/src/interfaces`） | §2 全部 |
| 服务入口 / 全局 filter·guard·interceptor | §1 鉴权 + 该服务所在域 |
| 数据库迁移 / 全局配置 | §4 用户与数据（写入面）+ §3 发布流水线（迁移执行面） |
| 共享 UI（`packages/ui`） | §6 共享层 |
| 测试与构建基建（`jest.config`、`scripts/ci`、CI workflow） | §7 基建自检（**这一组没有单测，只能靠 `cases/run.sh` + 全量**） |

两条硬要求（SOP §7.6）：
1. 命中共享面的**每个直接消费包**至少挑 1 条；
2. 挑不足 5 条 → 说明影响面实际不大，**退回局部单测**，别硬凑。
