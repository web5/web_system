### 2.4 数据结构
表 / 字段 / 索引 增改，标注是否需 DDL 发布（**流水线不同步 DDL**，必须显式进发布清单阶段 2）。

### 2.5 配置清单
| 配置项 | 类型 | 改动 | 环境差异 | 发布关联 |
|---|---|---|---|---|
| gateway `/api/content-admin` 路由 | 网关路由 | 新增 | dev/prod 均需 | 🔴 阶段1 网关部署（漏过→404/服务器错误） |
| 静态路径 `static/modules/admin/<env>/<commit>/` | 部署路径 | 沿用+commit段 | 各环境 | 阶段3 上传 |
| deploy-console app key / envId | 发布配置 | 沿用 | dev/prod 不同 | 阶段3 指针切换 |
| 第三方凭证 / LLM Key | 环境变量 | 沿用 | 无 | 阶段4 验证 |

> 配置三类最易漏：**网关路由 / 权限规则 / 部署路径+凭证**。前两类直接导致白屏或无权限。

### 2.6 依赖系统或接口
| 依赖对象 | 类型 | 强/弱 | 缺失后果 | 发布关联 |
|---|---|---|---|---|
| gateway 路由 | 内部 | 强 | 前端整模块 404 | 阶段1 |
| auth 服务（权限） | 内部 | 强 | 无权限操作 | 阶段2 权限同步 |
| 外部数据源 / 发布渠道 | 外部 | 强/中 | 功能不可用或降级 | 阶段4 验证 |
| MySQL / Redis | 中间件 | 强 | 全功能不可用 | 阶段2 DDL |

> 规则：**内部强依赖最易漏**（路由、权限、指针），依赖清单必须回灌进「改动范围」与「发布清单」。

### 2.7 初始化数据 / 种子数据 🆕
**只收「运行时业务数据」**——功能依赖它才有内容/能跑，且**存 DB 需预置**。
| 数据项 | 内容 | seed 方式 | 幂等 | 环境差异 |
|---|---|---|---|---|
| 采集源清单 | 8 源 2 管线 | `archive/migrations/p38-content-sources-seed.mjs` | 幂等（唯一键 + ON DUPLICATE KEY） | **dev + prod 都要跑** |
| 字典/枚举 | 数据源类型、质量状态 | 代码常量 | — | 随代码 |

**边界判定（三问法）**：
1. 是运行时业务数据、缺了功能空转？→ **是 = 初始化数据**
2. 是代码声明（router / 常量 / 配置）？→ **否**，归 2.2 / 2.5 / 2.8；但**生效同步**必须进发布清单
3. 存 DB 且需手工预置？→ **是 = 初始化数据**（含 DB 存储的菜单树、权限项、角色映射）

> ⚠️ 权限与菜单在 web_system 是**代码声明**（权限常量启动自动 seed、菜单在 router），故不算初始化数据；
> 但**权限需重启 user-service 同步、菜单需前端模块发布**，二者「生效」都是发布阶段必勾项。

### 2.8 权限模型 🆕
| 权限项 | 授予角色 | 门控什么 | 生效方式 |
|---|---|---|---|
| `content:view` | admin/super_admin | 菜单与列表可见 | 代码常量 + 重启 user-service 自动 seed |
| `content:manage` | admin/super_admin | 新建/编辑/重发 | 同上 |

## 5. ⭐ 发布任务清单（强制，按依赖顺序）

> **发布唯一入口 = 平台流水线**。Agent 走 MCP：`POST /api/mcp/pipeline`（`X-Mcp-Key`），
> 人走控制台 `/api/pipelines`（JWT）。执行已固化：
> `bash ~/.workbuddy/skills/web-system-deploy/scripts/publish.sh dev|prod|plan|rollback <svc> --commit <sha>`
> ⚠️ `scripts/deploy.sh` 已 DEPRECATED；**禁止从本地 SSH 手工 scp 发布**。
> ⚠️ `POST /mcp/pipeline` **没有 dry-run**，只读预演只认 `plan`（= `/api/mcp/release-plan`）。

### 阶段 0 · pre-flight（必做）
- [ ] `plan <env> <svc>` 预演：看 blockers / 风险分 / currentVersion
- [ ] 表结构差异比对：`SHOW CREATE TABLE` dev vs prod
- [ ] 网关路由比对：目标环境 gateway 版本是否已含新路径
- [ ] **初始化数据确认**：目标环境业务表是否已有 seed 数据（如 `content_sources` 行数）

### 阶段 1 · 后端（按 moduleKey 逐个发）
- [ ] `content-hub`、`gateway` 等提交流水线，**`--commit <sha>` 显式指定**
- [ ] dev/prod 都会停在 `awaiting-approval`，需 approve（prod 另需 `confirm:true`）

### 阶段 2 · 表结构 + 初始化数据 + 权限同步 🔴
- [ ] DDL：`CREATE TABLE IF NOT EXISTS` / 查 `information_schema` 后 `ALTER`
- [ ] **业务 seed 脚本执行**（幂等；prod 必跑，否则功能空壳）
- [ ] **重启 user-service 让权限 seed 生效**，确认权限项已入 DB

### 阶段 3 · 前端
- [ ] admin / portal 模块发布（构建 → 上传 → 切指针）
- [ ] 校验产物 HTTP 可达：`GET /static/modules/admin/<env>/<commit>/index.js` → 200

### 阶段 4 · 验证
- [ ] 按 §4.3 用例矩阵逐条走查（**dev + prod 都要**）
- [ ] 接口探活、回滚预案就绪

> **顺序铁律**：后端 → 数据 → 前端指针（颠倒会导致 404 白屏）。

## 6. 回滚预案
| 层 | 回滚方式 | 限制 |
|---|---|---|
| 后端代码 | `publish.sh rollback <env> <svc> <tag>`（prod 需 `--yes`） | 目标产物须在盘上 |
| 前端 | 指针切回旧 commit | — |
| 配置/路由 | 还原配置并重启 | — |
| 表结构 DDL | 一般向前兼容，**不回滚** | 如需 DROP 须单独评估 |
| **初始化数据** | **不可回滚**（seed 幂等可重跑，但已产生业务数据需人工清理） | 🔴 |
