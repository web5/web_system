# 合同翻译官 · 问题诊断

> 版本：v1.0 · 2026-08-27
> 主题：当前合同分析"太简单/太啰嗦"的根因分析

## 现状：为什么"太简单或太啰嗦"

问题不在 prompt 长度，而在 **缺少用户视角 + 场景化深度**。

| 维度 | 当前 contract-risk 提示词 | 问题 |
|---|---|---|
| **分析维度** | 只按"8 个法定尺子"扫描（利率上限/砍头息/违约金/搭售/续费/格式条款） | 只见风险，不见"这笔交易值不值、我怎么操作"。用户的真实诉求是"利率合不合适、月供明细合不合理、提前还款划不划算、怎么把权益最大化" |
| **场景深度** | `scene` 只有 7 个枚举标签，无场景专属分析 | 贷款合同和购车融资租赁的"关注点"完全不同，但提示词对两者一视同仁 → 输出泛泛 |
| **叙事结构** | 只输出 `signals`（点状风险）+ `rights`（权益） | 没有"先看合不合适 → 再看哪里坑 → 再看怎么操作"的逐层叙事，用户容易看懵 |
| **专业词汇** | 有 `termExplain`，但只是"有这个词时解释"，被动 | 没有"主动在解读里顺手科普"，也没有针对关键决策点（如"先息后本 vs 等额本息"）的利弊解读 |
| **用户引导** | 结论要求带"真实数字 + 下一步动作" | 已经不错，但缺乏"对比其他贷款优劣势""最大化权益的路线图"这类用户强烈想要的产出 |

## 一句话根因

> 现在是一个"**合规扫描器**"，用户要的是一个"**看懂这笔交易、知道怎么操作、能要回多少钱的老朋友**"。

## 付费意愿排序（产品视角）

```
能要回钱（可主张金额）  >  看懂风险（风险解读）  >  了解权益（权益清单）
```

当前实现停留在第二层偏弱的位置，第一层（可要回的钱）完全空白，这是付费转化的最大缺口。

## 关键结论

1. **不引入新 skill 机制**。当前架构（agent + 3 个确定性工具）是对的，问题 90% 在 system prompt 的"分析框架"和"场景化"，直接在 prompt 改最有效。
2. **标准库缺少"可主张金额"**。现有 `actions` 是"做什么"，没有"能要回多少钱"，这是要补的核心。
3. **前端缺"丝滑理解 + 快速追问"**。专业词汇要靠用户自己理解，不能快速引用追问。
