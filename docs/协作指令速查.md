## 0. 总原则 / 工作流偏好（橙子哥哥约定）
- **结论先行 + 表格 + 具体命令**；回复先给结论再细节。
- **运维动作直接执行**（SSH/远端/DB/重启），不必逐项确认；凭证归档 `~/env_config/`（servers.env / llm.env）。
- **先功能跑顺，再可维护性/健壮性**（拍板口径 2026-09-29）。
- **改前取工程事实**：从仓库根 `README.md` 及 `docs/**` 检索，**勿凭记忆或本文件猜数值**（本卡只列红线，不列端口/服务清单）。

## 2. 强制 commit trailer 速查
- UI 源码：`Proto: <已确认原型/规格的 sha>` + `Design: pass`（缺 → R10/R11 拦截）
- 发布/环境/数据：`Release: pass` 或报告路径（缺 → R14 拦截）
- 契约变更：`Contract: pass` 或报告路径（缺 → R13 拦截）
- 新增接口：`Code: pass` 或报告路径（缺 → R15 拦截）
- 纯微调豁免：在 message 写 `Micro-exempt: <理由>`（发布/契约/代码评审门适用）
- UI 门应急：`UI_GATE=off`（绕过原型/评审硬步骤）
- ⚠️ **原型/规格必须「单独 commit」**，不得与 UI 落地代码混同一 commit（hook 强制）。

## 2.5 PR 合入：建完立刻挂自动合入（不许干等）
- **标准动作**：建 PR 后**立刻**执行，然后转去做别的事，不要同步轮询：
  ```
  ~/.local/bin/gh pr merge --auto --merge <PR号或分支>     # 仓库 allow_auto_merge=true，惯例 merge commit
  ~/.local/bin/gh pr update-branch <PR号>                  # 仅当 mergeStateStatus=BLOCKED（分支落后 master）
  # 收尾统一对账：gh pr view <PR号> --json state,mergedAt
  ```
- **为什么不是「立刻合了」**：master 有分支保护（必填 checks + 要求与 master 同步），
  CI（红线扫描 + 改动包 build/test）约 1 分钟；`update-branch` 会**再触发一轮 CI**。
  当前 PAT 是 fine-grained **无 admin 权限**（读 `branches/master/protection` 403）→ 不能绕过/强合。
- ✅ 已验证可用：#238、#239 均通过 `autoMergeRequest` 自动合入。

## 3. 编码铁律（coding-best-practices 禁项）
- **CORS**：`CORS_ORIGINS` 默认空串，禁回退 `'*'`。
- **异常过滤器**：生产环境（`NODE_ENV=production`）非 `HttpException` 消息替换为「服务器内部错误」，不泄露表名/路径。
- **Logger**：禁 `console.log`，统一 NestJS `Logger`。
- **入参校验**：`@Body()/@Query()/@Param()` 必须 class-validator DTO，禁 `Record<string,string>` 裸类型。
- **JWT_SECRET**：`onModuleInit` 校验非空，空则 `process.exit(1)`。
- **横切修改 grep 全量**：改 CORS/异常过滤器/Logger/strict 时 grep 所有服务，不只改手头一个。
- **TypeORM 锁 0.3.x**（禁升 1.x：`CURRENT_TIMESTAMP(6)` 与 `datetime(0)` 冲突）；实体复用 `@web-system/shared` 的 `SnakeNamingStrategy`；**DDL 不写 `COLLATE`**（5.7 无 `utf8mb4_0900_ai_ci`）。
- **PM2 部署用 `restart`**，禁 `delete+start`（零停机）；**禁 `pm2 restart --update-env`**（会把会话变量固化进 `pm2_env`，dotenv 不覆盖已存在 `process.env` → 服务用错配置源）。
- **Docker**：敏感端口绑定 `127.0.0.1`；必须 healthcheck + `.dockerignore`。

## 4. 工程红线（实测事实，勿凭记忆，勿提交反例）
- **端口**：dev/prod 均 **6000 系**（gateway 6000、deploy-console 6200…）；`.env.example` 里的 3000 系是**本机**端口，服务器照抄必踩雷。
- **pm2 用短名**（gateway/auth-service…），非 ecosystem 的 `web-*`。
- **DB**：dev MySQL = dev 机本地 `127.0.0.1:3306 / web_system_deploy`；prod = `172.16.16.10:3306 / web_system`（云库）。本机另有同名库，别查错。
- **两段式发布（最大体验断点）**：流水线只把 dist 投递到版本目录，**不自动生效**；须再调 `POST /api/deploy/modules/:key/envs/:env/deploy`，且 `versionTag` 传**完整引用** `<templateKey>/<commit>`（传纯 commit → 500「找不到版本目录」）。
- **deploy-console** `synchronize:true`（实体随启动同步），但迁移仍要跑（补种基线快照）。
- **bash 脚本**：`bash -n` 抓不到「ssh 行尾缺续行符」→ 下一行命令落到执行机本地（语义 bug）。改脚本必扫该项（pipeline-lint L5）。
- **公开仓库去敏**：`web5/web_system` 是 PUBLIC。提交脚本/文档**勿写**服务器 IP、用户名、密钥路径、口令；现存 15 文件含三台 IP 待清理（用 `scripts/history-secret-scan.mjs` 只读扫描）。
- **prod 零触碰**：deploy-console 不在 prod 部署（违反零触碰 + 会污染 prod 库）；console 经 ssh2/scp 直连 prod 是已知债（应拆 runner）。
- **Docker 端口挡截**：`-p 0.0.0.0:6379:6379` 走 nat DNAT→FORWARD→DOCKER，**只加 `iptables -I INPUT` 无效**；须加 `DOCKER-USER` 链（云安全组是第一道）。
- **网络暴露面（已止血待根治）**：prod 曾有无口令 Redis(6379)/MySQL(3306)/6000-6010 公网可达；iptables 已插 INPUT+DOCKER-USER 白名单并 `iptables-save`。根治：容器绑定回环、收敛安全组。

## 5. 任务执行环境注意
- 远程机 SSH：`ssh -i ~/.ssh/id_ed25519_servers <user>@<ip>`（DEV=ubuntu、GATEWAY/PROD=root）。
- 探测端口是否真对外：**勿用本机 `nc`**（沙箱代理假阳性）；从另一台机 `timeout 5 bash -c "cat </dev/tcp/<ip>/<port>"` 实连。
- 跑流水线 lint：`DEV_DB_PASSWORD='web_system_root_2026' node scripts/pipeline-lint.mjs --from-db`（须 `export LINT_SSH_HOST=ubuntu@<dev-ip>`）。
- 历史敏感扫描（只读）：`node scripts/history-secret-scan.mjs`。
