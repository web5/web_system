四种编排范式对比区别只在「下一步由谁决定」

先看这张定范式。四种范式不是并列优劣，而是「控制流放在谁手里」的差异：放在模型手里就有灵活性但难预测，放在代码手里就可控但丧失自主性。

Agent-as-Tool 委派调用链父循环不动，子 Agent 只是一个「特殊工具」

范式定了之后看链路。这张图是主链路图（ai-agent-run-flow.svg）中「递归层」（第 12–15 段，青色虚线框）的放大：子 Agent 走的是普通工具的同一条 execute 路径，所以引擎几乎不用改；真正要新增的是中间那道护栏。

读法：先定范式（图一），再看链路（图二）。落地顺序建议「先补 agent_runs.outcome 质量归因，再上多 Agent」—— 顺序颠倒会得到一堆无法归因的失败：多 Agent 之后，「第几层第几步失败」在当前埋点下完全不可见。
