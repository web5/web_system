# 交互评审 · 小程序对话页「语音输入（按住说话）」长按语义修复

- 关口：**D2/D3**（规格先行 + 落码一致性）
- 规格：`apps/kedou-ai-minigram/prototype/voice-input-spec.md`
- 落码：`apps/kedou-ai-minigram/services/asr.ts`、
  `pages/chat/index/index.{ts,wxml,wxss}`、`tests/asr-hold.test.ts`
- 判据源：`.codebuddy/skills/ux-prototype-designer/references/ux-review-checklist.md`（A–I）
- 评审方式：独立自检（先读判据源再看被审物），2026-10-11

## 背景

真机反馈「点一下麦克风也会弹出录音浮层，并不是长按录音」。
根因是授权异步窗口期（旧实现在 `await` 期间保持 `idle`）让 touchend 无法收尾，
属**手势语义缺陷**，不是视觉问题 —— 故本次走完整规格 + 评审，不适用微调豁免。

## 通过项

- **A 信息架构**：未新增页面/路由，入口挂在既有输入栏，浮层为临时态，不改变 3 层结构。
- **B 任务闭环**：按下 → 说话 → 抬手 → 文本进输入框 → 可编辑 → 发送，闭环完整且可中断（上滑取消）。
- **C 危险动作隔离**：无删除/不可逆动作；取消路径不写任何数据。
- **D 状态可见性**：`preparing / recording / recognizing / 取消中` 四态均有文案与波形区分，
  识别中与准备中用静止波形，避免"看着像在录其实没录"。
- **E 语言与语气**：「准备中…」「松手识别，上滑取消」「按住麦克风说话，松手识别」
  均为动作导向短句，无技术词（未出现 RecorderManager / 授权失败码等）。
- **F 数据诚实**：识别失败、空结果、服务未开通（503）分别给不同文案，
  不把"没听清"伪装成成功；503 明确归为运维侧问题，不误导用户反复重试。
- **G 一致性**：沿用 `.chat-mic` / `.vm-card` 既有控件与 token（`--brand`、`--card`），
  未引入新视觉体系；与微信聊天"按住说话"的既有心智一致。
- **H 可中断/可恢复**：任意时刻上滑可取消；系统打断（touchcancel）与页面卸载均按取消处理，
  `preparing` 态同样可被取消，无"开麦后无人收尾"的悬挂态。
- **I 失败可见**：权限被拒引导去设置；未登录直接拦在 preparing 之前；
  录音 <500ms 归为误触并给出正确用法提示。

## 重要（非阻塞）

1. **授权结果按会话缓存**（`privacyOk` / `authOk`）：不缓存会导致每次按下都多一轮 await，
   用户感知"按了没反应"。已实现；首次仍需系统授权弹框，由 `preparing` 态兜住。
