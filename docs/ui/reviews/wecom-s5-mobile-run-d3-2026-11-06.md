## 1. 改版背景（为什么不是「微调」）

用户 2026-11-06 18:20 的原始反馈：

> 「你直接这么压缩不太好吧，要是流程再长一点你怎么看，建议流水线详情页这里，流程竖着展示，点击按钮放在上面。
> 只需要当前流程信息，其他信息不需要，其他入口也不需要，如有需要后面再根据移动端场景加。」

对应三条设计决策：

| 反馈 | 落点 | 判断依据 |
|---|---|---|
| 流程竖着展示 | `.timeline` 竖向时间轴：圆点 + 连接线，**节点名与状态分两行** | 横向节点条在 8+ 节点时必然挤压；竖排只往下延伸，与流程长度解耦 |
| 按钮放在上面 | 操作区（返回 / 刷新）固定在状态头之上 | 流程长到需滚动时，底部按钮会滚出视野或遮挡末尾节点 |
| 只留当前流程信息 | 删运行 id / 版本 / 分支 / 触发 / 起止时间；删桌面控制台入口 | 手机上「看懂了就走」优先；排查与动手属桌面场景 |

> 与上一版的关系：上一版把「查看发布结果」从提权里拆出来了（票据域内闭环），方向对；
> 但页面本身仍在承载「桌面控制台的信息量」，这次是**按移动端场景做减法**，不是推翻。

### 3.3 色板与对比度（本轮发现并修复的问题）

浅色白底要求：`--bg:#F7F7F9` / 卡片 `#FFFFFF` / 主文字 `#1A1A1F` / 次要 `#6B7280` / 点缀青 `#0EA5A4` 系。

**发现**：v2 初版沿用旧 token，次要文字用 `#9CA3AF`、进行中用 `#D97706`，实测对比度不达 AA：

| 前景 | 背景 | 实测对比度 | AA（小字 4.5:1） | 处置 |
|---|---|---|---|---|
| `#9CA3AF` | `#FFFFFF` | **2.54** | ❌ | 改 `#6B7280` → **4.83** ✅ |
| `#D97706`（进行中状态文字） | `#FFFFFF` | **3.19** | ❌ | 改 `#B45309` → **5.02** ✅ |

改动落点：`.card h4` / `.state` / `.timeline li.pending .name` / `.disclaimer` / `.timeline li.running .state`。

保留低对比的两处（合规豁免或非文字）：
- `.act:disabled` = `#9CA3AF`：禁用控件，WCAG 1.4.3 明确豁免
- 圆点内 `✓ / ×` 白字在 `#16A34A` / `#DC2626` 上约 3.2:1：属**图形**（非文本），按 1.4.11 需 3:1，达标

其余关键组合：`#1A1A1F` 17.33、`#0F766E` 5.47、`#DC2626` 4.83、`#B45309` 5.02 全部 ✅。

## 5. 防假绿记录（关键，别跳过）

### 5.1 第一次变异是「假绿」，原因不是断言弱

变异动作：`.actions` 加 `position:fixed;bottom:0`（模拟回退到底部），重新构建并部署 → 期望「操作区在顶部」变红。

**第一次跑出 12/12 全绿**。排查后确认：`scp` 只传了 `dist/assets/`，**没有传 `index.html`**，
浏览器加载的还是旧 index 引用的旧 CSS → 页面根本没变，断言自然全绿。

> 教训：资源带 hash 的构建产物做部署验证时，**`index.html` 与 `assets/` 必须同批更新**，
> 只覆盖一半等于「改了产物但没改入口」，出来的绿是假的。
> 与本仓库历史坑同源：`nest build` 增量缓存跳过改动（新文件反而编译），都是「验证的是旧东西」。

### 5.2 第二次变异精准命中

补传完整 `dist/` 后复跑：**11/12**，唯一红项 `操作区在顶部  actionsY=798 headY=56`。
还原代码、重新构建、整目录部署 → **12/12** 恢复。

结论：该断言依赖真实几何位置，不是「元素存在性」的表面检查。
