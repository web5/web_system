# 设计评审 · S4 审批页「审批前查看完整流程」入口（D5）

> 2026-11-06 20:30 · 对应规格 `specs/deploy-console/page-spec-wecom-mobile-run.md` v4（V11–V13）
> 关联台账 #8611 · 产品需求 `14-…技术产品方案.md` §4.4
> 结论：**Design: pass**

## 1. 要解决的问题

审批页详情态（S4）底部只有「驳回」「通过」，S5 入口只在**审批完成后**的结果态。审批人想知道
「这次要发什么、前面几步跑到哪、批完还有几步」——只能先通过才能看，实质是盲批。

真机证据（11-06 20:09–20:12）：三张待审批卡片，用户前两张直接驳回（意见「时机不对」），
第三张才通过。事后确认不是判断失误，是页面上没有查看入口。

## 2. 视觉决策

| 决策 | 选择 | 为什么不选另一种 |
|---|---|---|
| 放在哪 | 「最近节点」卡**内**、节点列表之后 | 放卡片外（独立行或 footer 上方）会变成第三个并列操作，与「驳回/通过」争权重；放卡内则语义连续：「最近节点 → 完整流程」 |
| 什么形态 | 整行 `<button>` + 上分隔线 | 用 `<a>` 会进 tab 序与历史栈，且这里不是跳转到新资源而是页内导航；用 `text-decoration: underline` 的小链接触控面积不够 |
| 什么文案 | 「查看完整流程 →」 | 不沿用「查看发布结果」：审批前还没有结果，用词会误导；也不用「查看详情」，与 S1 详情页混淆 |
| 字号字重 | 13px / 600 | 与 `.act`（顶部操作区）一致，形成「这是次级导航」的一致语言 |
| 颜色 | `#0F766E`（teal-700） | 主按钮是橙 `#F97316`，次级不能用同色；teal 在本产品里已是「跳转类」语义（顶部「返回审批单」同色） |
| 触控面积 | `min-height: 44px`，整行可点 | 第一版用 `padding` 只撑出 **28px**，实测点不准；iOS HIG 底线是 44pt |
| 分隔线 | `1px rgba(0,0,0,.06)` + 上边距 8px | 没有分隔线时，入口紧贴最后一个节点（「发布确认 · 等待你确认 ← 当前」），会被读成节点列表的一部分 |
| 底部留白 | `margin-bottom: -6px` | 卡片本身有 12px 内边距，入口自带 44px 高度会显得下重上轻；负边距把视觉重心拉回 |

## 3. 对比度核验

| 元素 | 前景 / 背景 | 比值 | 结论 |
|---|---|---|---|
| 入口文字 | `#0F766E` / `#FFFFFF` | 5.47:1 | ✅ AA（正文） |
| 分隔线 | `rgba(0,0,0,.06)` / `#FFFFFF` | 约 1.1:1 | 装饰性，不承载信息，不受 AA 约束 |

> 与上一版踩过的坑对齐：`#9CA3AF`（2.54:1）和 `#D97706`（3.19:1）都不达 AA，本入口不用它们。

## 4. 作用域隔离

入口只在 `screen === 'detail'` 分支渲染：

- **结果态**（审批完成后）已有主按钮「查看发布结果」，再出现「查看完整流程」会让人以为是两件不同的事 → 不渲染
- **冷提示页 / 错误页**（无票据、链接过期）没有可看的流程 → 不渲染

样式用 `.more` 独立类，不挂在 `.card` 或全局 `button` 上，避免污染「判断依据」卡与失败卡。

## 5. 与 S5 的联动

本屏（S5）顶栏由 `发布结果` 改为 `发布流程`：现在它服务两个入口（审批前看全景 / 审批后看结果），
标题必须中性。审批前进入时状态头显示「等待审批」（`statusTone = idle`，灰点），
不是「发布失败」（红叉）—— 这点已用 mock 断言锁住。

## 6. 未覆盖

- iOS 企微内置 WebView 真机目视：`min-height` 与 `display:flex` 在旧版 WKWebView 的居中表现
- 超长设备语言（德语/俄语）下「查看完整流程」的换行 —— 本产品仅中文
