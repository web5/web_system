| 原型屏 | 判据 | 结果 |

| S1 详情 | 首屏四要素（环境 / 模块 / 版本 / 提交人）不滚动可见 | ✅ 「判断依据」卡置顶，四项齐全；另加「提交时间 / 分支 / 最近节点」 |

| S1 详情 | 环境徽标（PROD 红 / 非 prod 中性）+ 发布方式徽标 | ✅ `.tag.prod` / `.tag.dev` + `.tag.mode` |
| S1 详情 | 底部双主操作：驳回 / 通过，一屏一组 | ✅ 固定 footer，`ghost` + `primary` |
| S2 prod 二次确认 | prod 不允许一键通过：确认层 + 输入「确认」+ 后端 `confirm=true` | ✅ 输入框非「确认」时按钮 disabled；后端另校验 `confirm`（缺则 400） |

| S3 驳回 | 快捷理由四枚：分支不对 / 版本不对 / 时机不对 / 其他 | ✅ **本轮改齐**（此前误写「分支错 / 版本错」） |

## 本轮据对照修正的两处

| # | 差异 | 处理 |
|---|---|---|
| 1 | 驳回快捷理由写成「分支错 / 版本错」，原型是「分支不对 / 版本不对」 | 改齐原型（文案是审批人与提交人之间的通用语，不该各自一套） |
| 2 | S2 缺「影响全部线上用户 / 网关缓存约 10s / 回滚需再发一次」三条后果 | 补入确认层；prod 放行必须让人看见「影响面 + 生效延迟 + 回滚代价」 |

## 已知偏差（非阻塞，记录在案）

| 偏差 | 为什么不阻塞 |
|---|---|
| S1 状态药丸未显示「已挂起 N 分钟」，只写「流水线已挂起」 | 提交时间已在卡片里，挂起时长不构成判断依据；跨端时钟差反而会误导 |
| S4 未显示「审批人 / 审批时间」，改为「审批单号 + 流水线状态」 | 决策接口只回审批结果与流水线状态，未回审批人；审批人本就是这个操作者自己，信息价值低于「发布有没有继续」 |
| 原型顶部示意为「企业微信 · 返回箭头」导航条，实现为纯标题条 | H5 由企微内置浏览器承载，返回由容器提供，页面再造一个返回键会与容器手势冲突 |
