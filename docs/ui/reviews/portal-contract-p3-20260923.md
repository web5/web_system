## 通过项

- **A 信息架构**：首页 → 上传 → 分析中 → 报告 四步齐全；每步都有回退路径（分析中「取消体检」→ 上传，报告「回到首页」，失败步「返回修改」），无死链；层级 2 层。
- **B 任务流闭环**：主路径全程可点通（选图 OCR / 粘贴 / 示例 → 开始体检 → 报告）；异常分支覆盖 OCR 中、体检失败、报告空态三态。
- **C 状态矩阵**：OCR 中（动点 + 文案）、分析中（动点 + 已生成字数 + 5 步计划）、失败（带原因与两个出路）、空态（「暂无报告数据」+ 重新体检）、完成态（报告 + 右栏原文）齐备。
- **D 操作与确认**：每屏 primary ≤ 1（上传=开始体检 / 报告=继续追问）；破坏性「取消体检」有 confirm 且写明后果（已上传的合同不会保存）；空文本时主按钮 `disabled`。
- **E Token**：全部走 `var(--brand-*)` / `--t1..t4` / `--line` 语义变量，无裸 hex；无 emoji；块间距取 8/16/24，文本域沿用既有 `.ta`（padding 12px）。
- **F 可访问性基线**：输入用 `<textarea>`、操作用 `<button>`；`:focus-visible` 焦点环已在同稿统一（前一轮增量）。
- **G 内容真实性**：示例合同为真实租赁条款（5.1/5.2/5.3/7.2/9.1），与风险信号、关键数字、权益三份数据同源；无 lorem / TBD 堆砌。
- **H 目标端**：桌面 Web，无小程序胶囊 / 移动端元素混入。
- **I 未定义项标注**：对话式体检标「P2 排期」；PDF / Word 不支持在上传区明示并归因 Q11；报告↔原文定位标 Q1 关键词兜底，未静默发明定位能力。

## 质检时发现问题（均已回流）

### 重要 1｜原上传步只有「点选择 / 用示例」，没有粘贴文本框

- 反例：规格写「拖拽图片 / 点击选择 / 粘贴文本」三条路径，但原型上传步只有 drop 区与两个按钮，粘贴路径无处可落——落码时会被前端自由发挥（或遗漏）。
- 判据：清单 B 主路径闭环 + page-spec §3.3 上传口径。
- 处置：原型补「合同文本」卡（textarea + `N / 8000` 计数），OCR 结果与粘贴共用同一处、可手工修改；主按钮随文本空/非空切换 disabled。

### 重要 2｜只有「分析中 → 报告」成功路径，缺失败与空报告

- 反例：PC 体检是长任务（数十秒），失败是必然要有的分支；原原型 1.8s 后必定成功，落码时失败态无稿可依。
- 判据：清单 B 异常分支 + C 状态矩阵（空态 / 错误态要有唯一恢复入口）。
- 处置：新增「体检未完成」步（原因 + 重试 / 返回修改 + 原文不会丢失）与报告空态（「暂无报告数据」+ 重新体检）；演示入口挂原型条「体检失败 / 报告空态」两个按钮（与既有「翻译卡片 / 代码块」同类，不与产品界面混）。

## 建议区

- S1｜原型未模拟「拖入 PDF 被拒」的报错反馈 → 上传区已有文字明示（Q11），落码层补明确报错「本轮仅支持图片 OCR」；不另加演示例。
- S2｜5 步计划中「测算真实年化利率」原型固定 `skip` → 落码同口径（非贷款类即 skip），与原型一致，不动态化。
- S3｜右栏原文在原型是静态高亮 → 落码为关键词回查（Q1 兜底），命中不到不高亮，规格 §3.3 已写明，不伪造定位。
