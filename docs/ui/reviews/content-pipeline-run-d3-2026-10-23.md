# 管线手动运行 + 账号列表接数 + 腾讯文档下线 · D3 实现一致性评审

阻塞: 0

## 范围与证据

三件事在同一个改动包里，都是「自媒体运营」功能组内的既有页面：

1. 发布管线补「立即运行」入口（后端接口 `POST /content/run/:pipeline` 早已存在，缺的是前端入口）
2. 账号管理列表从占位空数组接真实接口 `GET /content/accounts`
3. 腾讯文档从发布目标下拉下线（A5，2026-10-23）

依据原型 `docs/ui/prototypes/admin-media-ops.html`：
- 管线屏操作列加「立即运行」primary 按钮，点击**先二次确认**再执行，结果以
  「采集 / 新入库 / 发布 / 失败」四个数回显；表头操作列宽 140 → 230。
- 管线编辑屏发布目标只留 `wechat_mp`，删掉「腾讯文档目录」表单项，并在下方给出下线说明。
- 账号屏（p11–p16）形态不变，本轮只把数据源从占位换成真实接口。

核对对象：`ContentPipelines.vue`、`ContentPipelineEdit.vue`、`ContentAccounts.vue`、`api/content.ts`，
以及后端 `content-account.service.ts` / `account-credential.service.ts` / `content_accounts` 表。

## 检查结果

| 判据 | 结果与反例 |
|---|---|
| 运行入口与原型同形 | 操作列首位是 primary「立即运行」，与原型一致；不是页头全局按钮（全局会让人误以为是"跑全部管线"） |
| 真发布必须二次确认 | `a-popconfirm` 文案明写「会按发布目标真实投递内容（草稿或正式发布取决于该管线的发布模式）」——把"点了会真发出去"说在前面 |
| 结果四数可区分 | 成功提示为「采集 N · 新入库 N · 发布 N · 失败 N」；只回"成功"会让"跑了但没数据"和"跑了且发出去了"长得一样 |
| 防重复点击 | `runningCode` 单飞：点过的按钮转圈，其余按钮 disabled；管线运行是 20–60 秒的长任务 |
| 权限收窄 | 运行按钮仅 `content:manage` 可见（与新增/编辑/删除同级），查看者看不到 |
| 空体请求不踩 #428 | `runPipeline` 与既有 `republish` 一样传 `{}` 而非 `null`——axios 会把 null 序列化成裸 `null` 字符串，网关 body-parser strict 模式直接 400 |
| 账号列表形态不变 | 列表接真实数据后，加密说明条 / 筛选 / 7 列 / 空态 / 失败重试全部保留；只把顶部提示条从「接口建设中」改为「只读注册表 · 写操作待接入」，不假装已完成 |
| 凭据只回掩码 | 接口 VO 不含密文字段，只有 `credentials_mask` + `has_credentials`；页面掩码列逻辑不变 |
| 下拉只剩公众号 | 编辑页 `PLATFORMS` 只留 `wechat_mp`；列表/明细/成文三处的 `tencent_docs` **显示映射保留**——历史记录仍带该 target，删映射会变成裸值 |
| 无裸色值 / 无 emoji / 无红线词 | 沿用 antd token 与既有 `var(--*)`；文案无 emoji；无 R3 红线词 |

## 未覆盖（须人工复验）

- 真实运行时长与体感：原型用 1.2 秒模拟，实际 20–60 秒，前端只有按钮 loading，没有进度条
- seed 之后账号列表是否真的出现「大橙子社区」一行（依赖 dev 库建表 + key 文件 + seed 执行）
- 未配置 `ACCOUNT_CRED_KEY_FILE` 时的页面表现：列表应正常（不解密），只有写操作才报错——本轮无写操作接口，故未验证
- 管线目标仍为 `tencent_docs` 的存量数据：重发会给明确 400，但列表页那条记录仍显示「腾讯文档」，需在 dev 上确认存量是否有此类记录

## 原型 → 实现的已知偏差

- 原型用 `confirm()` + toast 演示；实现用 `a-popconfirm` + `message.success`（antd 同族组件，形态一致）
- 原型结果数是写死的 `12 / 3 / 1 / 0`；实现取后端 `RunResult` 真实四数
- 原型编辑屏用多选 `select` 展示发布目标；实现沿用既有 `a-select` 多选组件，仅选项减少

## 结论

三处改动与已确认原型一致，无阻塞项（`阻塞: 0`）。数据链路与存量数据缺口已在页面与本文档显式标注，
不构成实现一致性偏差。
