## 质检时发现问题

### 重要 1｜发现页在落码侧仍是占位态，收口后会断掉两个已落地能力的入口

- 反例：规格 §3.1 原写「发现 / 实验室为占位态路由」，而 `views/Discover.vue` 至今是 `WorkPlaceholder`。收口后顶栏不再直达 `/translate` `/contract`，**发现页是唯一入口**——占位态会让两项已落地能力失去入口。
- 判据：清单 A「每个入口可达、无死链」+ B「主路径闭环」。
- 处置：规格 §3.1 从占位态升为落地口径（卡片可点直达 + 未开放卡 Toast + 空态出口）；落码同步实现 `Discover.vue` 卡片网格（数据源仍写死，归因 Q3 / B2）。

### 建议区

- S1｜原型能力卡片是 `<div onclick>`（原型阶段允许）→ 落码须用 `router-link` / `<button>` 语义，保证键盘可达（清单 F）。
- S2｜原型在 `/translate` `/contract` 仍显示左栏「翻译记录 / 体检记录」（未来态），落码当前隐藏（待后端 `source=tool` 过滤）→ 已知差异，规格 §3.2/§3.3 已注明，不作为阻塞。
- S3｜能力页页头不再另设「返回发现」按钮（顶栏已高亮且可点），避免与顶栏重复出口。
