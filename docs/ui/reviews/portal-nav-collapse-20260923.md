## 通过项

- **A 信息架构**：顶栏由 6 项收为 4 项（开始 / 对话 / 发现 / 实验室）；翻译、合翻**经发现页可达**，返回路径 = 顶栏「发现」，无死链、无跳转环；层级仍为 2 层（发现 → 能力页）。
- **B 任务流闭环**：发现 → 能力工作台 → 顶栏回发现，主路径闭环；异常分支：未开放能力点击给 Toast「该能力尚未开放」（不是灰字死卡）。
- **C 状态矩阵**：发现页加载骨架 / 空态 / 失败态由原型全局状态开关覆盖，完成态反馈 = 页面跳转。
- **D 操作与确认**：发现页无 primary 按钮（卡片即入口），一屏 primary ≤ 1；本改动无破坏性操作。
- **E Token**：未引入新样式，沿用既有语义变量；无 emoji。
- **G 内容真实性**：能力卡片名称与说明沿用既有文案（语言翻译官 / 合同翻译官（合翻）/ 论文速读 / 文案改写），无占位堆砌。
- **H 目标端**：桌面 Web，顶栏为桌面横向 tab，无跨端元素。
- **I 未定义项标注**：能力卡片数据源写死已归因 Q3 / 后端 B2；顶栏高亮归属（`parent`）为本次新增口径，已在 §1 写明。

## 质检时发现问题

### 重要 1｜发现页在落码侧仍是占位态，收口后会断掉两个已落地能力的入口

- 反例：规格 §3.1 原写「发现 / 实验室为占位态路由」，而 `views/Discover.vue` 至今是 `WorkPlaceholder`。收口后顶栏不再直达 `/translate` `/contract`，**发现页是唯一入口**——占位态会让两项已落地能力失去入口。
- 判据：清单 A「每个入口可达、无死链」+ B「主路径闭环」。
- 处置：规格 §3.1 从占位态升为落地口径（卡片可点直达 + 未开放卡 Toast + 空态出口）；落码同步实现 `Discover.vue` 卡片网格（数据源仍写死，归因 Q3 / B2）。

### 建议区

- S1｜原型能力卡片是 `<div onclick>`（原型阶段允许）→ 落码须用 `router-link` / `<button>` 语义，保证键盘可达（清单 F）。
- S2｜原型在 `/translate` `/contract` 仍显示左栏「翻译记录 / 体检记录」（未来态），落码当前隐藏（待后端 `source=tool` 过滤）→ 已知差异，规格 §3.2/§3.3 已注明，不作为阻塞。
- S3｜能力页页头不再另设「返回发现」按钮（顶栏已高亮且可点），避免与顶栏重复出口。

## 补充质检 · 返回路径（2026-09-23 用户实测后）

### 重要 2｜收口后能力页只剩顶栏「发现」可回，实测用户找不到回去的路

- 反例：本次收口把翻译 / 合翻从顶栏拿掉，返回只依赖顶栏「发现」按钮；用户实测反馈「发现进去之后，没有返回发现页面的地方」——说明**顶栏高亮是归属提示，不能当返回用**。
- 判据：清单 A「每个入口可达、**有返回路径**、无死链」+ B「主路径闭环」（去程有了，回程没有）。
- 处置（第一轮）：页头面包屑「‹ 发现 › 能力名」——**被用户驳回**：「没有创意，偏 admin 风格，这是 C 端用户」。
- 处置（终稿）：改为**能力切换器**（C 端场景/模型切换器形态）——页头一枚能力胶囊（图标 + 能力名 + ▾），点开浮层：
  ① 切换能力列表（当前项 ✓ 高亮；未开放项可点给 Toast「该能力尚未开放」）
  ② 底部「查看全部能力 ›」→ `/discover`
  一个控件同时解决「换能力」与「回发现」，且不带后台层级感；全步骤常驻（合翻四步）。
- 落码约束：胶囊与浮层项用 button 语义（键盘可达）；能力清单与发现页卡片同源（`config/capabilities.ts`），避免两处漂移。

### 位置修正（用户二次反馈）

- 反例：页头胶囊仍被判为「不在该在的位置」——用户要的是**左栏分区**：「放到翻译记录左侧面板的下面，或者直接把左侧面板分成两部分，下面少部分展示功能」。
- 处置（终稿·位置）：能力区移到**左栏下半区**（上 = 记录列表，下 = 能力，少部分高度 `max-height:34%` 自带滚动）：
  - 记录区可用（开始 / 对话）→ 上下分区；记录区不可用（翻译 / 合翻，待 `source=tool` 接口）→ 能力区占满左栏（不留空壳列表）
  - 发现 / 实验室不挂能力区（中栏已是能力网格，避免重复）
  - 未开放能力仍可点给 Toast；底部「查看全部能力 ›」→ `/discover`
- 页头胶囊实现已从原型移除（不留两套）。

### 重要 3｜能力面板高度按百分比切、会把记录区空态压掉（用户实测）

- 反例：能力区用 `max-height:34%` + 自带滚动，记录列表只剩 66%；当记录为空（新用户 / 工具页无记录）时，
  空态文案被压在极小区域里，用户感知成"记录没了"（2026-09-23 实测反馈）。
- 判据：清单 C「空态要有唯一恢复入口且可见」+ E「间距/层级不打架」。
- 处置：能力面板改为**高度固定**（不是百分比——按内容：默认 2 项 + 底部入口）、**钉在左栏底部**
  （`margin-top:auto`）、不随列表滚动；**默认只展示 2 项已启用能力**，其余不展开，统一收进
  底部「更多 N 项 · 查看全部 ›」→ `/discover`；记录区不可用时（`solo`）面板从顶部开始。
- 落码约束：能力区不再设 `max-height` / `overflow-y:auto`；列表区保持 `flex:1` 占据剩余空间。
- 用户补充口径：「更多 N 项」**就地展开**（不跳发现），展开后变「收起」，含敬请期待项；「查看全部能力 ›」另保留为跳发现的独立入口（两个入口职责不同：展开 = 看清单，查看全部 = 去发现页）。
