## 通过项

- **A 信息架构**：挂在既有「基础设施」分组下，2 层结构不变；新增菜单项与路由
  `/cleanup-scan` 一一对应，无孤儿路由、无死链。
- **B 任务闭环**：首页就能完成「跑一次 → 看结论 → 点开看候选」的完整闭环，
  不需要先去别处配参数；环境/模块这两个远端参数就地给，不跳转。
- **C 危险动作隔离**：页面零删除入口；顶部 alert 明写「本页只观测，不删除」，
  并把真正的开关指向环境变量 `RETENTION_ENABLED` / `REMOTE_CLEANUP_ENABLED`。
  「看」与「删」物理分离 —— 这与「随手可点的入口绝不能删东西」是同一条硬约束。
- **D 状态可见性**：初始加载 / 运行中 / 成功 / 失败 / 空态 / 截断 / skipped
  共 7 种状态均有表现（见原型 §4 状态矩阵）；运行中按钮 loading 且不可重入，
  避免并发跑批污染候选口径。
- **E 语言与语气**：结论标签用「只观测 / 已删除 / 跳过 / 出错」，不用英文枚举直出；
  空态文案带安抚信息「不会删任何东西」，对运维场景是必要的。
- **F 数据诚实**：候选超 300 条截断后显式挂 warning，而不是静默截断；
  未扫描到条目记为 `skipped`，不与「0 候选 = 一切正常」混淆 —— 这两条都是
  「不许假装完整/干净」的具体落点。
- **G 一致性**：Card / Table(10 条分页) / Drawer(720) / Descriptions(2 列 bordered) /
  message 全部沿用 console 既有组件与尺寸，未引入新视觉规范，学习成本为零。
- **H 可对比性（本页存在的前提）**：历史表格保留 巡检时间 / 类型 / 环境 / 候选 / 已删，
  使得「连续观察 7 天」后能横向对比同一维度数字是否稳定 —— 这正是本页要解决的事，
  如果记不下这些列，页面就没有存在价值。
- **I 降级取舍**：环境列表拉取失败只让下拉为空、不阻断远端巡检；写库失败只告警不抛。
  留痕类能力挂掉不应拖垮巡检本身，与审计日志同一取舍。

## §重要（1 项，已回流处置）

1. **重要性分层不清晰**：初版两个跑批按钮中，远端巡检（带环境副作用）若也用
   primary，会造成「默认动作 = 扫生产」的误触风险。
   处置：primary 只留给无参的数据保留巡检，远端巡检降级为 default 按钮，
   并把环境/模块选择紧邻其左侧，让「扫哪个环境」在点之前就必须被看见。
   已回流进原型 §3.2 与落码。
