# 自媒体运营模块（原「内容采集源」）UI 一致性检查

阻塞: 0

## 范围与证据

本次把单页三 Tab 的「内容采集源」重构为「自媒体运营」功能组（五个子页），新增试采能力。
依据原型 `docs/ui/prototypes/admin-media-ops.html` 与
`docs/ui/prototypes/admin-media-ops-设计决策记录.md`（Q1–Q8 已由需求方逐项拍板，原型口头确认「可以了」）。

本报告记录执行者的实现一致性自查。原型为静态 HTML（无浏览器自动化证据链），
交付保持草稿 PR，仍须人工在 dev 环境逐屏复验后合入。本轮不因此绕过合入/部署/真实页面复验门。

## 检查结果

| 判据 | 结果与反例 |
|---|---|
| 菜单结构与原型一致 | 侧边栏「内容采集源」单项 → 「自媒体运营」sub-menu，五子项；非新增顶层入口（与 Agents sub-menu 同构） |
| 路由层级与菜单同源 | `/content/*` 树与菜单 key 一一映射，`watch(route.path)` 分支已覆盖五个子页；无「菜单亮着但路由 404」 |
| 试采仅预览不入库 | 前端结果面板常驻「仅预览 · 未入库」徽章；后端 `POST /sources/test` 零副作用，由 9 个单测锁定（persist / collectLog 一次都不碰） |
| 试采读当前表单配置 | 未保存也可测；config JSON 不合法时先拦提示再发请求（不把脏配置发给后端） |
| 触发弹窗五态 | 成功/空/失败/拒绝/未接入五态各有文案，技术原文折叠在「技术详情」里，不直接糊在结果区 |
| 明细/成文走服务端分页 | 两处均传 limit/offset 与筛选参数，分页器 showTotal 显示真实总量；非前端切片 |
| 成文预览文章级聚合 | 预览抽屉区分 payload（发布留存）与 aggregated（按管线 + 发布日期重建）两种来源并在元信息行标注；未新增文章表 |
| 权限分级 | 页面 `content:view`；写操作（新建/编辑/删除/启用/触发/试采/重发）`content:manage`；admin 及以上由 `ROLE_PERMISSIONS` 全量继承，符合「管理员默认也有」 |
| 破坏性操作有确认 | 删除走 `a-popconfirm`；启用开关在只读权限下 disabled |
| 无裸色值 / 无 emoji | 沿用 antd token 与既有 `var(--*)` 变量，未引入 hex/rgba 硬编码；文案无 emoji |

## 未覆盖（须人工复验）

- 试采三态的真实后端返回（arxiv 上游可达性、rss 配置错误、空结果）依赖 dev 真实数据
- 成文预览在历史记录（2026-10-22 前、无 payload）上的聚合重建效果
- failed 成文重发：仅当发布记录留存 payload 时按钮可用，历史记录按钮置灰并给出原因
- 403 无权限态：原型未演示，实现沿用既有 `/403` 路由

## 原型 → 实现的已知偏差

- 原型的「演示切换器」实现为真实三态（后端返回驱动），原型中仅为演示
- 原型 `/content-sources` 单页在保留为列表页的同时拆走 Tab；编辑迁到独立页 `/content/sources/:id`
- arxiv / rss / hackernews 的告警条文案：原型写「暂不支持手动触发」，实现因 Q2 已补接入，改为「由定时管线自动采集」并引导试采
