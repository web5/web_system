# 科豆 AI · 页面规格书模板（Page Spec）

> 版本：v0.2（2026-10-22：补「原型继承」节——分支清单以原型演示控件场景包为单一来源）｜ 日期：2026-09-03（初版）
> 配套：《design.md》（判断层，先读它再填本规格）。
> **强制规则（2026-09-03 用户确认）：所有 UI 任务生成代码前必须产出本规格并经用户过目，禁止直接开写。**

---

## 0. 使用流程（强制顺序，不许跳步）

```
UI 任务需求
  → ① AI 判定页面类型 + 点名参照页（design.md §1）
  → ② 填本规格书（新页/大改用 Full 模板；小改用 Quick 模板）
  → ③ 用户过目（预期 30 秒内），可当场批注
  → ④ 用户确认后 AI 才写代码
  → ⑤ 写完后按 design.md §5 自检 + 截图基线 + 回流记录
```

- **新页面 / 布局级大改 / 交互重构** → Full 模板（下节）。
- **小改**（增删一列、改个状态色、调整按钮文案等）→ Quick 模板（第 2 节），仍须用户过目。

## 1. Full 模板

```markdown
## 页面规格书 · <页面名>

- 页面类型：<列表页|详情页|表单/向导页|仪表盘/监控|登录/例外>
- 参照页：<design.md §1 表内真实页面，多个则注明主参照>
- 需求一句话：<你理解的这个页面解决什么>

### 页头
- 标题：<h1 文案>
- 副标题：<一句话说明，选填>
- 主操作：<无 | 按钮文案 + 动作>（primary ≤ 1）

### 模块清单（自上而下，每个模块一行）
| 序 | 模块 | 数据来源/API | 承载组件 | 空态策略 | 备注 |
|---|------|-------------|---------|---------|------|
| 1 | <如：统计卡> | <如：GET /api/xxx> | <如：a-row 3 卡> | <如：显示 -- > | |
| 2 | <如：筛选条> | — | <字段清单> | — | |
| 3 | <如：数据表格> | | <列清单 + 操作列> | <原因+出路> | |

### 表格/列表列清单（数据页必填）
| 列 | 来源字段 | 展示规则（mono/tabular/时间格式/状态色） | 操作 |
|----|---------|----------------------------------------|------|

### 交互清单（每条操作一行）
| 操作 | 触发 | 反馈（成功/失败） | 是否破坏性→确认文案 | 完成后动作 |
|------|------|------------------|--------------------|-----------|
| <如：重启> | 行内按钮 | success/error message | Modal.confirm"重启会中断服务约 N 秒" | 刷新列表 |

### 状态覆盖自查（design.md §3，逐项勾）
- [ ] 加载中（loading）
- [ ] 空态（原因+出路）
- [ ] 失败可重试
- [ ] 破坏性二次确认
- [ ] 禁用有 tooltip 原因
- [ ] 保存中防重复提交
- [ ] 无弹窗套弹窗

### 原型继承（有原型稿时必填，2026-10-22 起）

> 原型稿 → 规格书不许「看着写」：**分支清单以原型演示控件的场景包为单一来源**，漏一个场景 = 漏一个分支。
> 控件规格见 `~/workspace/ai-agent-kit/skills/ux-prototype-designer/references/demo-control-panel.md`。

| 继承项 | 从原型稿抄什么 | 规格书怎么写 |
|---|---|---|
| 目标端 / 壳 | 稿头「目标端」 | 端 + 布局壳（如 admin BasicLayout / 移动竖屏壳） |
| **场景包 → 分支矩阵** | 控件里每个场景包（角色 × 屏 × 数据态） | 一行一个场景：路由 + 权限码 + 数据态 + 期望结果；**原型有几个场景包，这里就必须有几行** |
| 状态矩阵 | 五态 `normal/loading/empty/error/forbidden` | 每态对应组件 + 唯一出路口（重试/新建/申请权限），不许只写「显示空态」 |
| 角色可见性 | 控件角色切换下的菜单/按钮差异 | 写成权限码（`content:view` 看 / `content:manage` 改），并注明菜单项与页内操作分别怎么控 |
| 平台能力占位 | 原型里标「真机为准 / 原型模拟」的项 | 真机/真实实现方式（如微信授权、支付回调），不许留在「占位」状态 |
| 控件本身 | — | **不进实现**：演示控件是评审台，落地不搬 `data-demo-*`、不搬场景包 |

### 风险/待澄清
- <数据字段缺失、接口未就绪、跨权限等——没想清楚不许进实现>
```

## 2. Quick 模板（小改）

```markdown
## 迷你规格 · <改动点>
- 页面/组件：<路径>
- 类型与参照：不变（原页面） / <若变，说明>
- 改动内容：<精确到字段/样式/交互点>
- 涉及 Token：<--ws-* 或 antdToken 名；禁裸值>
- 交互影响：<无 / 需补状态矩阵某格>
```

## 3. 填写规则（什么算通过）

1. 类型判定 + 参照页必须先写——AI 写不出参照页 = 还没想清楚，不许进代码。
2. 所有颜色/圆角/字号只写 Token 名（`--ws-text-primary` / `uiTokens.radius.md`），**规格书里出现裸 hex 即打回**。
3. 交互清单必须覆盖"成功 + 失败 + 破坏性确认"三行，空态策略列不许空。
4. 模块清单顺序即页面自上而下顺序，用户改顺序 = 改布局，在批注阶段完成，不进代码后返工。
5. 表格列清单要写展示规则（mono/tabular/状态色语义），列取舍与排序在规格书阶段定死。
6. **有原型稿时，原型继承表必填**：原型演示控件的每个场景包都要在规格书里有一行（路由 + 权限码 + 数据态 + 期望结果）；场景包数 ≠ 规格行数即视为漏分支，打回。控件本身（`data-demo-*`、场景包）不进实现。
