R6 落地 · 8 个待确认点（依据 design.md §3.1，D-a/D-b/D-c 已定）
#问题原型默认方案（待批注）
1产物命名空间形态 modules/<模块>/<流水线key>/<commit>（目录分层，gateway/nginx 零改动）
备选：modules/<模块>/<流水线key>-<commit>（单层，改动更小但层级语义弱）
2「流水线 key」字段 模板新增 key（slug，^[a-z0-9-]{1,32}$，全局唯一）；内置默认线 = default。已是通用模板则新建时必填
3流水线 key 改名 允许改，但历史产物仍按旧 key 目录存在（旧版本仍可回滚）；改名后需提示"新产物落在新命名空间"
4默认线的模块差异 命令内 {MODULE_*} 变量 +「按模块预览」（本屏演示），不内置 case 分叉模板；差异大就复制专用线
5模块页「阶段命令」tab 整体移除（本屏演示）：改为一条提示 + 「查看引用本模块的流水线」跳转；不保留只读总览
6回滚候选组织 按流水线命名空间分组（本屏演示）+ 独立 legacy 组；不做跨组混合排序
7历史产物（无流水线段） 保留为 legacy 命名空间：可切指针回滚、不再新增；清理保留数按命名空间各自计（保留 5）
8迁移：现有模块命令去哪 为每个「已配命令」的模块自动生成专用线（模块 ↔ 专用线一一对应，语义等价）；未配模块走默认线
相对 v5 原型的变化（旧口径作废）
v5 原型里的东西本版处理
节点配置的「作用模块」下拉取消：命令是流水线的属性，不再需要模块坐标
「N 个模块仍配置了已移除节点脚本」孤儿提示（v5 决策 3）作废：命令随节点走，删节点即删命令，不存在孤儿
脚本编辑器标题「读写模块 × key」改为「本流水线 · 节点 key」，key 在本流水线内唯一
交互演示提示（体验重点）
① 点 构建 等 script 节点 → 下方出现「命令归属本流水线」+ 多操作序列编辑器（增删操作 / shell 与内置工具互切 / 单操作超时与容错）。
② 在命令里插入 {MODULE_TYPE} 等变量 → 用「按模块预览」看替换结果（全局线服务多模块时的差异表达）。
③ 侧栏「提交流水线」→ 改模块 / 流水线 / commit，产物与版本身份预览实时变化（目录 / URL / 指针值）。
④ 侧栏「模块页」→ 看「阶段命令」tab 移除后的信息去向（提示条 + 跳转）。
⑤ 侧栏「版本与回滚」→ 按流水线命名空间分组 + legacy 组；点「切到此版本」看破坏性确认文案。
