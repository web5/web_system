## 二、决策记录（D1–D7）

- **D1 不设 primary 操作**：用户详情页主操作是「保存用户信息」，「重新生成摘要」一律 secondary（表单规范 v1.3：同屏唯一主按钮）。
- **D2 删除确认形态**：用气泡（popconfirm 形态）不用 Modal——page-spec 状态覆盖自查明确「无弹窗套弹窗」；确认文案照抄 page-spec 交互清单原文「删除后 AI 将不再使用这条记忆，确定删除？」。
- **D3 删除后的摘要一致性（v1 口径）**：摘要由 LLM 从明细重算、下次对话后才刷新，UI 必须显式标「待更新」+ 说明文案，不能让用户以为摘要已同步。page-spec 已定此口径（备选「删后立即 refresh」留 v2 评估）。
- **D4 摘要与明细状态解耦**：skeleton / error / 重试各自独立，互不阻塞（S5 可验：摘要重试后明细仍 error）。page-spec 状态覆盖自查「摘要卡与明细表各用独立 skeleton」的自然延伸。
- **D5 场景包切换条**：S1–S6 置于稿头下方虚线区，标注「原型演示控件，不进实现」——沿用 admin-media-ops 的演示控件惯例，与业务 UI 隔离。
- **D6 明细分页**：原型画每页 8 条 + 页码（演示口径）；实现按 API 分页参数走，不在原型锁死。
- **D7 分类三色**：fact=蓝 / preference=紫 / habit=绿（page-spec 列清单指定），三色均为浅底深字（对比度按 AA 档选值），token 收在本稿 `:root` 局部扩展（`--cat-*`），不污染全局。
