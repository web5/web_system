## 二、决策记录（D1–D5）

- **D1 页头口径**：标题「记忆画像」副标题「AI 记住的关于你的信息」+「重新生成」**文字型链接按钮**（page-spec 页头规范；portal 轻量风格，不用实心按钮）。
- **D2 摘要卡形态**：轻量卡片（非 antd），与 portal 现有卡片风格一致；元信息行只放 条数 · 更新时间（page-spec portal 模块清单不设版本/复制——那是 admin 审计诉求）。
- **D3 删除补二次确认**：现有 Memory.vue 删除为**直删**（无确认）。page-spec 交互清单把删除定性为破坏性（「确定删除这条记忆？」）。原型按确认流画——这是对破坏性的**补齐**而非「现有交互退化」（分组形态 / 删除入口 / 反馈文案均不变）。**实装卡 2.3 需补一个确认步骤**，已在 page-spec 回填登记。
- **D4 待更新标注**：与 admin 同口径（v1：摘要 LLM 下次对话后重算），删除成功后画像卡标「待更新」+「将在下次对话后刷新」。
- **D5 场景包**：S7 有画像 / S8 无画像（引导文案 + 可点重新生成）/ S9 加载失败（内联 error + 重试，画像与分组独立）。

## 三、遗留项（实装时处理）

1. 删除确认的组件选型：实现可用 `a-popconfirm`（portal 已引 antd-vue）或自定义气泡，形态对齐本稿即可。
2. 摘要正文同样必须转义渲染（LLM 半可信输入）。
3. 画像与分组两个接口独立加载失败时的重试互不阻塞（本稿已演示），实现按两请求分开处理。
