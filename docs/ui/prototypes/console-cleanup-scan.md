# 原型与规格 · 部署控制台「清理巡检」页

> 对象：`apps/deploy-console/src/views/CleanupScan.vue`（新增页）
> 配套后端：`servers/deploy-console/src/reconcile/cleanup-scan*.ts`、`entities/deploy-cleanup-scan.entity.ts`
> 落码口径见文末「§5 落码口径」

## §1 页面定位

一句话：**只回答「如果现在开清理开关，会删掉什么」，本身一条都不删。**

背景是诊断 #18（库表数据保留）与 #10（远端版本目录产物）两个清理能力都支持
「只观测不删除」，但结论此前只出现在接口响应与日志里 —— 关掉页面就没了。
于是「连续观察 7 天再决定开不开开关」这件事实际上做不到：每天的数字都得靠人
手工抄，7 天后无从对比。本页就是给这若干天提供可对比的记录。

非目标（明确不做）：

- 不提供任何删除入口，页面里没有「清理」「删除」「立即执行」按钮；
- 不替代保留策略配置页，本页只读 + 触发一次观测；
- 不展示删除后果的模拟推演，只展示最近一次真实巡检的候选。

## §2 信息架构

```
基础设施
├── 服务监控
├── 环境管理
└── 清理巡检        ← 新增（路由 /cleanup-scan，菜单「清理巡检」）
```

层级仍为 2 层（左侧菜单 → 单页），无新增嵌套、无新弹窗栈。

## §3 区块与字段

### 3.1 顶部说明（a-alert · info）

红色线：**「本页只观测，不删除」**。正文说明真正的删除开关是环境变量
`RETENTION_ENABLED` / `REMOTE_CLEANUP_ENABLED`，与页面动作物理隔离。

### 3.2 操作区（a-card「巡检记录」上方 a-space）

| 元素 | 类型 | 说明 |
| --- | --- | --- |
| 跑一次数据保留巡检 | primary button | 无参数，loading 态 = `running === 'retention'` |
| 环境选择 | select | 仅作用于远端巡检，默认落到列表最后一个环境 |
| 模块 key | input | 留空 = 该环境全部模块（由指针表发现） |
| 跑一次远端产物巡检 | default button | loading 态 = `running === 'remote'` |

primary 只给「数据保留」这一个无参、无环境副作用的高频动作；远端巡检要选环境，
降级为普通按钮，避免「随手点 primary 就扫了生产」的误触。

### 3.3 筛选区（card #extra）

- 类型：全部 / 数据保留（库表）/ 远端产物（版本目录）
- 环境：全部 / 各环境
- 刷新

### 3.4 历史表格

列：巡检时间 / 类型 / 环境 / 组件·维度 / 结论 / 候选 / 已删 / 操作人 / 操作（详情）
分页 10 条，row-key = id。

结论（status）四种标签：

| status | 标签 | 颜色 |
| --- | --- | --- |
| dry-run | 只观测 | blue |
| deleted | 已删除 | orange |
| skipped | 跳过 | default |
| error | 出错 | red |

另有一枚 `未删除` 绿标签（dryRun 为真时同时出现）—— 两枚标签叠在一起是为了让
「这条记录没有产生副作用」这件事在表格里一眼可见，而不是要点开详情才知道。

空态文案：`还没有巡检记录 —— 先跑一次（不会删任何东西）`。

### 3.5 详情抽屉（width 720）

- a-descriptions（2 列 bordered）：类型 / 环境 / 组件·维度 / 操作人 / 候选总数 / 实删数 / 巡检时间 / 结论 / 说明（跨 2 列）
- 分维度汇总表：维度 / 候选 / 已删 / 受保护 / 扫描到 / 备注
- 候选清单：tag 流式列表，容器限高 320px 可滚；超过 300 条被截断时，下方挂 warning alert 明说「已截断」，不许假装完整

## §4 状态矩阵

| 状态 | 表现 | 处理 |
| --- | --- | --- |
| 初始加载 | 表格 loading | 拉取环境与最近 100 条记录 |
| 巡检运行中 | 对应按钮 loading 且不可再点 | 防止并发跑批互相污染候选口径 |
| 巡检成功 | message.success 报「候选 N 条（未删除）」 | 自动刷新列表 |
| 巡检失败 | message.error 错误文案 | 保持旧列表，不置空 |
| 环境列表拉取失败 | 环境下拉为空，远端按钮仍可用 | 降级不阻断，与审计同一取舍 |
| 无记录 | a-empty 引导文案 | 引导跑第一次 |
| 候选被截断 | 抽屉内 warning alert | 明示截断条数与上限 |
| 未扫描到条目 | status = skipped（不是「0 候选、一切正常」） | 与真·干净区分开 |

## §5 落码口径

1. 观测入口只有 `scan`，没有 `cleanup` —— 前端无删除调用、后端编排服务只调
   `remote.scan`，这条在单测里写死；
2. 候选清单截断上限 300，落库时记标记；
3. 写库失败只告警不抛（留痕挂了不该让巡检跑不了）；
4. 受保护版本口径复用 `RetentionService.protectedVersionKeys`，避免两处漂移；
5. 样式沿用 console 既有 Card / Table / Drawer / Descriptions / message，不引入新视觉规范。
