原型说明 · 设计决策记录
目标端：桌面 Web（deploy-console 管理台，admin 系规范，主橙 #F97316）

核心决策：
1. 部署与发布流水线解耦：独立「版本部署」界面，选已有版本直接部署，不进流水线执行记录；
2. 前端/微前端 = 切版本指针（复用现有 switchVersion / deployVersion 改指针能力）；
3. 后端服务 = 换产物目录 + 重启 pm2（复用现有 deployVersion 的 applyBackendVersion），确认弹窗写明中断后果；
4. 环境为页面主导筛选维度 → tabs；版本选择在抽屉内 radio 列表。

待拍板：
① 导航归属：微前端/API 网关两域各挂「版本部署」入口（本稿画法） vs 单独一级域；
② 应用详情「部署」按钮从跳流水线改为本抽屉（本稿屏 2 示意）是否一并改。

这是什么稿

  • 需求：微前端/API 网关服务的「部署」不再跳发布流水线，单独界面选已有发布版本直接部署。
  • 数据：版本列表来自 deploy_versions（流水线发布时写入）；部署动作走现有改指针接口。

评审动线（按顺序点）

  • 1. 表格行点「部署」→ 打开版本抽屉
  • 2. 选版本 → 「部署到 dev」→ 二次确认 → loading → 成功 toast + 当前版本更新
  • 3. 左侧切「API 网关 · 版本部署」→ 后端服务部署（确认弹窗含重启警告）
  • 4. 环境 tab 切「local」→ mcp-admin 空态 / portal 错误态
  • 5. 左侧「应用管理」→ 应用详情「部署」按钮入口改造示意

待确认项

  • ① 导航归属：双域入口 vs 独立一级域
  • ② 应用详情「部署」入口是否一并改
  • ③ 后端服务「选版本直接部署」是否开放（涉及重启）
