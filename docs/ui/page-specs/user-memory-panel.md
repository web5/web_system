# 页面规格书 · 用户记忆面板

- 页面类型：详情页内的嵌入面板（admin）+ 独立列表页内的嵌入卡片（portal）
- 参照页：
  - admin 主参照：`apps/admin/src/views/UserDetail.vue`（现 349 行，已有 `a-card` 分组结构：基本信息 / 头像信息）
  - admin 次参照：`apps/admin/src/views/UserList.vue`（列表页的表格与操作列范式）
  - portal 主参照：`apps/portal/src/views/Memory.vue`（现 187 行，已有 category 分组渲染 + 删除交互）
  - portal 次参照：`apps/portal/src/views/Profile.vue`
- 需求一句话：**让「AI 记住了用户什么」这件事可见、可查、可纠错** —— 摘要是给 Agent 用的画像，明细是给人看的审计记录。

## 交互清单（每条操作一行）

### admin 端（v1.1 只读：只有查看与读操作）

| 操作 | 触发 | 反馈（成功/失败） | 是否破坏性→确认文案 | 完成后动作 |
|------|------|------------------|--------------------|-----------|
| 查看摘要 | 进入用户详情页自动加载 | 加载中 `a-skeleton`；成功渲染；失败 `a-result status="error"` + 「重试」按钮 | 非破坏性 | 不变 |
| 查看明细 | 展开「明细（N）」折叠面板 | 加载中骨架；成功渲染表格；失败行内 error + 重试 | 非破坏性 | 不变 |
| 复制摘要 | 摘要卡右上「复制」图标 | 成功 message「已复制」；失败 message | 非破坏性（读操作） | 不变 |
| 分页浏览明细 | 明细表分页器 | 翻页拉取对应页 | 非破坏性（读操作） | 不变 |

> 🔴 **v1.1 移除的操作**（用户 2026-10-30 15:34 拍板「admin 端只支持查看」）：~~删除单条明细~~、~~重新生成摘要~~、~~空态「重新生成」按钮~~。实现侧不得在本面板渲染任何写操作入口；改记忆的入口在 portal。

### portal 端（v1.1：编辑为新增主交互）

| 操作 | 触发 | 反馈（成功/失败） | 是否破坏性→确认文案 | 完成后动作 |
|------|------|------------------|--------------------|-----------|
| 查看画像 | 进入记忆页自动加载 | 加载中骨架；成功渲染；失败内联 error + 「重试」 | 非破坏性 | 不变 |
| **编辑单条记忆**（v1.1 新增） | 条目 ✏️（hover 显形）→ 行内 textarea | 校验即时反馈（见下）；保存中按钮 `loading`+禁用；成功 message「已保存，AI 下次对话后会使用新内容」；失败 message「保存失败，请重试」且**保留编辑态与已输入内容**；越权/条目已删 message「无权修改该条记忆，可能已被删除」并退出编辑态刷新列表 | 非破坏性（改） | 刷新条目内容 + 摘要卡标「待更新 · 下次对话后刷新」 |
| 编辑校验 | 输入即时校验 | 空 → 「内容不能为空」；>200 字 → 「最多 200 字，已超出 N 字」+ 计数器变红；**校验不过时保存按钮禁用** | — | — |
| 取消编辑 | 「取消」按钮 | 直接退出编辑态还原原文，**不发请求不落改动** | — | 无 |
| **删除单条记忆** | 明细条目 🗑 | 二次确认 → 成功 message「已删除该记忆」；失败 message | 🔴 **破坏性** → 「确定删除这条记忆？」 | 刷新明细列表 + 摘要卡标「待更新」 |
| **重新生成画像** | 「重新生成」文字按钮 | `loading` + 禁用；成功 message「已更新」；失败 message | 非破坏性 | 刷新摘要卡 |
| 空态引导 | 用户无记忆 | 「还没有记忆画像」+「和我说说你偏好什么，我就能记住」 | 非破坏性 | 不变 |

> 🔴 **改/删后的摘要一致性**（v1 口径不变，v1.1 扩展到「改」）：明细被删或被改后，摘要行在**下次对话后**才更新（摘要由 LLM 从明细重算）。UI 上必须在摘要卡上**显式标注「待更新」状态**，不能让用户以为摘要还包含旧内容。
> 备选：改/删后立即触发一次 refresh（更快，但多一次 LLM 调用 + 延迟）。→ **v1 用「标注待更新」**，v2 评估立即刷新。

### v1.1 口径登记（来源：用户 2026-10-30 15:34「admin 端只支持查看，portal 端，用户可以自己改」）

1. **admin 只读**：删除列 / 删除二次确认 / 重新生成摘要 / 空态生成按钮全部移除；读操作（复制 / 折叠 / 分页 / 失败重试）保留。
2. **portal 编辑**：行内编辑，200 字上限（与 admin 明细内容「最长 200 字符截断」同一数值口径）、空值校验、保存 loading 防重复、取消不落改动、保存失败保留输入、越权明确报错；摘要仍不可手改（只能重新生成）。
3. **摘要一致性扩展到「改」**：改或删明细后摘要都标「待更新 · 下次对话后刷新」（v1 只覆盖删）。
4. **连带**：需求单 §四 批次 2 卡 2.2 的验收判据「明细可删；重新生成可点」随本口径**作废**，2.2 实装判据以本页 v1.1 交互清单为准（需 lead 在需求单侧同步）。
