### 0.1 实体口径（用户 2026-09-14 澄清）

```
流水线（发布流程定义）  1 ── N  流水线实例（每次提交/执行一次）
   deploy_pipeline_templates        deploy_pipelines
   · 名称 / 归属模块 / 环境           · 状态 / 日志 / 本次快照
   · nodes（节点序列）                · templateId → 流水线 id
   · approvers / 门禁配置
   · ↓ 流水线级变量（scope=pipeline）
```

- **只有两个实体**：「流水线」= 流程定义，「流水线实例」= 一次执行；**不存在第三层「流水线模板」**。
- 现状：`deploy_pipeline_templates` 表 / `pipeline-templates` API 里的 `template` 字样是**历史命名**，
  实体语义就是「流水线」。UI 与文档一律叫**流水线**；改名（表/实体/路由）属后续技术债务清理，**不在本期**。
- 变量因此只有两级：**global**（跨流水线共用）+ **pipeline**（挂某条流水线），不设 `template` 作用域。

## 1. Full · 编辑流水线（`PipelineEdit.vue`）

> **导航归属（用户 2026-09-14 确认；2026-09-21 核对：未采纳）**：原计划把 流水线列表 / 流水线变量 /
> 编辑流水线 / 流水线详情 收进侧边栏父菜单 **「流水线管理」**（可折叠）。
> **落地实际：`MainLayout.vue` 侧栏为平铺四项** —— 流水线列表 / 灰度管理 / 自助诊断 / 工具目录；
> **没有「流水线变量」页**（变量在编辑页「变量」Tab）；「编辑流水线」「流水线详情」由列表行内进入。

- 页面类型：详情页（分区信息块 + 关联列表）
- 参照页：`PipelineDetail.vue`；原型 `release-platform-v10-pipeline-edit-page.html`
- 需求一句话：让运维能在页面上**完整定义一条流水线**（拉代码 → 构建 → 审批 → 发布），而不用改数据库

### 1.1 页头
- 标题：`编辑流水线 · <流水线名>`（名取自流水线定义行，UI 不出现「模板」二字）
- 副标题：`定义态：基本信息 / 流程编排 / 变量 / 节点命令 · 未保存离开会确认`
- 主操作：`保存`（primary，右上，≤1 个）

### 1.2 模块清单（自上而下）

| 序 | 模块 | 数据来源 | 承载组件 | 空态策略 | 备注 |
|---|---|---|---|---|---|
| 1 | 基本信息 | `GET /pipeline-templates/:id` | 表单（名称 / key / 说明 / 归属系统标签） | — | **key 新建可填、保存成功后只读**（产物命名空间） |
| 2 | **流程编排** | 模板 `nodes` | 画布（节点卡 + 连接线 ＋，拖拽排序 / 删除 / 点节点开抽屉） | 空态：「还没有节点 · 新增节点」 | 顺序即执行顺序 |

### 1.3 右侧抽屉（核心，用户 2026-09-15）

| Tab | 内容 | 数据来源 |
|---|---|---|
| **节点** | 节点名 / key / 策略（optional、watchdog）+ **脚本与操作序列**（`StageActionsEditor`） | `GET /pipeline-step-commands/:tplId/:nodeKey` |
| **变量** | 本条流水线的变量表（键 / 值 / 是否密钥 / 说明），可增删改 | `GET/POST/PUT/DELETE /pipeline-vars?scope=pipeline&pipelineId=` |
| **参数** | 本次生效值预览（只读）：键 / 生效值 / 来源（内置 · 配置中心 · 流水线变量 · 节点内联） | 前端按注入优先级合并 |

- 点画布上任意节点 → 抽屉打开并停在「节点」Tab（`shell` 与 `approval` 都进；审批节点只展示审批人 / 超时 / 动作，无脚本）
- 写脚本时可随时切「变量 / 参数」Tab 查键名（条件判断、`${KEY}` 引用）
- 不再有底部「节点命令」卡片

节点 kind 二选（互斥 ≤5 且固定 → `a-radio-group`，不用 select，design §2.10）：

| kind | 字段 | 约束 |
|---|---|---|
| `shell` | 名称 / key / 超时(秒) / 可选开关 / 失败回滚开关 / **脚本或操作序列** | key 匹配 `^[A-Za-z0-9_-]{1,32}$`；不与保留字（version/pointer）冲突；**git 也是普通 shell 节点**（脚本可编辑，git 登录/权限不在流水线范围） |
| `approval` | 名称 / key / **审批人**（`UserSelect`，可空=所有持权限者）/ 超时 / 超时动作(abort\|auto-approve) / 拒绝动作(abort\|rollback) | 审批人候选来自 `GET /pipelines/meta/approvers`；`rollback` 拒绝动作本期已实现（见 §8） |

`UserSelect` 为共享组件（`@web-system/ui/components/UserSelect.vue`），`degraded=true` 时组件自带告警文案。

|---|---|---|---|---|

### 1.5 校验（前端 + 后端同名规则）
- 节点 key 唯一；至少一个 shell 或 approval 节点
- 节点 key 不与保留字冲突（`version` / `pointer` 仍是平台保留：写版本 = 发布节点的 service action，切指针 = 环境部署动作）
- **不再有「平台节点（git/version/pointer）必须齐全」的约束** —— git 是普通 shell 节点（用户 2026-09-15）
- `rollback` 拒绝动作已实现（§8），不再置灰

## 2. Full（小）· 流水线变量（**独立于配置中心**）

> 用户 2026-09-14 澄清①②③：
> ① **配置中心属于服务/模块配置，与流水线无关，不往里塞东西**；流水线变量只属于流水线，入口在**流水线管理**；
> ② admin 与 ai-agent 的发布路径不同 ⇒ 选**方案 B**：做两级作用域（**全局 + 流水线级**）；
> ③ 纠正：**不是模板级** —— 实体只有「流水线 + 流水线实例」两层，变量挂在**流水线**上。

### 2.1 归属与边界
| 项 | 配置中心（`ConfigCenter.vue`） | 流水线变量（新增） |
|---|---|---|
| 管什么 | 服务/模块的运行配置（global/env/module） | 流水线用的变量（**global + pipeline** 两级） |
| 入口 | 配置中心页 | ~~流水线管理 → 流水线变量~~ → **落地：编辑流水线页「变量」Tab**（无独立变量页） |
| 存储 | `config_items` | **新表 `deploy_pipeline_vars`**（不复用 config_items） |

### 2.2 两级作用域
| 作用域 | 含义 | 典型键 | 存放处 |
|---|---|---|---|
| `global` | 所有流水线共用；跨流水线一致的值 | `PUBLISH_HOST`、`SSH_KEY` | 落地：编辑页「变量」Tab 的 `global` 作用域 |
| `pipeline` | 挂在**某一条流水线**上，可覆盖同名全局键 | `PUBLISH_PATH`、`BUILD_CMD` | 落地：编辑页「变量」Tab 的 `pipeline` 作用域（无独立变量页） |

> 「流水线」= 发布流程定义（当前落在 `deploy_pipeline_templates` 表 / `pipeline-templates` API，历史上叫“模板”，实体上就是流水线本身）。
> **不存在第三层模板**，`scope` 的取值因此是 `global | pipeline`，**没有 `template`**。

### 2.3 注入优先级（后者覆盖前者）
```
平台内置（RELEASE_DIR/MODULE_KEY/…）
  → 配置中心：global → env → module      ← 服务配置层，保持不变
  → 流水线变量：global → pipeline        ← 流水线级可覆盖全局同名键
  → 节点内联（action.env / 命令内）
```
运行时：实例持有流水线 id ⇒ 合并 `global` 与该 `pipeline` 的变量进 `process.env` 交给节点脚本。

### 2.4 数据模型（新表）
`deploy_pipeline_vars`：
`id / scope('global'|'pipeline') / pipelineId(nullable) / key / value / isSecret / description / enabled / updatedBy / createdAt / updatedAt`
- 唯一键：`(scope, pipelineId, key)`；`scope='global'` 时 `pipelineId` 为 NULL
- 密钥值只写入不回显（列表掩码 `****`）

### 2.5 变量的落点（用户 2026-09-14：**跟着流水线走，不单独成页**）
- **编辑流水线页**：变量区表格，做增删改查（`POST/PUT/DELETE /pipeline-vars`），列：键 / 值（密钥掩码） / 说明 / 密钥 / 操作
- **流水线详情页**：Tab **执行进度 / 历史记录 / 参数 / 变量**（用户 2026-09-14 批注后补「历史记录」）——
  「历史记录」= 实例事件流（提交 / 节点开始结束含耗时与退出码 / 审批动作 / 状态流转，来自实例日志 + 审批记录）；
  「变量」Tab 只读展示本条流水线的变量，需修改跳编辑页
- 菜单里**没有**「流水线变量」这一项；**流水线列表一屏列出所有模块的流水线**（带「模块」列），
  每个模块默认 3 条（local / dev / prod），缺的环境用「+ 新建流水线」补

### 2.6 编辑流水线页的变量区
- 位置：基本信息之后、流程编排之前；数据来源 `GET /pipeline-vars?scope=pipeline&pipelineId=`
- 与本页一起保存/单独保存均可，但必须**即时落库**（脚本执行时才取得到）
- 空态：`未定义流水线变量 · 新增`

### 2.7 流水线详情「参数」面板
- 位置：`PipelineDetail.vue` 新增分区（概览卡之后）
- 数据：内置 + 配置中心 + 流水线变量（global → pipeline）+ 节点内联 → 前端按 2.3 合并，展示**最终生效值**
- 列：键 / 生效值（密钥掩码） / 来源（内置·配置中心·流水线变量·全局·流水线变量·流水线级·节点内联） / 被谁覆盖
- 空态：`本次发布未使用额外参数`

## 7. 决策记录（用户 2026-09-14 答复）

| # | 议题 | 结论 |
|---|---|---|
| 1 | admin / ai-agent 发布路径不同（全局变量共用）怎么办 | **做两级作用域**（方案 B）：`global` + `pipeline`，脚本统一引用 `${PUBLISH_PATH}`，不采用 `PUBLISH_PATH_ADMIN` 这类带模块后缀的键 |

| 3 | 发布参数变量化后旧脚本是否同步改 | **同步改**：脚本一律引用 `${PUBLISH_PATH}` 等变量，不再写死默认值（否则"改变量不生效"） |
| 4 | `onReject=rollback` 是否置灰禁用 | **不接受禁用** → **本期实现**：拒绝且 `onReject=rollback` 时执行回滚（见 §8） |
| 5 | 是否出可点击 HTML 原型 | **出**：由 `ux-prototype-designer` 产出，过目后再写代码 |

## 9. 流水线边界调整（用户 2026-09-14 确认）

### 9.1 节点序列收敛

```
旧：拉取代码 → 构建 → 发布确认 → 投递产物 → 写版本 → 切指针 → 验证
新：拉取代码 → 构建 → 发布确认 → 发布          ← 流水线到此为止

                                    产物按版本目录落地后即写一条版本记录
```

- 「发布」节点 = **普通 shell 节点，无内置语义**：脚本两步 —— ①上传文件（工具）②调用写版本接口（工具）；

### 9.2 模块管理（新页面组，三子模块）—— ⚠️ 2026-09-21 核对：**未落地**

> **落地实际**：`/modules*` 已下线，改由**双域重构**取代 —— 微前端域「应用管理 `/apps`」+
> 「环境管理 `/environments`」+「版本部署 `/deploys/micro`」；API 网关域「服务管理 `/services`」。
> 本节仅作设计过程记录，**不要再当落地依据**。

| 子模块 | 内容 | 数据来源 |

- **版本只在这里被"投向环境"**，流水线不决定哪个环境跑哪个版本 ⇒ **回滚 = 部署历史版本**

  - 模块列表（默认首页）：点记录进详情，点「编辑」进编辑页
  - 模块详情：三 Tab 只读查看 —— 配置信息直接看；**版本行可直接「部署」**，并有「AI 验证」按钮（下发该版本的验证任务，agent 未接入前占位）；环境行「部署版本」→ 选版本
  - 编辑模块：同三 Tab，配置信息可编辑 + 保存
- 编排交互（编辑流水线）沿用**现有流程画布**：拖拽改顺序、连接线 ＋ 插入、节点 ✕ 删除、点节点编辑脚本 / 变量值 / 超时 / 审批人
- 实现影响：现有 `version` / `pointer` 两个 platform 节点的语义要改 —— `version` 并入发布节点，`pointer` 从流水线移除后在「环境部署」里独立可用（见 `tasks.md` 已知缺口）

### 9.3 流向

```
流水线：拉代码 → 构建 → 审批 → 发布 ──▶ 产出版本（版本列表）
                                            │
模块管理 · 环境部署：选版本 ──▶ 切指针 + 探活验证 ──▶ 环境指向该版本
```

- **基线版本**：在**提交时**快照当前线上版本（实例新增 `prevVersion` 字段），而不是等 version 阶段 ——
  审批节点通常在发布动作之前，那时还没走到 version 阶段，拿不到基线。
- 执行：拒绝且 `onReject=rollback` →
  1. 无基线版本（首次发布 / 查不到指针）→ 记日志「无基线版本可回滚」并按 `abort` 终止（**不静默**）；
  2. 基线 == 本次目标 → 记日志「本次尚未改动线上版本，无需回滚」并按 `abort` 终止；
  3. 否则调 `deployService.startRollback(env, prevVersion, operator, moduleKey)`，等结果，写日志与审计。
- 终态：无论哪种，流水线最终为 `failed`（拒绝 ≠ 成功），回滚结果写进日志与审计明细。
