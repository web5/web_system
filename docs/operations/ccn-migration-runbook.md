# 云联网（CCN）迁移 runbook：把 deploy-console → 云数据库改走内网

> ## 🔶 状态：**暂缓（2026-10-08 决策）**
>
> 当前执行路线改为 **A1：仅把 dev 机公网 IP 转换为弹性公网 IP**，保留公网链路；
> 云数据库公网 **SSL 暂不开**。方案见本文 §0.1。
>
> 本 runbook 保留为**后续可选升级路径**，暂不执行。重新启用时请注意两个连带影响：
> - 改内网后可收紧 `cloud-db.service.ts` 的超时参数（现按公网调：`connectTimeout` 10s / 查询 8s）
> - **SSL 证书 SAN 绑定外网地址**，改内网后必须重配 SSL（= 再重启一次云数据库实例）
>   → 顺序必须是**先改内网、后定 SSL**，反了要多重启一次

> 目标：撤掉 dev → 云数据库的公网链路，改用腾讯云骨干内网
> 收益：MySQL 端口不再暴露公网（比 SSL 强一个量级）、延迟更低更稳、**EIP 与 SSL 两项运维需求随之消失**
> 说明：需控制台操作，CI/CD 无 cvm/cdb API 权限

---

## 0.1 当前执行路线：A1 —— 公网 IP 转 EIP

**做什么**：把 dev 机的普通公网 IP 转成弹性公网 IP（EIP）。

| 项 | 结论 |
|---|---|
| IP 是否变化 | **不变**（转换过程不中断公网访问，无需改云数据库白名单） |
| 是否可逆 | ❌ **不可逆**，转成 EIP 后无法转回普通公网 IP |
| 配额 | 每账户单地域 EIP 配额 20 个，本场景用 1 个 |
| 计费 | 保留原有网络计费模式；EIP 可能有独立的 IP 保有费（以控制台为准） |

**控制台操作**（公网 IP 控制台 / 云服务器控制台二选一）：

1. 公网 IP 控制台 → 顶部选地域 → 列表中找到 dev 机的公网 IP
2. 操作列 → **更多 > 转换为弹性公网 IP** → 确定
   （或在云服务器控制台 → 实例行 → 公网 IP 右侧的转换入口）

**转换后验证**：

```bash
# 出网 IP 应与转换前一致（若 ipify 不通可用 myip.ipip.net）
ssh <dev> "curl -s https://myip.ipip.net"

# console 与云库探活应不受影响
ssh <dev> "curl -s http://127.0.0.1:6200/api/health/cloud-db"
./scripts/check-cloud-db-consistency.sh --env dev --quiet; echo "EXIT=$?"
```

**这一步解决了什么**：dev 机若因变配/重装/重建导致公网 IP 变化 → 云数据库白名单失效 →
prod 发布时因 `DEPLOY_CLOUD_DB_STRICT=true` 直接 503。转 EIP 后 IP 可随服务迁移重绑，风险消除。

**⚠️ 与「超时参数收紧」冲突**：公网链路下 `connectTimeout` 10s / 查询 8s 是**刻意放宽**的
（实测公网阻断时单次 connect 会挂 31s，靠应用层硬超时才压到 9s 返回）。
**走 A1 就不要收紧超时**，否则会把正常的公网抖动误判为故障。等真的改成内网再动。

**⚠️ SSL 未开**：链路仍是公网明文。云库中只有版本指针与部署配置（不含业务隐私数据），
风险已评估为可接受；日后若改走内网或直接关公网，则 SSL 也不再需要。

## 0. 为什么做这个

2026-09-30 基座事故的根因是「dev 写本机库、prod gateway 读云库 → 版本指针分裂」。M1–M5 用应用层双写解决了**一致性**，但底层链路仍然依赖**公网**：

```
dev（南京 10.206.16.0/20）  ──公网 gz-cdb-8y2lp8rt:27241──▶  云数据库（广州 172.16.16.10）
```

公网链路带来两个 SPOF：
1. **dev 机公网 IP 变化 → 白名单失效**（普通公网 IP 会随实例变配/重建而变，绑 EIP 只能缓解）
2. **MySQL 端口暴露公网**（可被扫描/爆破/嗅探，SSL 只防窃听不防探测）

云联网把两地 VPC 打通后，dev 可以直连 `172.16.16.10:3306`，**两个问题同时消失**。

## 2. 操作步骤（控制台）

### 步骤 1：创建云联网实例
云联网控制台 → 新建

| 配置项 | 建议值 | 理由 |
|---|---|---|
| 计费模式 | **后付费** | 先观察，稳定后可改预付费省 ~20% |
| 计费类型 | **流量计费** | 我们只有镜像写 + 巡检，流量极小且波动 |
| 服务质量 | **银** | 镜像写失败不阻断，对通信质量不敏感；比白金便宜很多 |
| 限速方式 | 地域间限速（默认） | — |

### 步骤 2：关联网络实例
实例详情 → 关联实例 → **新增实例**，两侧各加一次：

| 实例类型 | 地域 | 实例 |
|---|---|---|
| 私有网络 | 南京 | `vpc-ljskd1kp` |
| 私有网络 | 广州 | `vpc-hiltvaat` |

### 步骤 3：检查路由表
详情页 → 路由表 → 逐个查看，**确认没有「失效」状态路由**。
若失效说明网段冲突，需先解决再继续（不要强行启用）。

### 步骤 4：配置地域间带宽
带宽管理 → 调整带宽 → 地域 A 南京 / 地域 B 广州，**最小档即可**。

> 💰 费用构成：① 网络连接实例费（按关联实例数/小时）② 跨地域流量费 ③ 入方向流量处理费。
> 实际金额请在控制台实时报价确认——本场景流量极小，远低于起量业务的量级。

### 4.3 代码侧：`cloud-db.service.ts`
连接池参数是按公网调的，改内网后注释与语义要同步更新（否则后人误判）：

## 6. 回滚

任一环节失败，改回公网即可，**无需动数据表**：

```bash
DEPLOY_CLOUD_DB_HOST=gz-cdb-8y2lp8rt.sql.tencentcdb.com
DEPLOY_CLOUD_DB_PORT=27241
pm2 restart deploy-console
```

期间若短暂不可达，`DEPLOY_CLOUD_DB_STRICT=true` 会让 prod 发布**显式报 503**（这是 M2 的收益：宁可失败也不让 prod 静默跑旧版本）。

## 7. 收尾（推荐，观察 3–7 天后）

确认稳定运行且无其他用户走公网后：

1. 控制台关闭云数据库的**公网访问**（`gz-cdb-8y2lp8rt` 不再对外暴露）—— **这才是本项最大的安全收益**
2. 释放/保留 EIP 与否都不再影响数据库连接
3. 如需 EIP，纯粹是为了机器本身的可用性，与数据库无关

---

## 8. 与 SSL 的关系（重要）

**如果先开了 SSL，走内网后必须重配**：SSL 证书的 SAN 只绑定所选连接地址，改内网后证书校验失败；而重新配置 = 再开关一次 SSL = **再重启一次云数据库实例**。

所以顺序是：**先走内网 → 内网场景通常不需要 SSL**（腾讯云内网链路本身隔离，且端口不暴露公网）。
