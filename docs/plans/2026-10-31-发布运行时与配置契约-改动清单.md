## 0. 「松耦合」在这套系统里早已定义（代码原话，非我发明）

| 层 | 职责 | 机制 | 证据 |
|---|---|---|---|
| **编排** | 声明「做什么」+ 顺序 + 条件 | 节点/阶段 + **参数** | `deploy_pipelines.nodes`（git→prebuild→build→gate→release） |
| **能力** | 「怎么做」的**唯一实现** | `deploy_tool_catalog`（20 个工具，`kind=service\|shell`） | 实体注释：「平台『能力单元』统一目录，供模板步骤编排与阶段命令编辑器参考」 |
| **引用** | 编排不写正文，只引用能力 | `StageAction.type='service'` → `tool: <code>` | 「type=service 时引用的工具 code（deploy_tool_catalog.code）」 |
| **技术栈** | 平台不掌握，模块自声明 | `deploy_module_stage_commands` | 「每模块每阶段一条命令，DB 为真相源，**流水线零技术栈知识**」 |

→ **松耦合的正确形态系统已经建好了**：编排持有「引用 + 参数」，实现在能力单元里且只有一份。
→ v1/v2 都在**最耦合的那一层**（编排正文）里解决问题，方向错了。

## 7. 🔴 架构纠正（2026-11-01 11:05）—— 前六节的落脚点判断错了

**用户纠正**：deploy-console **只跑在 dev，从不部署到 prod**；**prod 的服务全部由 dev 的 deploy-console

### 7.1 真相：prod 重启走 `DeployService.applyBackendRemote`（deploy.service.ts:1654），有两条分支

| 分支 | 触发条件 | 重启方式 | prod 覆盖 |
|---|---|---|---|
| **A · 隔离运行（主流）** | 远端 `${HOME}/web_system_runtimes/<moduleKey>/<versionTag>/runtime-manifest.json` 存在 | `backendRuntimeActivationCommand()` → 把 `backend-runtime.ts` 的 `executeBackendRuntime` **序列化成 node 程序 ssh 到远端执行**；内部 `run('pm2', ['restart', name])`（**321 / 332 行**） | **已实锤**：prod 上 `user-service` / `auth-service` / `system-service` 的 `dist` 是软链 → 指向 `web_system_runtimes/<svc>/<svc>-dev/<commit>/dist`，正是 activate 的 `fs.symlinkSync` 产物 |

### 7.3 重复造轮子（违反规范附录 A「不另起炉灶」）

`backend-runtime.ts` 的 activate **已经具备**我写进 restart-clean 的全部能力，而且更严：

| 能力 | restart-clean | activate（`backend-runtime.ts`） |
|---|---|---|
| 端口兜底 | ❌ 只认外部传入（缺陷 D2） | ✅ `input.port ?? pm2_env.PORT ?? .env/.env.generated 的 PORT`，且**不一致直接报错** |
| dist 软链 | ❌ `mkdir + cp -a` 会把软链变真实目录（缺陷 D1） | ✅ `rename` 备份软链、`symlinkSync` 落地、回滚先校验 `isSymbolicLink` 再 `unlink + rename` |
| 探活 | ✅ curl HTTP 200 | ✅ **更强**：HTTP 2xx + `ss -ltnp` 校验监听者 `pid=` 与 pm2 进程一致 + 连续两次采样稳定 |
| 进程归属 | ❌ 按名字猜 | ✅ `realpathSync(pm_cwd) === service` 精确归属，且要求 exactly one healthy |
| 失败回滚 | ✅ 回滚 dist + 重起 | ✅ 同 |

**唯一缺的就是「干净环境」：`pm2 restart` → 应改为 `pm2 delete + env -i`。**
