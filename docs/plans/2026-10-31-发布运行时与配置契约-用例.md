## 1. 背景与不变量

**要解决的问题**：`pm2 restart` 是 in-place，进程环境沿用 `pm2_env`（merge 语义）；
叠加 `@nestjs/config@3.3.0` 的 `config.module.js:188`（`filter(key => !(key in process.env))`
→ 对已存在的键**只补不覆盖**）→ 改 `.env` 的值重启后**永久不生效**。
唯一解是 `pm2 delete` + `env -i`（让 `.env` 成为唯一配置源）。

**不变量（任何人改这条链路都不能破）**

| # | 不变量 | 破了会怎样 |
|---|---|---|
| I1 | 干净重启后 `pm2_env` 里除 `PATH/HOME/PORT(+EXTRA_ENV)` 外无业务键 | 又回到「改了不生效」 |
| I2 | 重启前必须探活，失败要能回到起得来的版本 | 「删了没起来」变人工事故 |
| I3 | 不得破坏 `servers/<svc>/dist` 的**软链版本机制**（指向 `web_system_runtimes/<svc>/<env>/<commit>/dist`） | 平台回滚/版本管理失效（见 pitfalls「dist 是软链」） |
| I4 | 前置不满足（无产物 / 端口未知 / pm2 未纳管 / 工具停用）必须**回落**并 warn，不得让部署失败 | 发布链路被重启步骤卡死 |
| I5 | 脚本正文只存 `deploy_tool_catalog`，代码不持有实现 | 又变回 31 份内联副本 |

## 3. 已知缺陷与待补用例

| 编号 | 缺陷 | 影响 | 用例 |
|---|---|---|---|
| **D1** | `restart-clean.sh:176-185`：给 `VER_DIR` 时执行 `mv dist dist.bak` + `mkdir dist` + `cp -a` → **把软链变成真实目录**，破坏 I3；回滚 `rm -rf dist && mv dist.bak dist` 同理 | 当前 **不触发**（bootstrap 不传 VER_DIR，第 4 步直接 `nest build` 写 `servers/<svc>/dist`）；一旦流水线接入必踩 | TC-04 |
| **D2** | 端口只认外部传入（第 29 行 `: "${PORT:?}"`），无 `$SVC_DIR/.env` 兜底 | `bootstrap` 的 `port_of` 读 `ecosystem.config.cjs`（旧文件 2235B，非 `.js`）；新服务若只在 `.js` 配 PORT → 发版硬失败 | TC-06 |
| **D3** | delete 后端口未即时释放 → 日志报「占用者是 pm2 纳管进程，跳过」 | 潜在 EADDRINUSE 时序风险 | 观察项 |

**D1 修法（软链优先）**：
- 检测 `dist` 是否软链（`[ -L "$SVC_DIR/dist" ]`）
- 是 → 备份只记 `readlink` 值（写 `dist.bak-<stamp>.link` 或直接记日志），落地用 `ln -sfn "$VER_DIR" "$SVC_DIR/dist"`，回滚用 `ln -sfn "<旧目标>"`
- 否（旧布局真实目录）→ 沿用现有 `mv`/`cp -a` 实体备份
- 收益：不破坏平台版本机制，且不产生实体拷贝（避坑：runtimes 每服务 5 个版本 ~1.4G）
