## 设计原则

在现有九阶段流水线 + Hook + MCP + Agent 架构上**增量扩展**；监控/审批/通知/配置以独立模块接入；发布核心流程保持稳定；所有横切关注点（CORS/异常过滤器/类型安全/审计）按 `CODEBUDDY.md` 铁律统一收口。

## 一、本期明确需求（用户指定）

### ① 本地服务监控（新增）
- **目标**：让控制台能监控 deploy-console 运行主机（本机）实际运行的进程，而非只能看远程。
- **能力**：新增「本地」监控源，复用已有 `execSync` 能力在本机执行 `pm2 jlist` / 端口探活 / 日志（**不走 SSH**）；前端 `ServiceMonitor` 环境切换增加「本地」选项，与 dev/prod 并列。
- **验收**：控制台可看到本机 pm2 进程列表（CPU/内存/端口/重启次数/存活），并可与远程视图切换。

### ② 模块管理 tab 化（修改）
- **目标**：模块注册表由「单表格 + 类型下拉」改为「按类型 tab 分组」。
- **能力**：`ServiceManager.vue` 改为「全部 + 后端 / 前端 / 微前端 / 小程序」tab，tab 上显示各类型模块计数；每 tab 内为该类型模块表格，保留新建/详情/编辑/删除。
- **验收**：点击 tab 即筛选对应类型；tab 显示计数；旧下拉筛选已彻底移除。

## 二、P0 · 生产必补（可靠性闭环）

### ③ 回滚真正重建后端
- **能力**：`rollback` / `publishVersion` 对 backend 模块执行 `restart` 到目标版本产物（从发布目录拉取/重建进程），而非仅切版本表指针。
- **验收**：回滚后本机/目标 pm2 进程实际运行旧版本代码（端口探活确认）。

### ④ 发布后健康检查探针（并入发布可靠性）
- **能力**：`verify` 阶段对 backend 服务做端口/HTTP 探活（复用 monitor 探针逻辑），结果写入发布记录与审计。
- **验收**：发布记录含健康探活结果；探活失败阻断并触发⑤。

### ⑤ verify 失败自动回滚
- **能力**：verify 阶段失败自动回滚到上一稳定版本（含 backend restart）。
- **验收**：探活/校验失败时系统自动回退，且回退动作留痕。

### ⑥ DB Migration 纳入发布
- **能力**：后端模块发布自动执行（或校验）DB Migration；失败阻断发布。
- **验收**：发布流水线含 migration 阶段；迁移失败不切指针。

### ⑦ 发布并发锁 / 幂等
- **能力**：同一模块同一环境并发发布串行化/加锁，防止版本指针错乱；重复提交幂等。
- **验收**：并发发布不互相覆盖；重复 job 被拒或合并。

### ⑧ 多环境发布编排
- **能力**：支持一键向多环境（dev→prod）顺序发布 + 灰度（已有 grayscale 雏形，补齐编排与状态）。
- **验收**：多环境发布有统一进度与回滚边界。

### ⑨ 发布前预检（pre-check）
- **能力**：构建前校验分支存在、DB 可达、密钥/配置就绪，失败早停。
- **验收**：预检失败不进入构建，省算省时。

### ⑩ 配置中心（环境变量 + 密钥，页面可配置，吸收原⑲）
- **目标**：运维人员可在控制台页面统一管理环境变量与密钥，按「模块 × 环境」维度配置，发布/重启时注入进程，并随版本快照可回滚。
- **核心能力**：
  1. **页面入口**：新增「配置中心」页，左侧「模块/环境」树，右侧配置键值表；也支持从模块详情进入专属配置。
  2. **普通环境变量**：增删改（如 `PORT`、特性开关、日志级别）；**三级作用域**——全局默认 → 环境级 → 模块级，后者覆盖前者。
  3. **密钥配置**：以「引用名」存储（如 `DB_PASSWORD`），真实值 AES 加密存 DB（服务侧主密钥，不落明文）；页面仅显示掩码 `••••`，支持「重新设置」「测试连接/校验」，**不可读明文**。
  4. **版本化与回滚**：每次保存生成配置快照并关联发布版本；回滚版本时配置同步回退。
  5. **注入机制（吸取 `PORT=6200` 污染教训）**：发布/重启时按优先级合并后**强制覆盖**注入 pm2 启动环境；禁止在 shell 全局预设写死 `PORT`。
  6. **校验**：保存时校验端口冲突、必填项、密钥格式。
  7. **审计**：所有配置变更留痕（谁/何时/改了什么/前后 diff，密钥值不记明文）。
- **验收**：运维无需 SSH，在页面完成「某模块某环境」的配置与注入；密钥明文不落库、不回显。

## 三、P1 · 一致性（体验与治理）

### ⑪ 模块详情聚合增强
- **能力**：模块详情页聚合版本历史 / 部署记录 / 当前部署 / 环境，统一入口。
- **验收**：从模块列表「详情」进入可一站式管理该模块前端/后台的部署版本与环境。

### ⑫ 发布流水线可视化增强
- **能力**：阶段进度、日志、耗时、失败定位的前端增强（承接现有 PipelineView）。
- **验收**：运维可直观看到每个 stage 状态/耗时/日志。

### ⑬ 灰度/金丝雀发布增强
- **能力**：灰度规则配置 + 放量 + 一键全量/回滚（承接 pipeline `grayscale`）。
- **验收**：灰度发布可配置规则、观察、放量、回滚。

### ⑭ 审批流（发布门禁）
- **能力**：关键环境（如 prod）发布需审批，谁批谁发留痕；与⑨预检、⑰审计串联。
- **验收**：未审批的 prod 发布被阻；审批记录可查。

### ⑯ 通知中心
- **能力**：发布成功/失败/审批/回滚事件通知（站内 + Webhook + 企业微信可选）。
- **验收**：关键事件有可达的通知通道与历史。

### ⑰ 审计增强
- **能力**：全量操作审计（谁/何时/改了什么/前后 diff），密钥不记明文；与⑩⑭串联。
- **验收**：任意变更可追溯到人/时间/前后值。

## 四、P2 · 可观测（度量与自助）

### ⑮ 可观测性仪表盘
- **能力**：发布成功率、时长趋势、失败分布、各模块发布频次的时间序列图；数据源复用 `deploy_deployments` / 审计表。
- **验收**：控制台有独立「发布度量」页，可按环境/模块/时间筛选。

### ⑱ 自助诊断/运维工具
- **能力**：端口冲突检测、进程一键重启、日志聚合检索。
- **验收**：常用排障动作可在页面自助完成，减少 SSH 直登。
