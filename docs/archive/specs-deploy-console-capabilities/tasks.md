## 阶段 1 · P0 构建可配置化（新增，最高优先级）

> 来源：2026-09-02 排查结论——`stageBuild` 硬编码 nest/vite + buildCmd/Hook 两套设计冲突 + 发布核心从未评审。

- [ ] 1. build 阶段收敛到 `buildCmd`（fail-fast）
  - 步骤：`stageBuild` 只取模块 `buildCmd` 执行；移除内置 nest/vite 分支；缺失 → 阶段失败并报明确错误（不回退）
  - 依赖：无
  - _验收：当 模块配置了 buildCmd 时，pipeline 应执行该命令并输出日志；当 模块未配置 buildCmd 时，pipeline 应在 build 阶段失败，且不执行任何内置构建命令_
- [ ] 2. `buildCmd` 存量迁移与默认值
  - 步骤：按类型生成默认 `buildCmd`（backend→`nest build`；frontend/micro-frontend→`vite build`）；迁移脚本一键填充；检测已配 build hook 的模块并提示转换
  - 依赖：1
  - _验收：当 迁移脚本执行后，所有 enabled 模块的 buildCmd 应非空_
- [ ] 3. 模块详情「构建命令」页面配置
  - 步骤：模块详情增加 `buildCmd` 输入框；保存前 `bash -n` 语法校验；仅控制台 JWT 可写（不暴露 MCP）；变更写审计
  - 依赖：1
  - _验收：当 运维保存非法 shell 时，应拒绝并提示语法错误；当 保存合法命令时，应落库且审计留痕_
- [ ] 4. 清理 build 阶段 Hook + 对齐文档事实源
  - 步骤：移除 build 阶段 hook 作为构建来源；修订 `deploy-pipeline-dev.md:101`（「buildCmd 已废弃」→「buildCmd 为事实源」）；对齐 `release-system-design.md`
  - 依赖：1
  - _验收：当 查阅 deploy-pipeline-dev.md 与 release-system-design.md 时，两者关于 build 机制的陈述应与 design.md 一致_
- [ ] 5. `pipeline.service.ts` 纳入独立子代理评审
  - 步骤：对 build/pipeline 改动执行独立子代理评审；结论写入 `design.md`「评审结论」
  - 依赖：1
  - _验收：当 build 相关代码变更后，design.md 应存在对应批次的独立评审结论记录_

## 阶段 2 · P0 可靠性闭环（原批 2，重梳）

> 依赖：阶段 1 先落地（build 是发布必经阶段）。

- [ ] 6. ④ 发布后健康检查探针
  - 依赖：1
  - _验收：当 发布进入 verify 阶段时，应对 backend 做真实端口/HTTP 探活，并将结果写入发布记录与审计_
- [ ] 7. ③ 回滚真正重建后端
  - 依赖：无
  - _验收：当 执行回滚后，目标 pm2 进程应实际运行旧版本代码（端口探活确认），而非仅切版本表指针_
- [ ] 8. ⑤ verify 失败自动回滚
  - 依赖：6、7
  - _验收：在 verify 失败状态下，当 pipeline 捕获失败时，应自动回滚到上一稳定版本并写审计留痕_
- [ ] 9. ⑥ DB Migration 纳入发布
  - 依赖：无
  - _验收：当 backend 模块发布时，应执行/校验 DB Migration；当 迁移失败时，应阻断发布且不切指针_
- [ ] 10. ⑨ 发布前预检（pre-check）
  - 依赖：无
  - _验收：当 预检失败（分支不存在 / DB 不可达 / 配置缺失）时，应早停且不进入 build 阶段_
- [ ] 11. ⑦ 发布并发锁 / 幂等
  - 依赖：无
  - _验收：当 同一模块同一环境并发发布时，应串行化或拒绝重复提交，不互相覆盖指针_
- [ ] 12. ⑧ 多环境发布编排
  - 依赖：11
  - _验收：当 提交多环境发布时，应按顺序执行并提供统一进度与回滚边界_
- [ ] 13. ⑩ 配置中心（环境变量 + 密钥）
  - 依赖：无
  - _验收：当 运维在页面配置某模块某环境的变量/密钥时，注入应按 全局→环境→模块 合并并强制覆盖 pm2 env；密钥明文不落库、不回显_

## 执行约定（方法论）

- **TDD**：每个任务 RED（写失败测试）→ GREEN（最少代码通过）→ REFACTOR，逐项标记完成。
- **防回归**：每个缺陷修复补一个「修复前会失败」的测试；校验对外可见行为，不校验实现细节。
- **证据**：宣称通过必须附实际运行结果（lint / 测试 / 接口返回）。
- **收尾**：全部完成后走 `verification-before-completion` + `rd-review`，再交由用户确认；**不主动 commit**。
- **阶段门**：阶段 1 全部完成并经评审后，才启动阶段 2。
